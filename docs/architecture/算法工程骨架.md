# 算法工程架构

更新时间：2026-08-10

## 1. 工程边界

本仓库只实现跌倒风险和心理健康风险的算法原型。两个模块共享人员、设备、时间和事件字段约定，但各自评分并输出自己的 `AlgorithmEvent`。

算法工程负责数据适配、质量控制、特征提取、规则或模型推理、评估工具和标准化事件输出。业务系统负责账号、设备管理、数据库、消息通道、工单和人工处置。

## 2. 代码分层

| 目录 | 职责 |
|---|---|
| `common/` | YAML、JSONL 和 `AlgorithmEvent` 公共契约 |
| `modules/fall_risk/` | 跟踪、姿态、质量控制、步态、坐站、近跌倒、个体基线、跌倒内部评分，以及 manifest、标注校验、split 和事件评估 |
| `modules/mental_health/` | 行为/睡眠适配、日级聚合、个人基线和心理健康评分；`wandering/` 实验子包含版本化轨迹、来源 manifest、转换报告、split 契约和安全 JSONL I/O |
| `runtime/` | 跌倒实时姿态跟踪、滑动窗口、采样/gap 诊断、episode 状态机、不可变事件版本和事件节流 |
| `service/` | 跌倒直播流读取、有界 latest-frame 队列、单会话 epoch 生命周期、进程内有界异步 outbox、FastAPI 和单次 HTTP 回调尝试 |
| `inference/` | 两个模块的离线命令行入口 |

依赖方向以公共契约和领域模块为内层，运行时和服务为外层。算法模块不访问业务数据库。

## 3. 跌倒风险链路

```text
视频帧
  -> YOLOv8-Pose + ByteTrack
  -> 主目标姿态与质量控制
  -> 10 秒内存窗口
  -> 步态 / 坐站 / 近跌倒 / 跌倒状态 / 个体基线 / 场景特征
  -> 规则 baseline 与模型化增强分支（TCN / MS-TCN++ / ST-GCN）
  -> 安全覆盖与风险融合
  -> fall_risk AlgorithmEvent
  -> episode 生命周期与不可变服务事件版本
  -> 有界异步 outbox 与后端 HTTP 回调
```

离线 JSONL 脚本仍用于数据处理和调试；实时主路径使用内存对象，不通过临时 JSONL 串联。

与推理链路并行的数据与评估控制链已经具备自动化实现：

```text
本地数据资产
  -> 确定性 manifest + 内容 hash + 媒体元数据
  -> 来源独立的候选标注导入
  -> schema / 来源 / hash / 技术排除严格校验
  -> fall_event / near_fall_event / functional_proxy / longitudinal_baseline 独立 split
  -> 版本化事件匹配、指标与失败案例 bundle
```

该控制链默认失败关闭。当前 v2 根标签 formal 校验仍为 `formal_ready=false`；四任务开发 split 中 `fall_event_v1`、`near_fall_event_v1` 为 provisional `ready`，`functional_proxy_v1`、`longitudinal_baseline_v1` 因缺少对应真值继续 `blocked`。独立的训练标签 v3 已通过 fall/near-fall 事件监督与无泄漏 split 门禁，但动作类型门禁仍未通过；上述产物均未冻结。跌倒事件 P0 审计器会绑定当前 manifest、v3 标签、split、formal/v3 报告及训练/评估配置 hash，并在 formal、独立事件规模、连续背景、老人域、冻结协议或 test 保管门禁缺失时输出 `infrastructure_only`。合成数据评估只能证明工具链可运行，不能证明真实算法效果。

## 4. 心理健康链路

```text
带绝对时间的姿态记录 + 可选睡眠/自评
  -> 输入适配与质量校验
  -> person_id + 自然日聚合
  -> 3-14 日个人历史基线
  -> 活动、睡眠和规律性偏离评分
  -> 风险等级、置信度和人工复核建议
  -> mental_health AlgorithmEvent
```

当前入口是离线日级 CLI；仓库尚未实现心理健康定时调度或 HTTP 服务。

## 5. 当前实现状态

当前跌倒风险研发处于模型化增强阶段。模型增强优先覆盖步态、坐站、近跌倒/跌倒事件等时序分支；规则 baseline 继续作为对照、安全覆盖和低质量输入 fallback。个体行为基线的因果周期契约、鲁棒统计、冷启动、EWMA/CUSUM 候选、防污染状态机，以及 Phase 2 纵向 schema、前向 split、泄漏审计、四组消融评估和 test release 门禁已完成合成验证；但没有在线周期聚合来源，也没有连续个人数据、`risk_labels` 真值、非空冻结 split 或冻结评估协议，因此尚未证明效果或在实时链路启用。

## 6. 现行约束

- 模型化增强阶段优先可验证的时序模型，但必须保留可解释、可复现和可降级的规则 fallback；复杂模型不能成为唯一安全路径。
- 缺失或低质量数据应降低置信度、限制等级或输出不可用状态，不能填成正常值。
- `person_id` 是跨时间聚合的业务身份；`track_id` 只表示单路视频内轨迹。
- 两个模块分别建立验证集、指标和阈值，不能用一个模块的结果证明另一个模块有效。
