# 环境因素多模态增强设计方案

## 1. 设计目标

现有 `scene_risk_score` 只能表达浴室、床边等静态场景先验。本方案增加实时照度和水浸探头输入，用于识别“人体行为风险与环境暴露同时出现”的情况。

环境信号只增强跌倒模块内部风险判断，不独立告警，不改变以下边界：

- 人体检测、跟踪、姿态质量控制和行为分析仍是主链；
- 环境缺失或故障不等于低风险；
- 4 级紧急风险仍只由现有跌倒或长时间静止强触发产生；
- 最终只输出 `module=fall_risk`，不与心理健康风险融合；
- 设备管理、固件升级和业务告警流程不在本仓库范围内。

## 2. 总体架构

```text
ESP32-S3
  ├─ TSL2591 照度
  └─ 水浸探头
        |
        v
POST /v1/environment/readings
        |
        v
EnvironmentStore（进程内、有界、按设备缓存）
        |
        | 按摄像头绑定和视频帧接收时间取快照
        v
FeatureAssembler
  ├─ 步态 / 坐站 / 近跌倒
  ├─ 弱光分数
  ├─ 水浸区域暴露
  └─ 人-环境交互分数
        |
        v
FallRiskPipeline
  ├─ disabled：不启用环境分支
  ├─ shadow：只记录，不改风险
  └─ assist：通过门禁后有限加分
        |
        v
AlgorithmEvent(module=fall_risk)
```

`create_app()` 创建唯一的 `EnvironmentStore`。环境接口负责写入，各 `FallRiskSessionEngine` 只读查询，避免会话间出现互不一致的环境状态。

## 3. 环境数据契约

ESP32-S3 以 1～2 Hz 上报照度和探头状态，探头状态变化时立即补报。

```json
{
  "schema_version": "1.0",
  "device_id": "env-node-01",
  "boot_id": "01J4DEVICEBOOT",
  "boot_started_at": "2026-07-29T09:58:02.100+08:00",
  "sequence": 1842,
  "observed_at": "2026-07-29T10:20:31.420+08:00",
  "clock_status": "synced",
  "illumination_lux": 18.6,
  "illumination_status": "ok",
  "water_probes": {
    "bathroom_door": {
      "state": "dry",
      "sensor_status": "ok"
    }
  },
  "sensor_status": "ok"
}
```

字段规则：

| 字段 | 规则 |
|---|---|
| `device_id` | 稳定设备 ID，必须存在于配置 |
| `boot_id` | 每次启动生成新值，用于区分 sequence 归零 |
| `boot_started_at` | 用于判断 boot 新旧，同一 boot 内保持不变 |
| `sequence` | 同一 boot 内严格递增 |
| `observed_at` | 带时区设备时间，用于传输年龄和时钟健康检查 |
| `clock_status` | `synced/unsynced`；未同步记录不可参与融合 |
| `illumination_lux` | 通道正常时为有限非负数，故障时为 `null` |
| `illumination_status` | `ok/degraded/fault` |
| `water_probes.*.state` | `dry/water/unknown`；故障时必须为 `unknown` |

接口使用现有 Bearer Token 鉴权。固定响应语义如下：

| 状态 | HTTP | 处理 |
|---|---:|---|
| 首次有效记录 | 202 | 写入缓存，返回 `accepted` |
| 完全相同的重复记录 | 200 | 不重复写入，返回 `duplicate` |
| sequence 回退、旧 boot 或同键不同载荷 | 409 | 拒绝写入 |
| schema、设备或字段非法 | 422 | 拒绝写入 |
| `environment.mode=disabled` | 503 | 不接收环境记录 |

新 boot 只有在 `boot_started_at` 晚于当前 active boot 且设备时钟健康时才能生效。服务为有效请求补充 `received_at`、`received_monotonic_sec` 和 `transport_age_sec`。

## 4. 时间对齐与可用性

设备 UTC 与视频源 PTS 不直接相减。在线对齐使用服务端单调时间：

1. 先检查 `clock_status`、传输年龄和未来时间偏差；
2. 按会话摄像头 ID 找到绑定的环境设备；
3. 选择 `environment_received_monotonic <= frame_received_monotonic` 的最新记录；
4. 计算 `snapshot_age_sec`；
5. 只有快照年龄不超过 `max_age_sec` 时才允许计算环境特征。

环境分支沿用现有三态：

| 状态 | 含义 |
|---|---|
| `valid` | 输入可信且计算成功；有效 `0.0` 表示当前未观察到环境风险 |
| `unavailable` | 缺失、过期、故障、绑定失败、关键点不足或 ROI 失效，不参与融合 |
| `inference_error` | 输入可用，但环境特征代码发生非预期异常 |

流重连时姿态窗口和 episode 按原逻辑清空。环境缓存可以保留，但每次使用前仍要重新检查因果性、新鲜度和绑定关系。

## 5. 环境特征

### 5.1 弱光分数

```text
lux >= normal_lux      -> low_light_score = 0
lux <= severe_low_lux  -> low_light_score = 1
其他                   -> (normal_lux - lux) / (normal_lux - severe_low_lux)
```

结果限制在 `[0, 1]`。两个阈值按安装位置现场标定，不作为通用照明标准。缺少标定或照度通道不可用时不计算分数。

### 5.2 水浸区域暴露

每个探头绑定一个归一化画面 ROI：

- 探头为 `dry` 时，`water_exposure_score=0`；
- 探头为 `water` 时，再判断当前主目标是否进入对应 ROI；
- 默认最近 3 帧中至少 2 个可用帧命中 ROI，才判定人员位于探头区域；
- 脚踝质量不足、多人歧义、摄像头移动或 ROI 版本不符时，结果为 `unavailable`。

```text
water_exposure_score = water_presence_near_probe * person_in_probe_zone
```

探头只表示其附近检测到水，不能推断整个地面湿滑。

### 5.3 人-环境交互

行为锚点只使用当前有效的行为分支：

```text
behavior_anchor = max(
  有效的 gait_risk_score,
  有效的 sit_stand_risk_score,
  有效的 near_fall_event_score
)

light_interaction_score = low_light_score * behavior_anchor
water_interaction_score = water_exposure_score * behavior_anchor
environment_interaction_score = max(有效的交互分数)
```

没有有效行为分支时，环境交互分为 `unavailable`。`fall_event_score` 和 `long_static_score` 不进入行为锚点，避免环境分支介入 4 级强触发。

## 6. 融合策略

| 模式 | 行为 |
|---|---|
| `disabled` | 不接收、不计算环境数据，现有链路保持不变 |
| `shadow` | 计算环境特征并写实验日志，不改变风险决策 |
| `assist` | 在环境与行为均有效且行为锚点达到门槛时有限加分 |

shadow 模式不得修改 `risk_score`、`risk_level`、`confidence`、`trigger_event`、顶层 `risk_factors`、`recommended_action`、`model_version` 或 episode 转移，也不把环境字段加入现有 `feature_coverage` 和 `fusion_mask`。

assist 使用以下公式：

```text
behavior_anchor < min_behavior_anchor
  -> environment_contribution = 0

否则
  environment_contribution = environment_weight * environment_interaction_score

adjusted_score = clamp(base_risk_score + environment_contribution, 0, 1)
```

约束：

- 环境或行为不可用时完全回退 `base_risk_score`；
- 基线已为 4 级时保持原结果和触发原因；
- 基线低于 4 级时，环境最多将结果提升到 3 级；
- 环境不能产生 `fall_or_long_static`；
- 首版保留 `base_confidence`，不因环境加分自动提高置信度；
- 只有形成交互贡献时才增加交互型风险因子；
- 权重、行为门槛和策略版本必须由固定 train/validation 确定。

## 7. 内部与对外字段

| 字段位置 | 内容 |
|---|---|
| `features["environment_features"]` | 弱光、水浸暴露、行为锚点和交互分数 |
| `features["environment_mask"]` | 各环境通道是否可用 |
| `branch_diagnostics["environment"]` | 状态、原因、设备序列、快照年龄、ROI/标定版本和耗时 |
| `AlgorithmEvent.metadata["environment"]` | 原事件已生成时附加的紧凑环境证据 |

普通 0 级观测不会回调，因此 shadow 数据由独立、有界、非阻塞的 JSONL 记录器保存，不能依赖 `AlgorithmEvent` 收集。

建议交互型风险因子：

- `unstable_gait_under_low_light`
- `sit_stand_difficulty_under_low_light`
- `near_fall_under_low_light`
- `unstable_gait_near_water`
- `near_fall_near_water`

`low_illumination` 和 `water_presence_near_probe` 仅作为环境观测写入 metadata，不单独作为顶层风险因子。

## 8. 配置

```yaml
environment:
  mode: disabled
  max_age_sec: 3.0
  max_transport_age_sec: 2.0
  max_future_skew_sec: 0.5
  store_capacity_per_device: 256
  shadow_log_path: null
  roi_window_frames: 3
  roi_min_usable_frames: 2
  roi_min_hits: 2
  roi_max_span_sec: 1.0
  camera_bindings:
    ezviz_cam_001:
      environment_device_id: env-node-01
      calibration:
        severe_low_lux: null
        normal_lux: null
        version: null
      water_probe_rois:
        bathroom_door:
          version: bathroom-door-roi-v1
          polygon:
            - [0.10, 0.72]
            - [0.42, 0.70]
            - [0.47, 0.98]
            - [0.05, 0.98]
  assist:
    weight: null
    min_behavior_anchor: null
    policy_version: null
    acceptance_report: null
```

默认模式必须是 `disabled`。shadow 必须配置日志路径；assist 还必须配置标定版本、权重、行为门槛、策略版本和准入报告，否则服务启动失败。

## 9. 模块职责

| 模块 | 职责 |
|---|---|
| `service/schemas.py` | 环境上报 schema |
| `service/app.py` | 鉴权接口和共享 store |
| `service/settings.py` | 环境配置校验 |
| `service/session.py` | 将共享 store 和配置注入会话引擎 |
| `runtime/environment_store.py` | 有界缓存、去重、boot/sequence 和因果查询 |
| `modules/fall_risk/environment.py` | 弱光、ROI 和交互评分纯函数 |
| `runtime/feature_assembly.py` | 环境特征、mask、三态和缓存签名 |
| `runtime/realtime_fall_risk.py` | 查询快照并提交 shadow 记录 |
| `runtime/shadow_log.py` | 非阻塞 JSONL 记录 |
| `modules/fall_risk/features.py` | assist 特征与缺失 mask 契约 |
| `modules/fall_risk/pipeline.py` | shadow 不变量和 assist 融合限制 |

以上路径均相对于 `src/elderly_monitoring/`。环境分支关闭后，不应要求业务调用方修改会话请求或事件消费逻辑。
