# 跌倒风险个体化行为基线算法增强计划

更新时间：2026-08-12

执行状态：Phase 0-1 已于 2026-08-12 完成代码与合成序列验收；Phase 2 的算法侧基础设施也已完成，包括纵向 observation/review 契约、按保守来源组隔离且同人时间前向的确定性 split、泄漏审计、四组固定消融评估、分层/置信区间/失败案例 bundle 和哈希绑定的 test release 授权门禁。真实 Phase 2 效果验收仍受连续个人数据、稳定身份、非空 `risk_labels`、冻结 split 和评估协议阻塞；Phase 3 未开始。该状态只证明算法行为和评估链失败关闭，不证明真实老人域效果。

计划审查修正：Phase 1 的鲁棒统计和防污染必须以前置 Phase 0 的因果周期契约为条件，不能独立验收。负责人尚未冻结周期与跨设备策略时，本次按计划停止条件采用保守 provisional 默认：自然日、`person_id + camera_profile_id` 分层、无历史 unavailable；没有启用跨摄像头合并或在线 pose 聚合。

## 1. 计划目标

本计划只增强跌倒风险模块内部的个体化行为基线算法，不涉及心理健康模块，也不扩展家属端、后台、消息推送、账号权限或通用服务工程。

目标是在保留现有统计/规则 fallback 的前提下，把当前原型推进为可验证的个体化趋势算法：

```text
步态、坐站、近跌倒、活动和场景周期特征
  -> 严格早于当前观测的个人历史
  -> 逐指标质量与可用性门禁
  -> 鲁棒个人 reference
  -> 短期偏离、长期漂移和突变状态
  -> baseline_deviation_score + 解释因子 + 置信状态
  -> 跌倒风险模块内部融合
```

最终需要回答三个比赛层面的问题：

1. 相比固定群体阈值，个人历史是否能更早识别状态恶化。
2. 相比无个体基线的融合，个人基线是否降低误报或提高高风险召回。
3. 统计方法已经足够时，轻量监督模型是否仍有稳定、可复现的增益。

## 2. 当前起点与不可越过的边界

当前已有：

- `baseline.py` 支持按 `person_id` 和日/小时聚合记录。
- 已计算均值、标准差、分位数、近期均值和方向性偏离。
- 已输出 `baseline_deviation_score`、`baseline_reference`、`baseline_quality` 和 `deviation_factors`。
- 历史不足和整体低质量时已有保守分数上限。
- 规则风险融合可以消费 `baseline_deviation_score`。

当前算法缺口：

- 在线 10 秒 cleaned pose 与离线日/小时特征契约不一致。
- 历史没有强制严格早于当前观测，存在当前周期污染和未来信息泄漏。
- 缺失、质量和观测次数没有逐指标处理。
- 冷启动、稳定基线、昼夜模式、长期漂移和突变没有形成状态化算法。
- 没有异常期隔离，后续增量更新可能把持续恶化学习为正常。
- 权重和阈值没有真实纵向数据校准。
- `risk_labels.jsonl` 为 0 条、subject profiles 为 0 人，`longitudinal_baseline_v1` 为 `blocked/0`。

因此，本计划不得把候选统计方法或模型描述为已验证能力。缺少连续个人数据或纵向真值时，规则/统计 fallback 必须保留，个人基线只输出跌倒模块内部特征，不直接给出最终风险等级。

## 3. 目标算法设计

### 3.1 周期特征契约

新增统一的个人基线周期特征概念 `FallBaselinePeriodFeatures`。每条记录只表示一个已完成小时或自然日，至少包含：

| 类别 | 字段 |
|---|---|
| 身份 | `person_id`、`device_id`、`camera_profile_id` |
| 时间 | `period_id`、`period_start`、`period_end`、`timezone` |
| 步态 | 平均步速 proxy、速度变异、横向摆动、转身不稳定、有效步态窗口数 |
| 坐站 | 平均耗时、失败尝试数、站稳时间、有效事件数 |
| 近跌倒 | 事件数、按有效监测时长归一化的频率、事件最高分 |
| 活动 | 活动量、夜间活动次数、有效监测时长 |
| 场景 | 场景分布和各场景有效监测时长 |
| 质量 | 每项指标的观测数、覆盖率、质量、缺失原因和可用状态 |
| 追溯 | 上游算法版本、周期聚合版本和输入摘要 |

算法约束：

- 只使用 `period_end < current_period_start` 的历史。
- 同一 `person_id + camera_profile_id + period_id` 只能有一条有效记录。
- `unknown`、空 ID、时间不完整或未完成周期不得进入个人 reference。
- 次数类特征必须同时保存有效监测时长，避免把离线时间误判为活动下降。
- 跨摄像头合并必须经过数据验证；验证前按 `camera_profile_id` 分层。

### 3.2 逐指标 reference

每个指标独立维护：

```text
median
MAD
p10 / p25 / p50 / p75 / p90
winsorized_mean
observed_period_count
total_exposure
quality_weight_sum
recent_level
slow_level
```

默认主统计使用中位数和 MAD，均值/标准差保留为对照和诊断。有效历史不足的指标保持 unavailable，不得填为零偏离。

### 3.3 冷启动与状态机

建议状态：

| 状态 | 含义 | 算法行为 |
|---|---|---|
| `none` | 无合格历史 | 个人偏离不可用；保留群体规则 fallback |
| `cold` | 有记录但未达到初始门槛 | 只积累统计，不参与或极低权重参与融合 |
| `initial` | 达到初始门槛 | 开放高证据指标，限制总分和融合权重 |
| `stable` | 达到稳定门槛且分布稳定 | 开放完整个人偏离评分 |
| `drift_suspected` | 多周期持续偏移 | 冻结慢基线，输出趋势因子，不吸收异常期 |
| `recovery` | 异常后恢复观察期 | 继续冻结慢基线，确认恢复后再恢复更新 |

现有 3 日初始、7 日稳定、最多 14 日可以保留为 provisional 默认值，但必须进入后续敏感性实验，不能写成已校准阈值。

### 3.4 偏离评分

每个可用指标计算单向鲁棒偏离：

```text
robust_z = directional_delta / max(1.4826 * MAD, relative_floor, absolute_floor)
```

同时计算分位数越界和相对变化。单指标分数组合：

```text
metric_score = max(
  robust_z_component,
  quantile_component,
  relative_change_component,
  short_term_change_component
)
```

总偏离分只在可用指标中归一化：

```text
baseline_deviation_score =
  sum(metric_weight * metric_score * metric_quality)
  / sum(metric_weight * metric_quality)
```

若没有可用指标，输出 unavailable，而不是 `0.0`。近跌倒次数和夜间活动次数应按有效监测小时或家庭日归一化。

### 3.5 双时间尺度和防污染

使用“慢 reference + 快状态”而不是直接滚动平均所有记录：

- 慢 reference：仅吸收身份稳定、质量合格、非异常和非恢复期周期。
- 快状态：EWMA 跟踪近期水平，用于识别持续变化。
- 突变状态：CUSUM 或连续分位数越界用于触发 `drift_suspected`。
- 进入异常状态后冻结慢 reference，防止异常逐渐被学习为正常。
- 只有满足连续恢复条件后才重新开放慢 reference 更新。

PELT、Isolation Forest、One-Class SVM 等只作为后续对照，不在缺少可审计正常期数据时进入主线。

### 3.6 输出契约

个体基线输出至少包含：

```text
baseline_deviation_score
baseline_state
baseline_confidence
available_metric_mask
metric_deviation_scores
deviation_factors
baseline_reference
history_cutoff
model_version
```

其中：

- `baseline_deviation_score` 仍是跌倒模块内部特征。
- 不直接输出 `risk_level` 或 `recommended_action`。
- 不可用指标为 `null`，并在 mask 中明确为 false。
- 每个解释因子可追溯到当前值、reference、变化比例、质量和观测次数。

## 4. 分阶段执行计划

### Phase 0：修正算法契约和因果性

预计周期：1-3 天。

目标：确保算法消费正确的周期特征，且任何 reference 都严格早于当前观测。

任务：

| ID | 任务 | 预计涉及文件 |
|---|---|---|
| B0-01 | 定义周期特征字段、必填项、逐指标质量和版本 | `baseline.py`，必要时新增领域 schema 文件 |
| B0-02 | 为 reference/评分增加 `as_of` 和严格时间 cutoff | `baseline.py` |
| B0-03 | 增加 period 去重、乱序排序和同周期冲突拒绝 | `baseline.py` |
| B0-04 | 拒绝 `unknown`、空 ID、跨人和未声明相机域历史 | `baseline.py` |
| B0-05 | 在线分支只消费周期聚合结果；没有合格结果时失败关闭 | `feature_assembly.py` |
| B0-06 | 统一基线分支的 score、mask、状态和模型版本 | `feature_assembly.py`、`pipeline.py` |

测试先行顺序：

1. 当前周期和未来周期不得进入 reference。
2. 重复 period、乱序输入和时区边界结果确定。
3. 同人历史可用；他人、`unknown` 和相机域不符不可用。
4. cleaned pose 不能被误当作周期特征。
5. 缺少合格周期特征时 score 为 `null`、mask 为 false。
6. 每个分支状态与输出字段一致。

验收标准：

- `reference.window_end < current.period_start` 对所有样本成立。
- 在线基线不再从 pose 帧产生伪零分。
- 不可用分支不参与融合，也不增加特征覆盖率。
- 现有相关测试和新增回归测试全部通过。

依赖：无真实 risk labels 依赖。

停止条件：负责人尚未确定小时/日周期定义、时区或跨设备身份边界时，只完成失败关闭，不启用新聚合路径。

### Phase 1：增强鲁棒统计、冷启动和防污染

预计周期：3-5 天。

目标：形成数据量较小时也可解释、可复现的统计主线。

任务：

| ID | 任务 | 预计涉及文件 |
|---|---|---|
| B1-01 | 新增 median/MAD、winsorized mean 和分位数 reference | `baseline.py` |
| B1-02 | 逐指标记录观测数、曝光、质量、状态和缺失原因 | `baseline.py` |
| B1-03 | 只在可用指标内按质量加权归一化 | `baseline.py` |
| B1-04 | 实现 none/cold/initial/stable 状态和阶段性分数/权重上限 | `baseline.py`、融合特征装配 |
| B1-05 | 增加快 EWMA、慢 reference 和 CUSUM 候选 | `baseline.py` |
| B1-06 | 实现异常冻结和 recovery 更新规则 | `baseline.py` |
| B1-07 | 将全部 provisional 阈值集中到版本化算法配置 | 跌倒模块配置及加载代码 |

测试先行顺序：

1. 单个极端异常值不能显著移动鲁棒 reference。
2. 缺少步态时，其他指标正常评分，步态保持 unavailable。
3. 有效监测时长不同的次数指标不会直接比较原始次数。
4. cold、initial、stable 状态按固定序列转换。
5. 突然恶化触发快状态，慢 reference 保持不变。
6. 持续异常不会逐渐变成正常。
7. 恢复期满足条件后才恢复慢 reference 更新。

验收标准：

- 合成异常值、突变、缓慢漂移、缺失和恢复序列结果符合预期。
- 同一输入和配置结果完全确定。
- 每个偏离因子能回溯到具体指标证据。
- mean/std 旧规则仍作为对照，鲁棒统计不被写成真实效果结论。

依赖：不要求 risk labels；需要负责人确认冷启动和恢复的 provisional 默认策略。

停止条件：若真实数据尚不可用，不做效果阈值调优，只完成算法与合成验证。

### Phase 2：建立纵向数据、前向切分和消融评估

算法侧执行状态（2026-08-12）：B2-01 的 observation/review 契约、确定性前向 split、泄漏审计和固定四组消融评估器已完成，并通过 60 个纯合成身份、180 个评分周期的端到端烟测。B2-02 至 B2-05 的真实数据任务未完成；现行真实输入仍为 observation 0 条、`risk_labels` 0 条、subject profiles 0 人，因此机器产物必须保持 `blocked`，合成指标不得用于比赛效果结论。

计划审查修正：原“外层按人员、家庭或保守来源组隔离”表述不足以定义个体化 test。现行协议以家庭/保守 `source_group_id` 做外层分区，同时每个 `person_id + camera_profile_id` 在自身时间轴内先保留 reference-only 周期，再保留 scoring 周期。否则 test 新人没有前置历史，只能评估冷启动，不能评估个体化价值。分区算法不读取 `risk_level`；outcome 仅在评估阶段按 `outcome_label_id` 连接。

预计周期：取决于数据采集，算法侧准备约 5-7 天，采集周期另计。

目标：形成可以证明个体化价值的比赛证据。

数据任务：

| ID | 任务 | 完成标准 |
|---|---|---|
| B2-01 | 定义纵向 observation 和 `risk_labels` 契约 | 明确观察周期、预测范围、状态变化和人工复核规则 |
| B2-02 | 建立稳定脱敏身份和 subject profiles | 每位参与者有可审计 ID、设备/场景和授权记录 |
| B2-03 | 采集连续个人周期特征 | 覆盖正常期、自然波动、困难正常行为和状态变化期 |
| B2-04 | 记录有效监测时长和质量 | 每周期可区分真正活动下降与设备离线/遮挡 |
| B2-05 | 人工复核异常与恢复周期 | 形成可审计的纵向终点，不从模型分数反向制造标签 |

评估设计：

- 外层以家庭或更保守的 `source_group_id` 分配 train/validation/test；同一人员和来源组不得跨分区。
- 每个分区内，每个 `person_id + camera_profile_id` 的 reference 周期必须严格早于其 scoring 周期。
- 同一人的当前或未来周期不得参与任一 scoring observation 的历史 reference。
- split、特征配置、阈值搜索和评估协议在 test 前冻结。
- test 的单次发布由保管人流程登记并消费唯一 run ID，评估器保留失败案例；当前无状态评估器只校验绑定关系，不能独立证明 run ID 未被重复使用。
- assignments 绑定协议哈希且不含 `risk_level`、`risk_factors` 或 label ID；validation/test scoring 才连接独立真值。
- test 必须同时满足 frozen 协议、frozen split、`data_status=formal` 和保管人 release acknowledgement；代码校验 release 与 split、协议、预测、标签、commit、授权角色和 run ID 的绑定，run ID 的单次消费由保管人工作流负责。

最小消融矩阵：

| 实验 | 目的 |
|---|---|
| 无个体基线融合（含既有群体规则特征） | 冷启动对照，并证明个人基线分支的增量价值 |
| mean/std 个人基线 | 对照旧统计实现 |
| median/MAD 个人基线 | 验证鲁棒统计价值 |
| 鲁棒基线 + EWMA/CUSUM + 防污染 | 完整统计候选 |

建议指标：

- 高风险事件 Recall、Precision、F1 和 PR-AUC。
- 3 级及以上误报/家庭日或误报/有效摄像头小时。
- 状态变化提前量。
- 概率或分数校准误差。
- 冷启动阶段误报和漏报。
- 按人员、设备、场景、质量和有效监测时长分层的结果。
- 95% 置信区间和典型失败案例。

数值晋级门槛不得在看到 test 后制定。负责人应在 validation 前冻结“允许的误报增加”“要求的召回或提前量增益”和最小有效样本量。

验收标准：

- `longitudinal_baseline_v1` 具有非空、无泄漏、冻结的 split。
- `risk_labels` 和 subject profiles 非空且通过正式校验。
- 完成至少“无个人基线、旧统计基线、鲁棒统计基线、完整统计候选”四组同协议消融。
- 报告整体、分层、置信区间和失败案例，不只报告单一平均分。

依赖：连续个人数据、稳定身份、纵向真值、冻结 split 和评估协议。

停止条件：任一门禁缺失时，只能发布 development/provisional 结果，不得声明个体化算法有效或替换主路径。

当前停止条件已触发：真实 observation、真值和人员画像为空，协议仍为 provisional。允许继续采集、复核和生成 blocked 审计，不允许把 synthetic bundle 描述为完成 Phase 2 效果验收。

### Phase 3：门禁满足后评估轻量监督模型

预计周期：3-5 天，不含新增数据采集。

目标：判断轻量监督模型是否比完整统计候选有稳定增益。

候选顺序：

1. Logistic Regression。
2. EBM 或广义加性模型。
3. LightGBM。
4. 只有以上方法无法表达必要时间关系且数据量充足时，再考虑轻量 TCN。

模型输入：

- 当前周期指标。
- 鲁棒偏离分和变化率。
- EWMA/CUSUM 状态。
- baseline state、逐指标 mask、质量和有效曝光。
- 场景上下文，但场景不得单独触发个人恶化结论。

测试先行：

1. 训练入口不能读取 test 特征或标签。
2. 缺失 mask 与数值输入严格分离。
3. 模型输出失败、质量不足或契约不符时回退统计候选。
4. 模型版本绑定特征配置、split 和训练配置。
5. 校准只使用 validation，不根据 test 回改阈值。

晋级标准：

- 在冻结 validation 和按保管人单次发布流程执行的 test 上相对完整统计候选有稳定增益。
- 主要人员、设备、场景和质量分层不出现不可接受退化。
- 冷启动、缺失模态和异常输入行为满足预注册规则。
- 解释输出仍能定位到个人偏离指标。

停止条件：数据规模不足、分层结果不稳定、test 未冻结或增益只来自单一人员/来源时，停止模型晋级并保留统计主线。

## 5. 推荐实施顺序

```text
第 1 周
  Phase 0：周期特征契约、因果 cutoff、失败关闭
  Phase 1 前半：逐指标质量、median/MAD

第 2 周
  Phase 1 后半：状态机、EWMA/CUSUM、防污染
  构建合成序列和可解释时间线

第 3 周起
  Phase 2：纵向数据采集、前向 split、正式消融

数据门禁通过后
  Phase 3：Logistic/EBM/LightGBM 对照
```

若比赛周期不足，应优先交付 Phase 0、Phase 1 和一组小规模但严格前向的 Phase 2 消融，不应为了增加模型名称跳过因果数据和统计基线。

## 7. 比赛交付物

Phase 0-1 完成后：

- 个体基线算法配置和版本说明。
- 冷启动、突变、持续恶化、恢复和缺失数据的合成时间线。
- 每个偏离因子的可解释计算示例。

Phase 2 完成后：

- 冻结的纵向 split 和评估协议。
- 有/无个体基线消融表。
- mean/std、median/MAD、EWMA/CUSUM 对照表。
- 按人员、场景、设备和质量分层的指标。

Phase 3 完成后：

- 统计主线与轻量模型候选的同协议对照。
- 校准曲线、阈值冻结记录和按保管人单次发布流程取得的 test 结果。
- 晋级或 No-Go 结论；No-Go 时继续以统计 baseline 为主路径。

## 8. 负责人需要冻结的决策

1. 个人基线的默认周期采用小时、自然日，还是二者并行。
2. `person_id` 是否跨设备稳定；跨摄像头是否共享 reference。
3. 无个人历史时保持 unavailable，还是使用群体先验。
4. `risk_labels` 的预测时间范围和状态变化终点。

6. validation 前冻结的比赛晋级指标、最小样本量和允许误报上限。
