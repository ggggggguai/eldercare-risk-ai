# 跌倒风险比赛演示视频拍摄流程

> 成片目标：约 5 分钟，1920x1080 横屏。
>
> 现场和成片统一顺序：场景 -> 服务在线 -> 正常动作 -> 受控失衡 -> 受控跌倒 -> 三组结果对照 -> 易误报动作 -> 说明系统怎样判断 -> 结尾。

## 一、导演先记住三件事

1. 先拍正常动作，再拍受控失衡，最后拍受控跌倒，不来回切换。
2. 每组动作都点击一次“开始检测”，生成独立的 `request_id` 和 `session_id`；会话本身不预设风险等级。
3. `LIVE-NORMAL-01`、`LIVE-NEAR-FALL-01` 和 `LIVE-FALL-01` 只是素材编号，不会传给算法。所有风险等级和分数都以现场实际输出为准。

## 二、正式拍摄时间线

### 第 1 段：实验室和设备（成片 0:00-0:18）

#### 现场怎么拍

1. 导演先让所有人员退出动作区。
2. 主摄横屏开始录制，先拍实验室全景 5 秒。
3. 导演喊“推摄像头”，主摄缓慢靠近固定摄像头，拍 4 秒。
4. 导演喊“拍动作区”，主摄转向地面行走线、椅子和扶物位置，拍 5 秒。
5. 导演喊“拍环境节点”，主摄依次拍 ESP32-S3、照度传感器和水浸探头，每件设备约 2 秒。
6. 导演喊“停”，主摄停止录制，文件命名为 `A01-scene.mp4`。

#### 后期旁白

> 这里是实验室模拟居家环境。固定摄像头采集人体姿态和轨迹，环境节点提供可选的照度和水浸证据。系统输出的是跌倒风险预警，不是医学诊断。

#### 拍完标准

- 摄像头、动作区域和设备之间的空间关系清楚。
- 画面角标写“实验室模拟居家环境”。
- 不出现直播地址、Token、姓名、手机号和家庭地址。

### 第 2 段：系统已经在线（成片 0:18-0:38）

#### 现场怎么拍

1. 算法操作员提前启动服务并打开 `http://127.0.0.1:8000/demo/fall-risk`。
2. 屏幕录制员开始录屏，范围只覆盖浏览器工作台。
3. 算法操作员点击顶部“真实直播”，但先不点击“开始检测”。
4. 鼠标从左到右缓慢指向四项状态：
   - 服务进程：在线；
   - 算法模型：已就绪；
   - 视频输入：未连接，等待正式会话；
   - Release：`fall-risk-competition-v2-20260827`。
5. 每项停留约 2 秒，最后让完整状态栏保持 5 秒。
6. 屏幕录制员停止，文件命名为 `B01-service-ready.mov`。

#### 后期旁白

> 本地算法服务已经就绪，下面三组动作使用同一摄像头、同一实验室和同一模型配置；受控跌倒会明确增加专业保护垫。

#### 拍完标准

- 页面处于“真实直播”，不能出现“模拟数据”提示。
- Release ID 完整可读。
- 录屏中不出现完整直播地址。

### 第 3 段：正常动作现场实拍（成片 0:38-1:28）

这一段只拍正常动作，不拍失衡。

#### 开始前的站位

1. 演示者站到画面左侧的行走起点，自然站立。
2. 主摄画面必须包含演示者全身、椅子和完整行走线。
3. 主摄先开始录制并说“主机已录”。
4. 屏幕录制员开始录制工作台并说“屏幕已录”。
5. 场记记录素材编号 `LIVE-NORMAL-01-T1`。

#### 建立监测会话

1. 算法操作员确认页面处于“真实直播”。
2. 点击“开始检测”。
3. 等页面生成 `request_id` 和 `session_id`，场记立即记录。
4. 等待“视频输入：已连接”、人体框、`track_id` 和姿态质量出现。
5. 未出现人体框前，演示者保持不动，导演不喊动作开始。
6. 状态就绪后，导演倒数：“3、2、1，正常动作开始。”
7. 演示者先抬右手到肩部 1 秒再放下，作为主摄和屏幕录制的同步点。

#### 演示者按秒执行

| 动作时间 | 演示者怎么做 | 导演怎么喊 |
|---:|---|---|
| 0-5 秒 | 在画面左侧的行走起点自然站立 | “保持” |
| 5-11 秒 | 从画面左侧的行走起点正常走到前方约 3 米、画面中央的转身位置 | “正常走” |
| 11-14 秒 | 在画面中央的转身位置站稳 | “停” |
| 14-18 秒 | 用 3 至 4 个自然小步转身 | “正常转身” |
| 18-24 秒 | 正常速度走回画面左侧原来的行走起点 | “走回来” |
| 24-28 秒 | 转向椅子方向 | “转向椅子” |
| 28-34 秒 | 走到椅子正前方约半米的位置 | “走到椅子前” |
| 34-38 秒 | 正常坐下，不用手猛撑 | “坐下” |
| 38-43 秒 | 保持坐姿 | “保持” |
| 43-48 秒 | 正常起身并站直 | “起身” |
| 48-55 秒 | 原地自然站立 | “保持” |

#### 动作结束后怎么拍页面

1. 导演喊“正常动作结束”，演示者继续留在画面中站立。
2. 算法操作员等待 8 至 12 秒，让最后一个分析窗口完成。
3. 屏幕录制员不要停止，依次拍：
   - 实时人体框和姿态：3 秒；
   - 真实处理进度：3 秒；
   - 步态、坐站、近跌倒和跌倒状态分支：共 6 秒；
   - 当前风险结果：5 秒；
   - 运行诊断：5 秒。
4. 正常动作可能不会生成 `AlgorithmEvent`，因为普通 0 级观测不回调。保留页面“未生成”的真实状态，不伪造低风险 JSON。
5. 算法操作员在停止前保存当前 `/demo/live-status` 状态。
6. 点击“停止检测”。
7. 屏幕录制员和主摄停止录制。
8. 文件分别命名为：
   - `LIVE-NORMAL-01-T1-camera.mp4`；
   - `LIVE-NORMAL-01-T1-screen.mov`；
   - `LIVE-NORMAL-01-T1-status.json`。

#### 后期旁白

> 系统先获取人体目标，保持连续轨迹，再检查姿态质量和时间连续性。正常行走、转身和坐站形成有效观测。普通 0 级状态不发送告警事件，因此未生成 AlgorithmEvent 是正常结果，不代表系统没有运行。

#### 这条什么时候算拍完

- 全身始终入框，跟踪和姿态有效。
- 正常动作没有出现 3/4 级高风险告警。
- 主摄、屏幕录制和状态 JSON 对应同一个 `session_id`。
- 如果正常动作出现 3/4 级告警，将这条记为误报候选，不能作为正式低风险对照。

### 第 4 段：受控失衡现场实拍（成片 1:28-2:20）

这一段只拍一次受控失衡，不重复拍正常动作。

#### 开始前的站位

1. 摄像头、椅子、灯光和地贴保持与第 3 段完全一致。
2. 稳定支撑物放在画面中央偏右的位置；演示者走到它旁边后，伸手即可抓住。
3. 安全员站在演示者后侧半臂距离，保证可以立即扶住，但尽量不进入算法画面。
4. 主摄和屏幕录制员开始录制。
5. 场记记录素材编号 `LIVE-NEAR-FALL-01-T1`。

#### 建立新的监测会话

1. 算法操作员再次点击“开始检测”。
2. 页面生成新的 `request_id` 和 `session_id`，场记立即记录。
3. 不能复用正常动作的 `session_id`。
4. 等待视频连接、人体框、`track_id` 和姿态质量全部就绪。
5. 安全员说“安全确认”。
6. 导演倒数：“3、2、1，受控失衡开始。”
7. 演示者抬右手到肩部 1 秒再放下，作为两路画面的同步点。

#### 演示者按秒执行

| 动作时间 | 演示者怎么做 | 安全员怎么做 |
|---:|---|---|
| 0-8 秒 | 在画面左侧的行走起点自然站立 | 保持保护位 |
| 8-14 秒 | 从画面左侧的行走起点正常走到前方约 3 米、画面中央的转身位置 | 跟随但不入画 |
| 14-17 秒 | 在画面中央的转身位置站稳 | 确认支撑物位置 |
| 17-21 秒 | 用自然小步转向画面中央偏右的稳定支撑物 | 保持半臂距离 |
| 21-26 秒 | 正常走到稳定支撑物旁、伸手可以抓到的位置 | 准备保护 |
| 26-27 秒 | 向支撑物方向横向迈一个 20 至 30 厘米恢复步，躯干轻微偏移 | 不接触，除非动作失控 |
| 27-29 秒 | 用惯用手抓稳支撑物，另一脚跟进一步恢复平衡 | 随时准备扶住 |
| 29-32 秒 | 保持扶物站立 | 观察是否站稳 |
| 32-36 秒 | 缓慢恢复直立并松开支撑物 | 确认站稳后再让其松手 |
| 36-46 秒 | 原地自然站立 | 保持保护位 |

禁止跳跃、交叉脚绊倒、跪地、倒地和闭眼失衡。未触发算法时也不能要求演示者把动作做得更危险。

#### 动作结束后怎么拍页面

1. 导演喊“受控失衡结束”，演示者继续站立 10 秒。
2. 算法操作员最多再等待 12 秒，观察风险事件和时间轴。
3. 如果出现风险事件，屏幕录制员按这个顺序拍：
   - 风险等级、风险分数和置信度：5 秒；
   - 近跌倒分支和其他分支：6 秒；
   - 事件时间轴：4 秒；
   - `AlgorithmEvent` JSON：8 秒；
   - 运行诊断：5 秒。
4. 场记核对 JSON 中的 `session_id` 与本条记录一致。
5. 算法操作员在停止前保存 `/demo/live-status` 状态。
6. 所有页面证据都拍完后，才能点击“停止检测”。停止后页面会清空当前结果，不能先停再补拍 JSON。
7. 屏幕录制员和主摄停止录制。
8. 文件分别命名为：
   - `LIVE-NEAR-FALL-01-T1-camera.mp4`；
   - `LIVE-NEAR-FALL-01-T1-screen.mov`；
   - `LIVE-NEAR-FALL-01-T1-status.json`。

#### 后期旁白

> 在摄像头、场地、配置和模型版本不变的情况下，我们把输入动作改为受控失衡和扶物恢复。系统根据现场观测生成风险事件，并输出触发因子、建议动作和证据窗口。具体等级和分数均来自本次真实会话。

#### 这条什么时候算拍完

- 动作安全，没有倒地或失控。
- 产生的事件可以追溯到本条 `session_id`。
- 页面结果、JSON、状态文件和录屏显示一致。
- 如果 12 秒后仍未生成预期事件，保存本条为漏检候选并停止；排查算法后再补拍，不加大动作危险度，不使用模拟结果替换。

### 第 5 段：受控跌倒现场实拍（成片 2:20-3:15）

这一段拍“从站立到倒地并保持侧卧”的完整过程。它必须作为第三个独立的真实直播会话拍摄，不能使用本地视频、回放或模拟结果。

#### 人员和动作底线

1. 只允许年轻演示者执行，不得由老人、身体不适者或没有倒地训练的人尝试。
2. 一名有相关经验的安全负责人全程指挥动作，另安排两名保护员分别守在保护垫的头侧和脚侧。
3. 如果现场没有符合上述条件的演示者和安全负责人，导演直接取消这一段，不临时教普通成员摔倒。
4. 演示者只做一次安全负责人事先验收过的侧向受控倒地，不做向后直摔、向前扑倒、绊脚、跳起后倒地或头部着地。

#### 布置倒地区域

1. 摄像头位置、拍摄方向、灯光、服装和算法 Release 保持不变。
2. 把受控失衡使用的稳定支撑物和椅子移出倒地区域，防止演示者碰撞。
3. 在画面中央铺设一整块防滑专业保护垫；保护垫必须覆盖演示者从站立位置到最终侧卧位置，四角压平，下面不得有电线或硬物。
4. 保护垫可以在画面中出现。成片角标写“受控动作，专业保护垫”，不得通过取景或后期假装这是真实意外跌倒。
5. 演示者站到保护垫边缘内侧，侧身面对主摄，保证站立、下降和倒地后的全身都在画面内。
6. 安全负责人检查演示者与墙、桌角和设备之间至少留出一人身长度，随后说“场地安全”。

#### 开始第三次监测

1. 主摄先开始录制并说“主机已录”。
2. 屏幕录制员开始录制工作台并说“屏幕已录”。
3. 场记记录素材编号 `LIVE-FALL-01-T1`。
4. 算法操作员确认上一条受控失衡会话已经停止，然后点击“开始检测”。
5. 页面生成新的 `request_id` 和 `session_id`，场记立即记录；不得复用前两条会话的编号。
6. 等待“视频输入：已连接”、人体框、`track_id` 和姿态质量全部出现。
7. 演示者先抬右手到肩部 1 秒再放下，作为主摄与屏幕录制的同步点。
8. 两名保护员退到画面边缘的保护位置，安全负责人最后询问“演员准备好了吗”；演示者明确回答“准备好”。
9. 安全负责人说“可以开始”后，导演才倒数：“3、2、1，受控跌倒开始。”

#### 演示者按秒执行

| 动作时间 | 演示者怎么做 | 其他人员怎么做 |
|---:|---|---|
| 0-8 秒 | 在保护垫边缘内侧自然站立，双脚稳定，全身侧对主摄 | 两名保护员保持保护位，导演喊“保持” |
| 8-13 秒 | 沿保护垫缓慢向画面中央走 2 至 3 步，在保护垫中央站稳 | 安全负责人确认最终倒地范围内没有障碍物 |
| 13-16 秒 | 保持站立，等待唯一一次动作口令 | 导演不提前喊，安全负责人再次观察保护垫是否移动 |
| 16-19 秒 | 听到“侧向倒地”后，按训练动作屈膝降低重心，身体向保护垫一侧连续下降，依次让大腿外侧、髋部和侧躯干接触保护垫，最终侧卧；下巴收紧，头部不接触地面，不用伸直的手臂撑地 | 只有安全负责人喊动作口令；保护员随时准备终止动作 |
| 19-29 秒 | 保持侧卧，不翻滚、不立刻起身；正常说话并向安全负责人示意身体无不适 | 安全负责人先口头确认状态，不遮挡摄像头；任何不适立即喊停并救护 |
| 29-35 秒 | 继续侧卧，等待导演说“动作记录完成” | 算法操作员观察页面是否出现跌倒状态和风险事件 |
| 35 秒后 | 在安全负责人和保护员协助下先坐起，确认无头晕后再站立并离开保护垫 | 主摄继续拍到演示者安全离场，不催促起身 |

动作必须由安全负责人按演示者已经掌握的倒地技术现场校正。表格描述的是镜头中需要出现的动作结果，不能代替专业动作训练。

#### 倒地后怎么拍页面

1. 演示者开始侧卧后，算法操作员立即看工作台，但不要点击“停止检测”。
2. 最多等待 12 秒，观察跌倒状态、风险等级和事件时间轴。
3. 如果出现风险事件，屏幕录制员按顺序拍摄：
   - 跌倒状态分支：5 秒；
   - 风险等级、风险分数和置信度：5 秒；
   - 事件时间轴：4 秒；
   - `AlgorithmEvent` JSON：8 秒；
   - 运行诊断：5 秒。
4. 场记核对页面和 JSON 中的 `session_id` 与 `LIVE-FALL-01-T1` 本条记录一致。
5. 算法操作员在停止前保存 `/demo/live-status` 状态。
6. 页面证据保存完成后，算法操作员点击“停止检测”，屏幕录制员和主摄再停止录制。
7. 文件分别命名为：
   - `LIVE-FALL-01-T1-camera.mp4`；
   - `LIVE-FALL-01-T1-screen.mov`；
   - `LIVE-FALL-01-T1-status.json`。

#### 后期旁白

> 这一条由受过倒地训练的演示者在专业保护垫上完成，动作、现场视频输入和算法判断同步发生，不使用回放。系统持续观察从站立、快速姿态变化到倒地保持的完整过程，并根据本次真实会话输出结果。

#### 这条什么时候算拍完

- 演示者安全完成动作并由安全负责人确认无不适。
- 站立、下降、倒地和侧卧阶段全身始终入框，没有被保护员遮挡。
- 主摄、屏幕录制、状态 JSON 和页面事件属于同一个 `session_id`。
- 如果 12 秒后仍未生成预期事件，将本条如实记录为漏检候选并停止。不得要求演示者加速、加大冲击或连续重拍。

### 第 6 段：把三组结果放在一起（成片 3:15-3:32）

这一段不再拍演员，只做后期画面对照。

1. 画面左侧放第 3 段正常动作结果，角标写“正常动作·现场实拍”。
2. 画面中央放第 4 段受控失衡结果，角标写“受控失衡·现场实拍”。
3. 画面右侧放第 5 段受控跌倒结果，角标写“受控跌倒·现场实拍”。
4. 三组只使用各自会话的真实结果，不能把不同拍摄次数的动作和 JSON 拼在一起。
5. 三组按相同顺序展示：
   - `session_id`；
   - 是否生成 `AlgorithmEvent`；
   - 风险等级/风险分数；
   - 触发事件；
   - 建议动作；
   - 证据窗口。

## 三、现场只需要的最小检查

正式开拍前只检查以下项目，不在拍摄流程里展开：

- 摄像头固定，全身和双脚始终入框；自动巡航、自动追踪和自动变焦已关闭。
- 正常动作、受控失衡和受控跌倒使用同一摄像头、拍摄方向、灯光、服装和 Release；受控跌倒只增加明确入镜的专业保护垫。
- 真实流已经通过烟测，工作台显示服务在线、模型就绪。
- 如果导入合成个人基线，工作台必须始终显示“合成正常基线，仅用于算法机制演示”。三组现场实拍只加载正常范围周期，不能加载合成偏离周期制造高风险结果。
- 受控失衡旁边有固定支撑物、软垫和专职安全员。
- 受控跌倒由受过倒地训练的年轻演示者执行，专业保护垫、安全负责人和两名保护员全部到位。
- 所有真人已授权，所有敏感信息已遮挡。

## 四、重拍规则

只允许因为以下原因重拍：

- `RETAKE-TECH`：无首帧、丢帧、人物出框、遮挡、录屏失败或页面错误；
- `RETAKE-ACTION`：演员走错点、漏动作或没有按口令执行；
- `STOP-SAFETY`：动作失控、地面打滑、支撑物移动或演员不适。

正常动作出现高风险告警时记录为误报候选；受控失衡或受控跌倒未触发时记录为漏检候选。不得删除日志后只保留“好看”的结果，也不得要求演员增加危险动作。受控跌倒因技术问题需要重拍时，必须先让演示者休息并由安全负责人重新确认；不得为了镜头效果连续倒地。
