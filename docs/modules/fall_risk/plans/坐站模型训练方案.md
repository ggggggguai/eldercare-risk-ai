# 坐站模型训练方案

更新时间：2026-08-10

状态：训练与评估方案。2026-08-10 已按专项执行任务书完成 P0-P3 的合成基础设施，真实连续标签与模型训练仍阻塞。本文描述目标任务、数据门禁、实验协议和模型替换条件，不代表连续坐站模型已经训练完成、通过验证或达到部署要求。当前能力和实测状态仍以跌倒风险模块 README、代码、机器校验报告及 `reports/` 下的实验产物为准。

## 1. 目标与边界

本方案面向跌倒风险固定算法路线中的“坐站转换能力分析”分支。模型只消费经过人体检测与跟踪、姿态关键点提取、质量控制和时序平滑后的序列，不跳过中间层直接从视频输出最终风险。

坐站建模必须拆成三个任务：

```text
cleaned pose sequence
  -> 事件定位：什么时候发生 sit_to_stand / stand_to_sit
  -> 相位分割：坐稳、准备、转换、站稳等逐帧状态
  -> 事件级动作/功能 proxy：正常、缓慢、失败及局部能力线索
```

三个任务的计划任务标识分别为：

```text
sit_stand_event_localization_v1
sit_stand_phase_segmentation_v1
sit_stand_action_proxy_v1
```

若未来取得独立功能量表、重复坐站测试或纵向结局，再单独建立：

```text
sit_stand_functional_proxy_v1
```

该任务当前受 `functional_proxy_v1` 无真实参考终点阻塞，不能用动作类别标签替代。

边界约束：

- 当前 `sit_stand_risk_score` 是跌倒模块内部的局部能力线索，不是未来跌倒概率、医学诊断或临床量表结果。
- 坐站分支只服务于 `module=fall_risk`，不生成跨模块综合风险。
- 动作标签 `A04/B06/C01` 只能监督“正常/缓慢/失败起身”的可观察动作 proxy，不能自动监督临床功能风险。
- 归一化 2D 单目坐标得到的距离、速度、角度、摇晃和接触均为 proxy。
- 没有椅子、扶手、墙面 ROI 或真实接触标签时，腕部轨迹只能输出 `support_contact_proxy`，不能声称识别了真实扶手或扶墙接触。
- 任何学习模型都必须保留规则 baseline；低质量、任务契约不匹配、checkpoint 加载失败、推理异常或超时均回退规则路径。

## 2. 当前事实

### 2.1 已实现能力

仓库当前已经实现：

- `src/elderly_monitoring/modules/fall_risk/sit_stand.py` 中的坐站事件状态机和规则评分，版本为 `sit-stand-risk-rule-v0.1`。
- 按 `person_id + track_id` 独立处理 cleaned pose 序列。
- 使用肩、髋、膝、踝 8 个核心点完成事件几何与质量覆盖计算；腕部为可选弱证据。
- 识别 `sit_to_stand` 和 `stand_to_sit` 候选，低质量时输出 `unknown_transition`。
- 输出耗时、失败尝试、躯干前倾角、站后摇晃、疑似支撑、站稳时间和中间特征。
- 使用 `duration/failed_attempt/trunk_forward/post_stand_sway/support_usage/stabilization_time` 六个规则分量计算局部分数。
- 低质量事件输出 `sit_stand_risk_score=0.0` 和 `insufficient_sit_stand_quality`，不会把不可用输入直接当成高风险。
- 离线入口 `scripts/collect/run_fall_sit_stand.py` 和合成序列回归测试 `tests/test_fall_risk_sit_stand.py`。
- 实时 10 秒窗口内存链路；坐站分支当前运行门禁要求至少 8 帧、有效 FPS 不低于 4、窗口覆盖不少于 1 秒、最大 gap 不超过 1 秒。

当前配置契约为：

```text
current_backend = rule_baseline
model_version = sit-stand-risk-rule-v0.1
input_format = cleaned_pose_jsonl
fallback = rule_baseline
```

### 2.2 尚未完成能力

- 当前动作片段标签不等于经过复核的事件 onset/offset；`boundary_precision=exact` 也需确认是否是真实转换边界，而非来源 clip 边界。

## 3. 三个子任务及输入输出

### 3.1 任务一：事件定位

目标：在连续背景中定位一次坐到站或站到坐转换，输出方向、开始、结束及疑似重复/失败尝试。

```text
输入：连续 cleaned pose [T,V,C] + timestamp + quality mask
输出：event_start/event_end + transition_type + confidence + quality
```

首轮输出契约建议为：

```json
{
  "task": "sit_stand_event_localization_v1",
  "transition_type": "sit_to_stand",
  "start_time": 12.4,
  "end_time": 15.1,
  "confidence": 0.78,
  "failed_attempts_proxy": 1,
  "quality_coverage": {},
  "model_version": "..."
}
```

监督要求：

- 必须有真实连续视频中的事件开始、结束和方向标签。
- 背景窗口必须来自显式复核的非坐站区间，不能把未标注背景自动当成 negative。
- 同一事件的所有窗口必须属于同一 partition。
- `A03` 可监督 `stand_to_sit`，`A04/B06/C01` 可监督 `sit_to_stand`；标签边界是否等于真实事件边界必须先审计。
- 失败尝试需要事件内部尝试次数或失败区间标注；只有 `C01` 类别不足以恢复精确尝试次数。

首轮对照：现有规则状态机、HMM/结构化状态机、轻量事件 TCN。学习模型必须在连续视频而非预裁剪动作片段上评估误报。

### 3.2 任务二：逐帧相位分割

目标：给连续序列的每一帧分配相位，用于稳定事件边界、解释动作过程和计算持续时间。

建议首版相位字典：

| 相位 | 含义 | 适用方向 |
|---|---|---|
| `background` | 非本次坐站事件或无法确定 | 两者 |
| `seated_stable` | 坐姿稳定 | 两者 |
| `rise_preparation` | 起身前躯干前倾或动量准备 | 坐到站 |
| `rising` | 髋部抬升、膝髋伸展的主要转换段 | 坐到站 |
| `standing_stabilization` | 已基本站起但仍在调整稳定 | 坐到站 |
| `standing_stable` | 站姿稳定 | 两者 |
| `lowering` | 从站姿向坐姿下降的主要转换段 | 站到坐 |
| `seated_stabilization` | 已接近坐姿但仍在调整 | 站到坐 |

椅面离座和接触时刻在单目 2D 中未必可见。首版将 `seat_off_proxy`、`seat_contact_proxy` 作为可选边界属性，不强制伪造成精确相位。

```text
输入：连续 cleaned pose [T,V,C] + quality mask
输出：每帧 phase probability + phase label + boundary confidence
```

启用条件：

- 完成逐帧相位标注规范、双人复核和边界一致性审计。
- 每个核心相位具有足够的独立人员/样本组和至少三个可用来源组；达不到时合并相邻相位或保持阻塞。
- 标注区分“看不见/不确定”与真实 `background`，质量差不能被训练成某一动作相位。
- 只有窗口或动作片段标签时，禁止插值生成逐帧相位真值。

首轮模型为状态机相位 baseline 与 MS-TCN++。ASFormer 只在逐帧标签规模、独立性和前序模型稳定后比较。

### 3.3 任务三：事件级动作与局部能力 proxy

目标：在已定位事件上区分可观察动作表现，并输出可解释的局部能力线索。

首版动作任务：

```text
normal_sit_to_stand vs slow_sit_to_stand vs failed_sit_to_stand
```

当前数据不支持正式三分类，因此分阶段执行：

1. 先用规则特征和 `A04` 建立正常起身分布，不发布监督分类结论。
2. `B06/C01` 只作为 auxiliary 训练或错误分析，不能进入正式测试分母。
3. 困难类补齐 primary、三分区和独立人员覆盖后，再冻结三分类任务。
4. 获得独立功能真值后，另建 `sit_stand_functional_proxy_v1`，不复用动作分类概率冒充功能风险。

建议输出拆开：

```text
action probabilities   -> normal / slow / failed
event features         -> duration / attempts / sway / stabilization / support proxy
action_proxy_score     -> 可观察困难动作分数
functional_proxy_score -> 当前必须为 unavailable，直到独立真值就绪
```

模型进入 shadow mode 前，不直接用未经校准的 `action_proxy_score` 替换现有 `sit_stand_risk_score`。

### 3.4 共享表征与运行顺序

推荐运行顺序：

```text
quality-controlled pose
  -> event localizer
  -> phase segmenter（标签门禁通过后启用）
  -> event feature aggregation
  -> action proxy classifier
  -> calibrated local score + confidence + explanations
  -> rule fallback / disagreement diagnostics
```

事件定位器和相位分割器可以共享轻量 TCN 编码器，但三个输出头必须使用各自监督 mask、损失和指标。共享编码器不能把缺失的相位或功能真值伪造成标签。

当前机器校验结果为：

```text
training_ready.action_type = false
functional_proxy_v1 = blocked
cross-partition leakage issues = 0（统一 split 当前报告）
```

无泄漏只说明现有分组没有跨分区冲突，不表示坐站三任务已经训练就绪。当前最直接的阻断是：困难起身无 primary、`C01` 无 validation 覆盖、逐帧相位标签为空、独立功能真值为空。

## 5. 数据门禁与标注补充

### 5.1 事件定位标签

每个连续视频至少标注：

- `event_id`、人员/保守源组、方向、onset、offset。
- 成功、缓慢、失败或中止结果。
- 尝试次数，以及每次尝试的开始和回落区间。
- 边界精度 `exact/approximate/unknown` 和不可见原因。
- 椅子/床边是否可见、下肢是否出画、遮挡、多人、相机切换和跟踪 ID 切换。
- 事件前后至少各保留一个可复核背景上下文窗。

背景 negative 必须由标注员明确确认。优先覆盖站立、静坐、正常步行、弯腰、下蹲、跪地、躺下、协助降低身体和跌倒等易混淆动作。

### 5.2 相位标签

逐帧相位标注先做小规模双人试标，冻结字典后再扩展。门禁至少包括：

- 每个事件有唯一方向，允许 `uncertain` 帧但不能强制归类。
- 相位顺序满足有限状态约束；违反顺序的样本进入复核。
- 报告双人 frame agreement、边界误差和 segment agreement。
- 对 seat-off/seat-contact 不可见的样本，只标可观察相位，不推断家具接触。
- 训练、验证、测试分别达到最小独立人员/保守源组覆盖后才冻结。

### 5.3 动作与功能标签

`B06/C01` 升级为 primary 必须满足现行 v3 规则：至少 30 个独立 sample group 且至少 3 个 source group，并同时满足 review、eligibility 和 split 覆盖。仅达到计数下限仍不够，还需要：

- train/validation/test 均有独立人员或保守源组。
- 每类覆盖老人域、多个视角和不同椅高/场景。
- `B06` 与 `C01` 边界由判定规则明确区分：一次成功但缓慢，对比失败/回落/多次尝试。
- test 由冻结前未参与建模的保管流程管理。

独立功能任务需要另外收集可合法使用的参考终点，例如 STS-5 完成时间、五次坐站失败次数、TUG/SPPB 子项或纵向功能变化。动作类别不得作为这些真值的同义词。

### 5.4 困难负样本

必须分层纳入：

- `A05 controlled_squat`、`A06 controlled_bend`、`A09 kneel_or_floor_activity`。
- `A07 controlled_lie_down`、`A11 assisted_sit_or_lowering`。
- 快速但可控坐下、床边转移、侧身落座和位置调整。
- `D01-D05` 跌倒/坐姿跌倒，防止快速高度变化被误判为坐站。
- 遮挡、低光、下肢出画、多人交叉、摄像机移动和 ID 切换。
- 正常扶椅、拿物和手腕靠近画面边缘，防止支撑 proxy 捷径。

训练内 hard-negative mining 只能使用 train 的 group split 或 OOF 错误。validation/test 失败案例不得反馈训练。

## 6. 姿态预处理、时间规范化与张量

### 6.1 姿态提取与质量控制

首轮固定与实时主线一致的 `YOLOv8-Pose + ByteTrack`，避免同时改变姿态后端和坐站模型。每个样本产物必须可追溯：

- 原视频、动作标签、manifest 和 split hash。
- 姿态模型、跟踪器、阈值、坐标系统和版本。
- `person_id/track_id`、FPS、源时间戳和帧号映射。
- 核心点覆盖、插值比例、跳点、最大 gap、有效 FPS 和 ID 切换。
- 椅子或支撑上下文是否可观察；没有检测器时显式记为 unavailable。

腕部缺失不能阻断髋、膝、踝和躯干的核心坐站指标。低质量窗口必须拒识或降级，不能用全零填充伪装正常。

### 6.2 时间规范化

训练与实时必须基于秒而不是原始帧数对齐。正式数据审计后冻结：

- 目标有效 FPS。
- 上下文窗口秒数和目标帧数。
- 最大相邻时间 gap。
- 最小有效帧比例和核心点覆盖。
- 短缺失插值上限及因果/非因果平滑边界。

当前实时门禁 `4 FPS / 8 帧 / 1 秒覆盖 / 1 秒最大 gap` 只是工程下限，不自动等于训练最优契约。建议首轮比较 4、8、12 FPS 和 4、6、8 秒上下文，在 validation 内冻结后再训练候选；不能根据 test 结果选择窗口。

### 6.3 张量设计

首轮沿用步态模型可复用的 14 点骨架概念，但为坐站增加明确的相位和上下文通道。计划输入：

```text
shape = [T, 14, C]
joints = 12 个 COCO 兼容关节 + pelvis center + shoulder center
base channels = [x, y, dx/dt, dy/dt, quality]
optional derived channels = [relative_height, joint_angle_proxy, valid_mask]
```

处理顺序：

```text
时间重采样
  -> pelvis centering
  -> torso-scale normalization
  -> 时间导数
  -> quality/valid mask
  -> 训练窗口与事件特征
```

为了保留起身高度变化，骨盆中心化不能删除所有全身垂直位移信息。至少保留相对图像/人体框高度、髋-踝关系或归一化高度通道，并做消融验证。训练和实时必须使用同一坐标变换顺序。

### 6.4 事件级结构化特征

结构化 baseline 使用当前规则已有字段及其质量：

- duration、failed attempts proxy。
- hip/shoulder vertical displacement。
- leg extension delta。
- trunk forward angle proxy。
- post-stand sway、stabilization time。
- support contact proxy。
- 可用帧比例、核心点覆盖、插值、跳点和最大 gap。

质量字段既用于拒识，也用于分层评估。不得让“低质量等于困难起身”成为模型捷径。

## 7. 无泄漏划分与冻结协议

### 7.1 分组优先级

split group 按以下最大保护单元生成：

```text
已知人员/家庭
  > physical_event_id 或多视角同一事件
  > source_group_id
  > sample_group_id
  > 原视频及其所有派生 clip/window
```

同一人的所有动作、相邻窗口、多视角和 KINECAL 多动作必须进入同一 partition。人员未知时使用保守来源池，不把不同文件假设成不同人。

### 7.2 禁止方式

以下结果不能作为替换证据：

- 随机帧、随机窗口或随机 clip 切分。
- 同一事件、视频或 sample group 跨 partition。
- 用 test 选择窗口、epoch、模型、阈值、校准器或融合权重。
- auxiliary/ignore 进入正式测试分母。
- 在完整数据上拟合 scaler、插值器或特征选择器后再切分。
- 将同一 KINECAL 参与者的 STS-5 与其他动作拆到不同集合。

### 7.3 建议协议

坐站专用 split 需要在补齐标签后计划新增，不能直接把当前统一 split 宣布为 frozen。建议：

1. 外层按人员/保守源组形成锁定 test。
2. 开发集内部做 group-aware train/validation 或 repeated group cross-validation。
3. 候选按 validation 最差来源表现和校准排序。
4. checkpoint、阈值和校准器冻结后，只运行一次外层 test。
5. NTU 正常动作可作为大规模正常压力集；老人域困难起身必须有独立测试组。

当某类 test 独立组不足时，该任务标为“不可评估”，不合并 auxiliary 或放宽分组填补数字。

### 7.4 评估单位

同时报告：

- 帧级：仅相位诊断。
- 事件级：事件定位和动作 proxy 的主要单位。
- 人员/保守源组级：置信区间和泛化结论单位。
- 数据源级：分别报告，不能由总体平均掩盖最差域。
- 正常观察时长：每小时误报和连续背景稳定性。

## 8. Baseline 与候选模型

| 路线 | 输入 | 监督 | 输出 | 启用条件 | 主要风险 | 降级 |
|---|---|---|---|---|---|---|
| 规则状态机 | 2D 姿态与阈值 | 无/少量校准 | 事件、规则特征、局部分 | 当前可运行 | 视角、椅高和 FPS 敏感 | 保持为最终 fallback |
| HMM/结构化状态机 | 离散/连续姿态特征 | 少量边界/相位 | 相位与事件边界 | 有复核边界 | 状态假设过强 | 回退规则状态机 |
| Logistic Regression | 事件聚合特征 | 动作类别/proxy | 类别概率 | 合法 group split | 线性表达有限 | 规则分 |
| LightGBM/EBM | 事件聚合特征 | 动作类别/proxy | 类别概率与贡献 | 依赖已存在或获批 | 小样本过拟合、来源捷径 | Logistic/规则 |
| 事件 TCN | `[T,V,C]` | 事件边界和动作标签 | 边界、方向或动作概率 | 边界审计及困难类门禁通过 | clip 捷径、边界偏移 | 状态机 |
| 多任务 TCN | 共享时序表征 | 事件+方向+动作，多头 mask | 多任务输出 | 各头有合法监督 | 缺失标签互相污染 | 单任务 TCN/规则 |
| MS-TCN++ | 逐帧张量 | 真实逐帧相位 | phase probabilities | 相位标签与独立组达标 | 过分割、长背景偏置 | 状态机相位 |
| ASFormer | 逐帧张量 | 真实逐帧相位 | 长时相位分割 | MS-TCN++ 已稳定且数据充分 | 小样本不稳定、延迟 | MS-TCN++ |
| ST-GCN++/CTR-GCN | 骨架图时序 | 事件/动作/相位 | 骨架协调表征 | TCN 基线完成且样本充分 | 忽略家具接触、复杂度上升 | TCN |
| PoseC3D/RGB 辅助 | 姿态热图或 RGB crop | 事件/上下文标签 | 椅子和接触上下文 | 隐私、算力、标签均通过 | 场景记忆和隐私成本 | 骨架/规则 |

RGB 或姿态热图只能作为受控辅助分支，不成为默认实时主线，也不能通过背景纹理识别数据源来取得虚假高分。

## 9. 损失、采样、不平衡与增强

### 9.1 多任务损失

计划的共享 TCN 首轮损失：

```text
L = lambda_event * L_event
  + lambda_direction * L_direction
  + lambda_action * L_action
  + lambda_phase * L_phase
  + lambda_boundary * L_boundary
```

每个头都有独立监督 mask。首轮只启用已有合法真值的项；`lambda_phase=0` 直到逐帧相位标签就绪，功能任务不在该损失中伪造。

候选损失：

- 事件/方向/动作分类：类别加权 cross entropy；focal loss 只作消融。
- 相位分割：frame CE + MS-TCN++ temporal smoothing loss。
- 边界：onset/offset 分类或距离回归，仅消费 exact/经复核边界。
- 概率校准不进入 test 后处理调参。

### 9.2 采样与权重

同一事件的所有窗口总权重固定，避免长事件或高 FPS 视频支配训练：

```text
sample_weight
  = tier_weight
  * 1 / windows_in_event
  * class_balance_weight
  * source_balance_weight
```

建议首轮 `primary=1.0`，auxiliary 只在 train 中以 `0.25-0.5` 做预注册消融；ignore 权重为 0。困难类 batch 过采样不得改变事件级评估分母。

### 9.3 数据增强

只在 train 应用并逐项消融：

- 左右镜像；同步交换左右关节。
- 小幅尺度、平移和旋转扰动。
- 基于实测姿态误差的小幅坐标噪声。
- 随机短时关键点缺失和质量 mask 更新。
- 随机帧丢失后按正式时间契约重采样。
- 轻微时间速度缩放，但不得把正常动作合成为“缓慢”或“失败”真值。

禁止通过标签定义直接生成困难起身：例如单纯拉长 `A04` 时间后标 `B06`，或人工回落后标 `C01`。这类合成只能做鲁棒性测试，不能进入正式监督分母。

## 10. 训练、调参、早停与校准

### 10.1 调参顺序

1. 冻结坐站标签审计、任务定义和 group split。
2. 跑规则状态机及结构化 Logistic/LightGBM/EBM baseline。
3. 在 event localization 上比较 HMM 与事件 TCN。
4. 冻结目标 FPS、上下文秒数、归一化和核心通道。
5. 比较 TCN 隐藏宽度、dilation、dropout 和任务头。
6. 加入 auxiliary 与 source-balanced sampling 消融。
7. 相位标签就绪后单独训练 MS-TCN++。
8. 生成 train OOF 预测，拟合校准器或受正则融合器。
9. 最后才比较 ASFormer、ST-GCN++/CTR-GCN 和 RGB 辅助分支。

### 10.2 首轮默认范围

以下只是 validation 内搜索范围，不是已实现配置或临床标准：

| 参数 | 首轮候选 |
|---|---|
| target FPS | 4 / 8 / 12 |
| context seconds | 4 / 6 / 8 |
| TCN hidden channels | 32 / 48 / 64 |
| kernel size | 3 / 5 |
| dilations | `1,2,4,8` 或 `1,2,4,8,16` |
| dropout | 0.1 / 0.2 / 0.3 |
| learning rate | `3e-4 / 1e-3` |
| weight decay | `1e-5 / 1e-4` |
| batch size | 8 / 16 / 32，受事件长度和显存限制 |
| seeds | 42 / 43 / 44 |

### 10.3 早停、阈值与校准

- 事件定位早停依据 validation 事件 F1 与边界 IoU 的预注册组合，不用窗口 accuracy。
- 相位模型依据 segmental F1 和 edit score，不能由长背景支配的 frame accuracy 早停。
- 动作 proxy 依据最差来源 balanced metric、PR-AUC 和 Brier。
- 分类阈值、事件合并 gap、最短持续时间和连续确认次数只在 validation 冻结。
- 比较 temperature scaling、sigmoid 和 isotonic；小样本时优先更简单校准器。
- 每个候选至少 3 个 seed，报告均值、标准差和最差结果。

## 11. 指标与报告

### 11.1 事件定位

必须报告：

- 事件级 Precision、Recall、F1。
- 匹配阈值下的 boundary IoU。
- onset/offset 绝对误差及 P50/P95。
- 重复检测数、漏检数和方向混淆矩阵。
- 每观察小时 FP，分正常活动类型统计。
- 检测延迟和事件结束确认延迟。
- 低质量拒识覆盖及拒识后的有效事件 Recall。

### 11.2 相位分割

必须报告：

- frame macro F1。
- segmental F1@10/25/50。
- edit score。
- mIoU 和各相位 IoU。
- 过分割/欠分割次数与边界误差。
- frame accuracy 只作次指标。

### 11.3 动作与局部能力 proxy

类别条件具备后报告：

- AUROC、PR-AUC；多分类采用 macro/one-vs-rest 并同时给每类结果。
- 预注册阈值下的灵敏度、特异度、Precision、F1。
- Brier、log loss、ECE 和 reliability diagram。
- 正常/缓慢/失败混淆矩阵。
- 分数与规则 duration/attempts/stabilization 的分层一致性。
- 拒识覆盖、拒识后性能和 fallback 比例。

没有独立功能真值时，不报告“功能风险 AUROC”或“未来跌倒预测指标”。

### 11.4 分层、区间与部署指标

按条件分别报告：

- 人员或保守 source group 的 cluster bootstrap 95% CI。
- 数据源、视角、老人域/非老人域、椅高可见性。
- 低光、遮挡、下肢出画、低分辨率和多人。
- 支撑使用可见/不可见、质量分位和动作 subtype。
- CPU/MPS/CUDA 的 P50/P95 推理延迟、峰值内存和吞吐。
- 可用事件比例、拒识率、规则 fallback、模型错误/超时和连续窗口抖动。

某一层只有单一保守来源组或样本过少时，置信区间和该层指标标为“不可评估”，不得改用窗口级伪独立 CI。

## 13. 暂定研发验收门槛

以下为补齐数据后预注册的研发候选门槛，不是临床或产品标准。

### 13.1 事件定位门槛

```text
validation event F1 >= 0.75
validation boundary IoU median >= 0.60
onset/offset median absolute error <= 0.50 sec
每个主要数据源 event recall >= 0.60
相对规则 baseline：F1 提升 >= 0.05，或相同 recall 下 FP/hour 明显下降
```

### 13.2 相位分割门槛

```text
macro frame F1 >= 0.70
segmental F1@50 >= 0.60
edit score >= 0.70
每个核心相位 IoU >= 0.40
```

### 13.3 动作 proxy 门槛

只有三类均为 primary 且三分区具备独立组覆盖后启用：

```text
validation macro F1 >= 0.65
每类 recall >= 0.55
Brier 相对未校准 baseline 改善
三个 seed 结论方向一致
最差来源表现不低于预注册下限
```

若学习模型相对规则/结构化 baseline 提升小于 3 个百分点且置信区间高度重叠，优先保留更简单模型。若随机窗口结果异常高，先审计来源、人物、场景、动作 clip 和姿态质量泄漏，不判断模型有效。

## 14. 主链替换与规则 fallback 门槛

候选 checkpoint 只有同时满足以下条件才可替换默认规则主路径：

- checkpoint `task`、标签字典、关节顺序、通道顺序、FPS、窗口秒数和归一化契约完全匹配。
- 数据、标签、manifest、split、配置、代码、依赖和 checkpoint hash 完整记录。
- 人员/保守源组、视频、事件和相邻窗口泄漏校验为 0。
- 与规则、HMM 和结构化模型在同一冻结协议下完成比较。
- 阈值、事件合并、校准器和融合权重只用 train/validation 确定。
- test 在模型冻结后按一次性流程运行，未参与返工选择。
- 每个主要来源、困难负样本、低质量和视角分层无不可接受回归。
- 真实 RGB 视频 shadow mode 记录模型/规则分歧、失败案例和拒识原因。
- CPU/MPS/CUDA 延迟、内存和稳定性满足实时服务预算。
- 低质量、任务不匹配、checkpoint 错误、异常和超时均显式回退规则。
- 输出保留 `score_source/model_score/fallback_score/fallback_reason/quality_coverage/model_version` 等可诊断字段后再接入。

安全覆盖原则：

```text
model valid and contract matched -> 模型分 + 规则解释/对照
model unavailable/error/timeout  -> rule_baseline
input quality insufficient       -> unavailable，不把缺失当低风险
```

当前规则模块对低质量离线输入输出 0 分；实时融合层必须依据分支三态和 `fusion_mask` 将其视为 unavailable，而不是零风险证据。

## 18. 风险、限制与不可声明结论

| 风险 | 处理原则 |
|---|---|
| 困难起身样本过少 | 保持 auxiliary，补独立人员和三分区，不用窗口扩增冒充人数 |
| `B06` 人员全为 unknown | 按四个保守场景池分组，不能声称人级泛化 |
| `C01` 无 validation 覆盖 | 重新治理并冻结专用 split；当前结果不可正式选择模型 |
| clip 边界不是真实事件边界 | 连续视频抽样复核，边界任务只消费合格标签 |
| 正常类主要来自 NTU | 分来源报告、老人域外测，审计摄像机和场景捷径 |
| 2D 视角与椅高敏感 | 归一化、视角分层、质量拒识和跨域验证 |
| 支撑不可见 | 只输出 `support_contact_proxy`，需要家具/接触标签才升级 |
| 质量成为类别线索 | quality mask、拒识、分层指标和去质量消融 |
| 相邻窗口伪独立 | 事件/人员整体分区与事件总权重归一化 |
| KINECAL 与 RGB 域不一致 | 参与者级域内辅助任务，独立 RGB 姿态验证 |
| 大模型小样本过拟合 | 强 baseline、小模型、多 seed、最差来源选择 |
| 测试集反复使用 | 冻结前预注册，候选冻结后一次性运行 |
| 模型分数不可解释 | 概率校准、规则特征对照、可靠性图和失败案例 |

在当前证据下，不得声明：

- 已经训练或部署坐站 TCN/MS-TCN++/ST-GCN++。
- 已经可靠识别真实扶手、墙面或家具接触。
- 动作分类分数等于临床坐站能力或未来跌倒概率。
- 当前统一 split 已经是坐站任务的冻结正式 split。
- 当前 `A04/B06/C01` 数量足以证明跨老人、家庭、视角和设备泛化。
- KINECAL 跌倒史 proxy 能证明未来提前预警。
- 合成测试或规则阈值能证明真实识别准确率。

本方案的决策原则是：先把事件、相位和动作/功能 proxy 的监督边界分清，再扩大模型；在困难类、边界和独立功能真值不足时，保留规则 baseline 和明确阻塞状态，比输出一个无法验证的高分模型更可靠。
