# 跌倒风险动作与事件标签 v3 训练版设计稿

更新时间：2026-08-04

状态：`implemented_event_supervision_ready_action_type_incomplete`

> 本文只定义供模型训练使用的动作标签和事件标签。两套 schema、迁移器、校验器及独立 v3 JSONL 已实现；现行 v2 根标签保持不变。2026-08-04 的哈希绑定项目裁决已补齐 NTU 全片跌倒边界、受审 C03 near-fall 正例和任务级 hard negative，现行 `fall_event` 与 `near_fall_event` 监督门禁通过，`action_type` 门禁仍未通过。实时数量和哈希以 `reports/fall_risk/training-labels-v3-validation.json`、统一 split 和模块 README 为准。

## 1. 目标与边界

### 1.1 唯一目标

v3 训练版只追求一件事：尽量减少错误、含混、重复和泄漏标签，使动作分类、事件检测和时序模型获得准确监督信号。

具体目标：

1. 动作标签描述画面中可见的局部动作或状态。
2. 事件标签描述可独立匹配的 `fall` 或 `near_fall` episode。
3. 动作和事件可以关联，但不能由同一记录混合表达。
4. 明确正样本、人工确认负样本和必须忽略的时间窗。
5. 同一物理事件只有一个 canonical 事件标签，多个来源只作为证据。
6. 标签能直接转换为分类、分割、检测和多任务学习目标。

### 1.2 不在本文范围内

本文不设计：

- release、eligibility、coverage sidecar 或评估报告结构。
- 比赛指标、PR-AUC、摄像机小时或置信区间。
- 运行时告警生命周期、业务 severity、风险等级和处置动作。
- 完整人工复核平台、任务分配系统或测试集治理。
- 临床有效性、个人长期风险或跨模块风险融合。
- motion/posture/stability 三维跌倒后状态体系。

为了避免训练污染，任务级 `negative/ignore` 窗口仍保留在事件标签中。它们是监督标签的一部分，不是评估治理附属物。

不再建立 observation、canonical、coverage、review 和 release 多层文件。每个 v3 标签本身就是模型消费的 canonical 记录，并通过 `source_refs` 保留来源；两类标签共用一份按资产和来源关系生成的防泄漏 split。

### 3.2 公共字段

动作和事件标签共用：

```text

label_id

asset_id
video_id
content_sha256
subject_id
source_group_id
sample_group_id
track_id

start_frame
end_frame_exclusive
frame_index_base
start_time
end_time_exclusive

target_status
boundary_precision
quality_flags
training_tier

source_refs
annotator_id
reviewer_ids
review_status

```

字段规则：

- `frame_index_base=0`。
- 区间统一使用 `[start_frame, end_frame_exclusive)`。
- v2 inclusive `end_frame` 迁移时必须加 1。
- 帧号是视频标签的权威边界；时间从 manifest 的有理 FPS 或可靠逐帧时间戳计算。
- `subject_id` 不可靠时必须有保守 `source_group_id`，用于防止同源样本跨 split。
- `content_sha256` 绑定原始媒体内容；重复文件不能因路径不同被分到不同 split。
- `sample_group_id` 绑定同一原片段的相邻窗口、重复裁剪和派生样本。
- `track_id` 只表示视频内目标，不替代 `subject_id`。
- `source_refs` 是来源数组，至少保留来源类型、来源记录 ID、来源路径和 SHA-256。
- 自由文本不得包含真实姓名、邮箱、手机号或直播地址。

### 3.3 目标、边界和训练等级

`target_status`：

```text
confirmed
single_person_assumed
uncertain
```

`boundary_precision`：

```text
exact
approximate
unknown
```

`quality_flags` 可组合：

```text
partial_occlusion
heavy_occlusion
low_light
motion_blur
low_resolution
off_screen
multi_person_uncertain
camera_cut
```

`training_tier`：

| 值 | 用途 | 最低条件 |
|---|---|---|
| `primary` | 主监督训练、验证和测试 | 类别明确、目标可靠、来源有效、复核达标 |
| `auxiliary` | 弱监督、预训练或单独消融 | 父类可靠但 subtype、边界或目标存在轻微不确定 |
| `ignore` | 不进入监督 loss | U01、重遮挡、目标不明、来源冲突或父类不确定 |

不使用主观连续 `label_confidence`。训练代码不得把 `auxiliary` 自动当作与 `primary` 等权；是否使用辅助标签必须由训练配置显式控制。验证和测试默认只使用 `primary`。

## 4. 动作标签设计

### 4.1 动作标签字段

`action_labels_v3.jsonl` 在公共字段之外增加：

```text
action_id
action_family
action_type
action_type_training_tier
action_attributes
linked_event_id
```

约束：

- `action_id` 是稳定字典编号。
- `action_family` 是父类，用于层级分类和稀疏类别合并。
- `action_type` 是模型可训练的具体动作。
- `training_tier` 控制父类监督，`action_type_training_tier` 独立控制具体动作监督；后者不得高于前者。
- `action_attributes` 只放可独立观察的属性，例如 `assisted`、`support_used`、`rapid`。
- `linked_event_id` 可为空；C03-C05、D01-D04 应在事件确认后关联 canonical event。
- 同一时间可以有一个主要动作和一个事件，不因关联而重复计算为两个事件样本。
- U01 是唯一例外：保留 `action_id=U01`，`action_family/action_type=null`，并强制 `training_tier=ignore`。

### 4.2 动作字典

#### A 类：正常与困难负样本动作

| ID | `action_family` | `action_type` | 主要作用 |
|---|---|---|---|
| A01 | walk | `normal_walk` | 正常步态对照 |
| A02 | turn | `normal_turn` | 不稳定转身负例 |
| A03 | sit_down | `controlled_sit_down` | 快速下沉、跌倒负例 |
| A04 | sit_to_stand | `normal_sit_to_stand` | 坐站困难负例 |
| A05 | squat | `controlled_squat` | 快速下沉负例 |
| A06 | bend | `controlled_bend` | 快速下沉、跌倒负例 |
| A07 | lie_down | `controlled_lie_down` | 跌倒最重要困难负例之一 |
| A08 | support_use | `routine_support_contact` | 快速扶物恢复负例 |
| A09 | floor_transition | `kneel_or_floor_activity` | 跌倒和快速下沉负例 |
| A10 | step_adjustment | `normal_step_adjustment` | 踉跄负例 |
| A11 | assisted_transition | `assisted_sit_or_lowering` | 跌倒和恢复判断负例 |

A07-A11 已纳入统一 v2 CVAT 动作标准，v3 继续保留其层级动作语义。没有这些困难负样本时，模型容易把主动躺下、正常扶椅、跪地或被协助坐下误判为跌倒/近跌倒。

#### B 类：功能异常动作

| ID | `action_family` | `action_type` |
|---|---|---|
| B01 | walk | `slow_walk` |
| B02 | walk | `dragging_walk` |
| B03 | walk | `shuffling_walk` |
| B04 | walk | `swaying_walk` |
| B05 | turn | `unstable_turn` |
| B06 | sit_to_stand | `slow_sit_to_stand` |

B 类属于动作分类或功能特征任务，不自动生成 fall/near-fall 事件。

#### C 类：明显失衡机制

| ID | `action_family` | v3 `action_type` | 与 v2 的区别 |
|---|---|---|---|
| C01 | sit_to_stand | `failed_sit_to_stand` | 保持动作标签，不生成基础事件 |
| C02 | support_use | `sustained_support_walk` | 持续扶物不等于 near-fall |
| C03 | balance_loss | `stumble` | 动作本身不写 recovery 结论 |
| C04 | balance_loss | `rapid_support_reaction` | 接触证据放入属性，不自动声称 near-fall |
| C05 | balance_loss | `rapid_body_drop` | 动作本身不写 recovery 结论 |

C03-C05 是否形成 near-fall，由事件标签中的恢复和未跌倒结局决定。若失衡继续发展为 fall，动作标签仍可保留，但不能生成 near-fall 正例。

#### D 类：跌倒动作和跌倒后状态

| ID | `action_family` | v3 `action_type` |
|---|---|---|
| D01 | fall | `forward_fall` |
| D02 | fall | `lateral_fall` |
| D03 | fall | `backward_fall` |
| D04 | post_fall_state | `post_fall_immobile` |

D04 不再命名为 `long_static_after_fall`。标签只声明已观察到静止，不能从短视频片段推断已经达到某个持续时长阈值。

#### U 类：忽略区间

U01 不作为模型类别。它生成 `action_id=U01`、`action_family/action_type=null`、`training_tier=ignore` 的动作区间，并要求在 `note` 中记录原因。对应帧从动作和事件监督 loss 中移除。

### 4.3 动作边界

| 动作 | start | end exclusive |
|---|---|---|
| walk | 第一步明显开始移动 | 停止或切换动作后的第一帧 |
| turn | 明显开始改变朝向 | 朝向稳定后的第一帧 |
| sit_down | 身体开始可控下降 | 坐稳后的第一帧 |
| sit_to_stand | 身体开始离座或上升 | 站稳后的第一帧 |
| squat/bend | 开始可控下蹲或屈曲 | 稳定或恢复直立后的第一帧 |
| balance_loss | 首次明显失衡 | 恢复稳定或进入 fall 的第一帧 |
| fall | 开始失去支撑 | 接触并稳定在倒地/倒卧状态后的第一帧 |
| post_fall_immobile | fall 结束后开始静止 | 明显移动、离画或视频结束后的第一帧 |

边界无法可靠判断时使用 `approximate` 或 `ignore`，不得为满足 schema 伪造精确帧。

## 5. 事件标签设计

### 5.1 事件标签字段

`event_labels_v3.jsonl` 在公共字段之外增加：

```text
physical_event_id
task_type
label_role

event_type
event_subtype
event_outcome
hard_negative_type
subtype_training_tier

onset_frame
peak_frame
impact_frame
recovery_frame

linked_action_ids
contact_evidence
```

`task_type` 只允许：

```text
fall_event
near_fall_event
```

`label_role`：

| 值 | 含义 | event 字段 |
|---|---|---|
| `positive` | 已确认目标事件 | `event_type/subtype/outcome` 必填 |
| `negative` | 人工检查的目标任务负窗口 | event 字段为空，`hard_negative_type` 必填或为 `background` |
| `ignore` | 该任务无法判断 | event 和 negative 字段均为空 |

同一视频窗口可以针对不同任务各有一条记录。例如真实 fall 对 `fall_event` 是 positive，对 `near_fall_event` 可以是 `progressed_to_fall` hard negative。

`training_tier` 控制父事件监督，`subtype_training_tier` 独立控制方向或机制监督。例如 LE2I 官方窗口可作为 `fall` 父类 primary，而方向仅来自单人 CVAT 动作时只能作为 subtype auxiliary；训练代码不得用 subtype 的不确定性降级可靠父类，也不得反向把父类 primary 当作 subtype primary。

### 5.2 正事件字典

| `event_type` | `event_subtype` | `event_outcome` |
|---|---|---|
| `fall` | `forward`、`lateral`、`backward`、`unknown` | `fell` |
| `near_fall` | `stumble_recovery`、`rapid_support_recovery`、`rapid_body_drop_recovery`、`sudden_stop_recovery`、`other_recovery`、`unknown` | `recovered_without_fall` |

fall 定义：明确失去支撑并形成倒地、倒卧或与较低支撑面接触后的稳定落位。

near-fall 定义必须同时满足：

1. 存在明显失衡机制。
2. 随后恢复稳定。
3. 没有形成 fall。

只有 C03/C04/C05 动作而无法观察恢复时，事件标签必须为 `ignore`；未经复核的候选保留在 v2/标注工具输出中，不进入 v3 模型标签，不能作为 near-fall positive。

### 5.3 事件关键帧

| 字段 | fall | near-fall |
|---|---|---|
| `onset_frame` | 开始失去支撑 | 明显失衡开始 |
| `peak_frame` | 最大失衡，可空 | 最大失衡，可空 |
| `impact_frame` | 首次明确接触，可空 | 必须为空 |
| `recovery_frame` | 必须为空 | 恢复稳定，primary 正例必填 |
| `end_frame_exclusive` | 接触并稳定后的第一帧 | recovery 后第一帧 |

关键帧无法观察时保持空，不由动作名称推断。LE2I 官方窗口只能支持 start/end 时，不伪造 peak、impact 或方向。

### 5.4 动作与事件的一致性

| 动作标签 | 可关联事件 | 规则 |
|---|---|---|
| C03 `stumble` | near-fall 或 fall | 恢复且未跌倒才是 near-fall |
| C04 `rapid_support_reaction` | near-fall 或 fall | 需确认明显失衡；日常扶物不是事件 |
| C05 `rapid_body_drop` | near-fall 或 fall | 需排除正常坐下、下蹲和弯腰 |
| D01-D03 | fall | 方向 subtype 一致 |
| D04 | 父 fall | 必须发生在 fall 结束之后 |
| A/B/C01/C02 | 通常无事件 | 不从动作规则自动生成事件正例 |

`contact_evidence`：

```text
observed
proxy
unknown
not_applicable
```

只有明确看到手或身体接触支撑物，或存在可靠家具 ROI 标注时使用 `observed`。仅凭腕部轨迹使用 `proxy`。

### 5.5 hard negative 字典

fall 任务至少包含：

```text
controlled_sit_down
controlled_lie_down
squat_or_kneel
bend
bed_entry_or_exit
assisted_lowering
occlusion_or_camera_motion
```

near-fall 任务至少包含：

```text
normal_turn
normal_step_adjustment
routine_support_contact
fast_but_controlled_sit
controlled_squat
controlled_bend
exercise_or_stretch
progressed_to_fall
```

规则：

- negative 必须是人工确认的目标任务负窗口。
- 未标注背景不能自动生成 negative。
- hard negative 窗口要覆盖事件前后足够上下文，但不能包含未处理的 ignore 帧。
- 同一原始窗口重复裁剪时共享 `sample_group_id`；属于同一事件时还应共享 `physical_event_id`，防止跨 split 泄漏。

## 6. 来源合并与复核

### 6.1 source refs

`source_refs` 中每个来源至少包含：

```text
source_type
source_record_id
source_annotation_path
source_annotation_sha256
source_label_id
```

允许一个标签引用 LE2I、CVAT 或人工复核等多个来源。来源多不等于样本多。

### 6.2 同一物理事件

若 LE2I 官方窗口和 CVAT D01-D03 指向同一跌倒：

1. 只生成一个 event label。
2. `source_refs` 同时保留两个来源。
3. `linked_action_ids` 关联 D01-D03 动作。
4. 来源边界冲突时由人工复核确定 canonical 边界。
5. `physical_event_id` 保持稳定，不能因新增来源产生第二个训练样本。

不能确认是否为同一事件时，相关标签设为 `auxiliary` 或 `ignore`，不得猜测合并。

### 6.3 最小复核规则

为保证监督准确性：

- near-fall primary 正例必须双人复核，确认“明显失衡、恢复、未跌倒”。
- C04/C05、来源边界冲突和目标身份冲突必须双人复核。
- clear D01-D03 或 LE2I official fall 可在来源 QA 后成为 primary；方向不可靠时 subtype 使用 `unknown`。
- negative/hard-negative 至少单人逐窗确认；与正事件容易混淆的窗口应抽样双人复核。
- reviewer 不得根据模型预测修改标签；模型失败案例可以进入下一版独立复核队列，但不能原地修改当前测试标签。

`review_status`：

```text
unreviewed
single_annotated
source_verified
single_reviewed
double_reviewed
adjudicated
```

primary near-fall 只能使用 `double_reviewed` 或 `adjudicated`。

## 7. 训练样本生成规则

### 7.1 动作模型

- 输入标签使用 `action_family` 和 `action_type` 两级目标；父类 loss 读取 `training_tier`，具体动作 loss 读取 `action_type_training_tier`。
- 稀疏 subtype 先训练父类，不用单个或极少样本建立独立输出头，也不得用父类 primary 状态替代具体动作层级。
- U01、`training_tier=ignore` 和严重遮挡帧从 loss mask 中移除。
- `primary` 用于主监督；`auxiliary` 只能在单独配置和消融中使用。
- D01-D03 与 event label 共享 episode group，不能拆到不同 split。

### 7.2 事件模型

- positive 来自 `label_role=positive`。
- negative 只来自 `label_role=negative`。
- ignore 帧不参与正负 loss。
- event detector 可以在标签窗口前后增加固定 context，但 context 中的其他事件和 ignore 必须重新遮罩。
- fall 与 near-fall 可以训练为两个二分类头，或共享 backbone 的层级多任务头；标签文件不预先绑定具体模型结构。
- near-fall subtype 数据不足时只训练 near-fall 父类，不训练 subtype classifier。

### 7.3 类别启用门槛

为防止极少样本类别制造虚假监督，采用以下默认工程门槛：

- 少于 10 个独立 `sample_group_id`：`action_type_training_tier=ignore`，不得进入具体动作 loss。
- 10-29 个独立 sample group，或来源少于 3 个 `source_group_id`：最多为 `auxiliary`，只能用于显式启用的辅助头。
- 至少 30 个独立 sample group 且来自至少 3 个 source group：具体动作才允许为 `primary`。
- 每条记录的最终具体动作层级取上述类别门槛与父类 `training_tier` 中更低者。

这些门槛是防止明显过拟合的工程下限，不是统计有效性保证。具体动作 primary 类及三分区覆盖必须以现行校验报告为准；事件级 C03 裁决不能反向证明所有 C03/C04/C05 动作 subtype 都满足独立训练门槛。

### 7.4 split 防泄漏

训练、验证和测试至少按以下组合分组：

```text
subject_id
source_group_id
physical_event_id
content_sha256
sample_group_id
parent/derived asset relation
adjacent/window group
```

同一事件的不同来源、相邻窗口、不同裁剪和派生姿态必须进入同一 partition。无法恢复人员身份时使用更保守的 source group，不能按单个 clip 随机划分。

## 8. v2 到 v3 映射

| v2 | v3 动作 | v3 事件处理 |
|---|---|---|
| A01-A06 | 保留并规范命名 | 作为事件 hard-negative 候选，不自动生成 negative |
| B01-B06 | 保留动作 | 不生成事件正例 |
| C01/C02 | 保留动作 | 不生成 near-fall 正例 |
| C03 | `stumble` | 人工确认后生成 near-fall/fall 或 ignore |
| C04 | `rapid_support_reaction` | 人工确认后生成 near-fall/fall 或 ignore |
| C05 | `rapid_body_drop` | 人工确认后生成 near-fall/fall 或 ignore |
| D01-D03 | 保留跌倒动作 | 生成一个 canonical fall；多来源去重 |
| D04 | `post_fall_immobile` | 关联父 fall，不生成第二个事件 |
| U01 | ignore 动作区间 | 为 fall/near-fall 生成 ignore mask |
| LE2I fall window | 无新增动作 | 生成 fall/unknown，可关联已有 D01-D03 |
| LE2I 0/0 | 无 | 不生成 negative，除非人工确认具体时间范围 |
| v2 severity | 删除 | 不进入动作或事件训练标签 |

迁移器允许确定性完成：

- inclusive end 转 exclusive end。
- 字段重命名和来源数组构造。
- D01-D03 与明确同一 LE2I fall 的去重候选生成。
- U01 ignore mask 生成。

迁移器禁止自动完成：

- C03-C05 到 near-fall positive 的升级。
- D04 到 long-static 的升级。
- 未标注背景到 negative 的升级。
- 来源冲突边界、目标身份或恢复结局的猜测。

## 9. 校验规则

校验器至少拒绝：

- 空区间、负帧号、inclusive/exclusive 混用或 frame/time 不一致。
- 未知 action/event 枚举或无效字段组合。
- `label_role=positive` 缺 event type/outcome。
- `label_role=negative` 同时填写 event type。
- `label_role=ignore` 被标为 primary。
- primary near-fall 缺 recovery frame 或双人复核。
- near-fall recovery 发生在 onset 之前或 end 之外。
- fall 填写 recovery frame，near-fall填写 impact frame。
- D04 没有父 fall、早于父 fall 结束或跨目标关联。
- 一个 `physical_event_id` 对应多个 fall/near-fall canonical positive。
- source ref 缺路径、记录 ID 或 hash。
- U01 被转换为正常类或负类。
- `action_type_training_tier` 与当前类别样本/来源门槛不一致，或高于父类 `training_tier`。
- v2 severity 出现在 v3 标签。
- `target_status=uncertain` 或 heavy occlusion 被标为 primary。
- 同一 physical event、派生窗口或内容 hash 跨 split。

校验输出只需报告：

```text
schema errors
class counts by training tier
positive/negative/ignore counts by task
source and subject/source-group counts
missing hard-negative categories
duplicate physical events
cross-split leakage
excluded records and reasons
```

校验器必须绑定当前 manifest、动作标签、事件标签和 split hash。旧 v2 `fall_event_v1` split 不能直接用于 v3；split 缺失、hash 过期或存在跨分区泄漏时，`training_ready` 必须保持 false。

- [x] v2 根标签未被覆盖，v3 写入独立文件。

- [x] action 与 event 不再共用同一个 `event_type` 平面枚举。

当前实现已经满足结构、迁移、双向引用、动作 subtype 分层、统一 split、事件 hard-negative 覆盖和校验相关条目。仍未满足的是部分动作 subtype 三分区覆盖、普通连续背景分母、老人域外部验证、长期风险真值和冻结测试治理；在无法新拍数据的条件下，只能继续复用现有授权媒体和开放数据补足可验证证据，不能拼接短片伪造连续或纵向数据。

满足上述条件只表示标签结构可供模型训练，不表示样本数量充分、模型准确率达标或真实场景泛化已经得到验证。
