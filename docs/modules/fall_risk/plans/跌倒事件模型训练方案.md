# 跌倒事件模型训练方案

## 1. 方案状态、目标与边界

**方案状态：拟议，尚未实现、训练或产生正式指标。** 当前跌倒主链使用规则状态机；学习模型只有通过数据、无泄漏 split、冻结评估、延迟、稳定性、校准和复现门禁后，才可申请替换默认识别路径。当前能力和待办分别以[模块 README](../README.md)、[算法工程骨架](../../../architecture/算法工程骨架.md)和[任务清单](../../../tasks/README.md)为准，本方案不重复维护实现状态。

目标是在固定、无泄漏的 `fall_event` 划分上提高事件级 Recall、F1 和 PR-AUC，同时约束每摄像机小时误报、onset/告警延迟、跨人和跨来源泛化、概率校准误差及部署成本。“效果好”指真实长视频中及时、稳定、可校准地检出跌倒，并控制正常快速动作误报，不指窗口 Accuracy 或测试集上的单一高分。

本方案不训练 `near_fall_event`，不做个体行为基线和最终风险融合，不输出医学确认，也不修改 `AlgorithmEvent` 契约。近跌倒必须按独立标签、split 和指标训练评估；规则和 episode 状态机继续承担 baseline、安全覆盖与 fallback（[算法事件输出接口](../../../interfaces/算法事件输出接口.md)）。

## 3. 任务与事件边界

### 3.1 目标事件

**拟议定义：** `fall_event` 是目标人物从可控支撑状态进入不可控下降，最终到达地面或明显更低支撑面的事件。标注点按可观察证据定义：

| 边界/点 | 拟议语义 | 监督准入 |
|---|---|---|
| onset | 首次持续的失衡或不可控下降；短暂弯腰、主动坐下的起始不算 | 主事件必需；现行 v3 正例也要求 `onset_frame` |
| peak | 下降速度、躯干角速度或姿态变化最强点 | 可靠时作边界辅助，缺失不补造 |
| impact | 身体与地面/低支撑面接触的可见点或可靠 proxy | 仅可靠标签启用；遮挡时不从音频或规则猜测 |
| 倒地稳定 | 快速下降结束且低位姿态开始稳定；作为 fall 事件结束候选 | exact/复核边界用于定位头，approximate 只用于事件分类 |
| 跌倒后静止 | fall 结束后的独立状态区间，不属于 fall 正例长度 | 可作可靠辅助头；现行运行时 `confirmed_static` 只表示工程静止条件满足 |

跌倒后恢复不改变 `event_outcome=fell`。现行 v3 明确禁止 fall 正例填写 `recovery_frame`，D04 只作为关联的 post-fall 状态（`configs/data/fall_risk_event_label_schema_v3.json`、`src/elderly_monitoring/modules/fall_risk/training_labels_v3.py`）。

### 3.2 类别边界

以下均不得并入 fall 正例：`near_fall_event`（失衡后恢复且未跌倒）、快速但可控坐下、正常躺下、下蹲、弯腰、跪地/地面活动、床边上下床、被协助降低身体。跌倒后静止是状态证据，不是第二个 fall。遮挡、出画、多人目标不确定、ID switch 或相机运动若无法确认目标与结局，应为 `ignore`，而不是 positive/negative。上述动作字典与 v3 角色约束见[标签字典](../data/跌倒风险标签字典.md)、[数据集标注规范](../data/数据集标注规范.md)和 `configs/data/fall_risk_event_label_schema_v3.json`。

## 4. 样本准入与数据门禁

| 角色 | 准入条件 | 用法 |
|---|---|---|
| primary positive | v3 `task_type=fall_event`、`label_role=positive`，媒体/来源 hash 可追溯，目标可确认，资产 eligible；边界头进一步只消费 exact 或经裁决边界 | 主损失与正式评估 |
| auxiliary positive | clip/近似边界或方向证据不足，但来源合法、事件结局明确 | 仅 train 中预训练或降权消融；不进正式分母 |
| 普通 negative | 人工确认的明确非跌倒背景窗，覆盖真实运行时长，且不是未标注背景 | 训练背景与误报率压力测试 |
| hard negative | 人工逐窗确认、经过复核、`source_type=manual_v3`，类型属于 fall 契约 | 主训练必需，按类型/来源均衡 |
| ignore | `U01/uncertain`、目标不确定、严重遮挡/出画、边界或结局无法确认、技术隔离资产 | 从所有 loss、阈值和正式分母移除 |

当前 fall hard negative 的机器门禁要求 7 类 primary negative 全部出现：`controlled_sit_down`、`controlled_lie_down`、`squat_or_kneel`、`bend`、`bed_entry_or_exit`、`assisted_lowering`、`occlusion_or_camera_motion`。负例还必须清空事件/关键点字段、填写 `hard_negative_type`、具备 `manual_v3` 来源且不能停留在 `unreviewed/source_verified`；`background` 合法但不替代 7 类覆盖。当前仅 `squat_or_kneel` 有 6 条三视角裁决负例，且全部在 train；其余 6 类和 validation/test negative 仍缺（`src/elderly_monitoring/modules/fall_risk/training_labels_v3.py`、`reports/fall_risk/training-labels-v3-validation.json`）。解除条件是：每类均有跨来源、跨保护组的复核窗口，train/validation/test 都有 primary positive 与 negative，重新生成 split 后 `training_ready.fall_event=true`；具体最小组数为**待预注册项**。

每个训练样本还必须绑定 manifest 内容 hash、标签/来源 hash、`subject_id`、`source_group_id`、`sample_group_id`、`physical_event_id`、原视频、视角、目标 `track_id/target_status`、边界精度、质量标记和复核状态。LE2I TXT `0/0`、辅助动作标签、弱目录标签和未标注背景均不得自动转成 primary negative（[数据集标注规范](../data/数据集标注规范.md)）。

## 5. 无泄漏 split 与测试治理

训练必须使用 v3 统一分区，并按下列保护关系求连通分量后整体分配：

```text
subject_id / 可恢复的同一人员
  + source_group_id
  + sample_group_id
  + physical_event_id
  + content_sha256 / 原视频及所有派生窗口
  + 同一物理事件的多视角、相邻裁剪和重编码副本
```

禁止随机帧/窗口划分，禁止同一事件的重叠窗口跨分区，禁止先在全量数据拟合归一化器。test 冻结后不得用于阈值、校准器、困难负样本挖掘、窗口/模型选择或失败驱动返工；测试只在 checkpoint、后处理和容器指纹冻结后由保管人执行一次。当前 v3 split 规则和 hash 绑定见 `src/elderly_monitoring/modules/fall_risk/training_labels_v3.py`、`data/splits/fall_risk/training_labels_v3/split.json`。

## 6. 拟议输入契约

实时模型输入为单目标骨架张量 `[T,V,C]`。`V=17`，关节顺序固定为 COCO：`nose, left_eye, right_eye, left_ear, right_ear, left_shoulder, right_shoulder, left_elbow, right_elbow, left_wrist, right_wrist, left_hip, right_hip, left_knee, right_knee, left_ankle, right_ankle`，与 `src/elderly_monitoring/modules/fall_risk/pose.py` 一致。**拟议通道**包括：

- joint：以髋中心平移、躯干或 bbox 尺度归一化的 `x/y`，同时保留图像归一化高度/框尺度以免抹掉快速下降；
- bone：按固定人体拓扑计算骨向量和长度；
- motion：按真实时间戳计算一阶/二阶位移，gap 后不伪造连续速度；
- quality/mask：原始置信度、质量权重、有效/插值/跳变标记、关节 mask、帧 mask、目标连续性；
- timing：相对时间、实际 `delta_t`、有效 FPS 和 gap 标记。

建议先搜索 2/4/6 秒历史的**因果窗口**，时刻 `t` 只能使用 `<=t` 的帧，告警延迟按实际 `alert_time-onset` 计算。离线非因果上限可使用对称上下文，但必须单列为 oracle，不得作为实时结果。质量层当前会短间隙插值、跳变抑制和平滑（`src/elderly_monitoring/modules/fall_risk/pose_quality.py`）；拟议 builder 必须额外保留未平滑 motion 或多尺度峰值通道，以 max/attention pooling 保护快速下降和 impact，禁止用过度平滑换取表面稳定。

## 7. 性能导向模型路线

| 路线 | 定位 | 选择理由/限制 |
|---|---|---|
| 现行规则状态机 | 必跑 baseline、安全覆盖、fallback | 可解释且已接入，但视角和阈值敏感 |
| **轻量因果膨胀 TCN** | **推荐实时主候选** | 小参数、固定延迟、直接利用 `delta_t/mask/quality`；相较 RGB 更少记忆场景，相较图卷积在当前小规模监督下更易正则化和复现 |
| ST-GCN++ | 骨架强对照 | 检验显式人体拓扑是否带来跨视角收益；算力、样本量和过拟合风险更高 |
| PoseC3D/RGB/教师模型 | 离线非因果上限或蒸馏候选 | 仅在隐私授权、算力、目标 crop 与家具/接触标签充分时启用，不作为默认实时主线 |

推荐 TCN 使用多尺度因果残差块和一个共享编码器；先做单阶段，只有 validation 显示边界碎片且延迟预算允许时才增加因果 refinement stage。预期泛化优势来自归一化骨架、显式质量/mask、较低容量和来源均衡，而不是堆叠模型。所有宽度、层数、dilation、窗口和参数预算均为**待 validation 搜索并预注册**。

## 8. 多任务监督与负迁移控制

拟议总损失为 `L=L_event+lambda_onset*L_onset+lambda_subtype*L_subtype+可选辅助项`，每个头独立 mask：

| 头 | 作用 | 启用条件/风险 |
|---|---|---|
| fall/non-fall | 主事件判断 | primary positive/negative 和 hard-negative 门禁通过 |
| onset/边界 | 提高定位与低延迟 | 只用 exact/裁决边界；approximate 不回归精确点 |
| event_subtype/方向 | 促使学习不同下降运动 | 仅 `subtype_training_tier` 合格；方向与来源强相关时可能负迁移 |
| impact | 保护高速接触峰值 | 仅 impact 人工可靠且非 proxy 时启用 |
| progressed_to_fall | 区分近跌倒与最终跌倒 | 必须由独立、可靠结局标签支持；不得把 near-fall 主任务并入 fall 指标 |
| post-fall 状态 | 约束倒地稳定/静止一致性 | 只在 D04 边界可靠时启用；长静止会拖慢主事件告警，不能支配主损失 |

辅助头若导致主任务最差来源 Recall、FP/hour 或延迟恶化即移除。缺失标签必须 mask，不以 `0` 填充；可比较固定权重与梯度冲突抑制，但不在 test 上选权重。

## 9. 训练与实际效果策略

- **不平衡：** 主损失比较 class-balanced BCE 与 focal loss；按 physical event 归一化窗口总权重，避免长事件/高 FPS 视频支配训练。
- **group-aware sampler：** batch 按来源、保护组、正负例和 hard-negative 类型分层；同组窗口不冒充独立样本。
- **课程学习：** 先用 primary 正例与普通人工负例稳定 onset，再逐步加入 7 类 hard negative；最后只从 train/validation 连续视频挖模型高分误报，经人工复核后保持原 partition。test 永不挖矿。
- **预训练：** 可在 train 分区骨架上做 masked-joint/temporal-order 自监督；可用来源合法的动作骨架做编码器预训练，但必须隔离 test 人员/事件并消融。RGB/PoseC3D 教师只在授权和算力允许时离线训练，以 soft target 蒸馏到 TCN，教师本身不进入默认部署。
- **增强：** 允许左右镜像并交换关节、小幅尺度/平移/旋转、坐标噪声、短时关节缺失、按真实时间戳模拟丢帧和轻微速度扰动。禁止时间反转、跨事件拼接、改变 `fell/recovered_without_fall` 结局、裁掉 onset/impact、把正常动作形变成跌倒或抹平峰值。
- **复现：** 建议固定 3 个预注册 seed；记录随机状态、依赖/代码/数据 hash、完整配置与设备。早停依据 validation 的事件 F1/PR-AUC、Recall 下限和 FP/hour/延迟约束，不用帧级 Accuracy。超参数搜索采用有预算的 group-aware validation；每 epoch 保存 last/best 和优化器状态，原 run 失败后从原 checkpoint 恢复，不覆盖目录。

## 10. 评估协议与分层

| 维度 | 必报指标 | 解释 |
|---|---|---|
| 事件识别 | Precision、Recall、F1、事件 PR-AUC | 主要效果；fall 与 near-fall 分开 |
| 边界/时效 | boundary IoU、onset 绝对误差、`alert_time-onset` 的 P50/P95 | 同时报提前告警和延迟，不能用非因果 onset 冒充告警时间 |
| 长视频误报 | FP/camera-hour、重复告警/事件 | 分母仅使用 `continuous_monitoring_eligible=true` 的有效观察时长 |
| 校准 | Brier、NLL、ECE、可靠性图、预注册阈值 PPV/Recall | 校准器只用 validation 拟合 |
| 状态一致性 | fall 后倒地稳定命中、过早 recovered、unresolved、重复 episode | 检查模型与 `long_static_score`/episode 的组合行为 |
| 部署 | 端到端与模型 P50/P95 延迟、峰值内存、吞吐、模型大小、fallback 率 | 在目标 CPU/MPS/CUDA 和实时采样率分别报告 |

现有评估器已实现一对一事件匹配、PR-AUC、边界 IoU、检测延迟及合法分母下的 FP/hour，但当前协议仍 provisional（`src/elderly_monitoring/modules/fall_risk/evaluation.py`、`configs/evaluation/fall_event_v1.provisional.yaml`）。校准和状态一致性属于**拟议扩展**。

必须按来源、受试者/保守源组、机位、跌倒方向、边界精度、质量层级和 hard-negative 类型分层；另做遮挡、低光、低 FPS、长 gap、ID switch、多人、相机运动、正常快速动作、床边动作和协助动作压力测试。跨来源采用 leave-one-source-out 或预注册外部压力集；组数不足时写“不可评估”，不改用窗口级伪独立置信区间。

## 11. 对照、消融与选择门禁

| 编号 | 实验 | 目的 |
|---|---|---|
| E0 | 当前规则状态机 | baseline 与安全覆盖 |
| E1 | 仅坐标 TCN | 最小学习基线 |
| E2 | E1 + motion | 验证快速下降信息 |
| E3 | E2 + bone | 验证拓扑相对结构 |
| E4 | E3 + quality/mask/timing | 验证缺失、gap 和姿态噪声鲁棒性 |
| E5 | E4 + onset/subtype 多任务头 | 验证定位与辅助监督净收益 |
| E6 | ST-GCN++ 同输入强对照 | 比较显式图建模 |

全部实验必须使用同一标签版本、v3 split、姿态/关节版本和冻结评估协议，只改变表中因素。模型选择先满足 Recall 安全下限，再以 validation 事件 F1/PR-AUC、FP/hour、P95 延迟、ECE、最差来源和多 seed 稳定性排序；具体数值均为**待预注册项**。

替换主路径必须同时通过：v2 formal、`training_ready.fall_event=true`、冻结无泄漏 split、冻结协议与盲测治理；在同一 test 上优于规则且无关键来源/方向/hard-negative 回归；长视频误报、检测延迟、资源、非有限输出、长时间运行、校准与多 seed 复现合格。任何一项不满足就保留规则主路径，不以总体 Accuracy 或复杂度换取通过。

## 12. 推理集成与 fallback

**拟议集成：** 模型先输出独立的 calibrated fall probability、onset 和可用性诊断；只有 checkpoint 的 task、17 关节顺序、通道、FPS/时间戳、窗口、归一化和 hash 全匹配且输出有限时，才映射为学习分支的 `fall_event_score`。现行 `long_static_score` 继续由规则状态机提供，episode 继续管理 `suspected/confirmed_static/recovered/unresolved`，最终仍输出 `module=fall_risk` 的 `AlgorithmEvent`（`src/elderly_monitoring/runtime/fall_state.py`、`src/elderly_monitoring/runtime/realtime_fall_risk.py`）。

学习分支遇到低质量、模型缺失或契约不匹配时输出 `unavailable`；加载/推理异常、超时或 NaN/Inf 时输出 `inference_error`，两者均不伪造 `0.0`，并尝试回到规则 baseline。若规则自身的质量门也失败，则整体保持 `unavailable/inference_error`，不能输出低风险分。模型阴性不得压制规则识别到的强跌倒证据或关闭活跃 episode；当前规则的 `fall_event_score>=0.80` 或 `long_static_score>=0.80` 紧急覆盖保持有效（[模块 README](../README.md)）。规则与模型分歧、score source、质量、fallback 原因、版本和耗时必须进入诊断，但不能改写共享事件必填字段。

## 14. 分阶段计划、停止条件与完成定义

| 阶段 | 交付 | 进入下一阶段条件 |
|---|---|---|
| A 数据解阻 | 7 类 hard negative、普通长背景、边界/目标/来源复核，formal 与 v3 报告 | `training_ready.fall_event=true`，分区正负监督完整 |
| B 协议冻结 | 无泄漏 split、测试保管、事件匹配、阈值选择、校准和资源预算预注册 | frozen hash 与评审记录齐全 |
| C baseline/主候选 | 规则、仅坐标 TCN、推荐因果 TCN 的多 seed validation | 无泄漏，Recall/FP/延迟达到预注册下限 |
| D 强对照与消融 | ST-GCN++、输入流、多任务、增强、预训练消融 | 推荐结论跨 seed/来源稳定，无关键分层回归 |
| E 冻结测试与 shadow | 一次性 test、真实长视频 shadow、资源和异常恢复报告 | 全部门禁通过后才申请主路径替换 |

遇到以下任一情况停止扩模并回到数据/协议：负例或来源覆盖不足；随机窗口分数异常高；最差来源 Recall 明显下降；FP/hour 无合法分母；告警依赖事件后未来帧；模型收益仅来自场景/质量捷径；校准、延迟或多 seed 不稳定；模型阴性会覆盖规则强证据。

完成定义是：数据与协议冻结、推荐因果 TCN 和 ST-GCN++ 在同一输入/split 上可复现比较，事件级与长视频指标、校准、鲁棒性、资源和失败案例齐全，shadow 中 fallback/安全覆盖可审计，并通过替换评审。达到该定义前，结论只能是“候选实验”或“仍阻塞”，不能声明已训练主模型、临床有效或已部署。
