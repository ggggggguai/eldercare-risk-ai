# 自采数据模型增强计划

更新时间：2026-08-11
适用批次：`SCF_MVP_V1`
文档性质：执行计划；G0-G2 的实际结果以 `reports/fall_risk/self_collected_scf_mvp_v1/README.md` 为准。

## 1. 执行结论

`SCF_MVP_V1` 当前最有价值的用途是增强近跌倒困难负例和坐站边界/负例，而不是直接扩大最终跌倒风险模型训练集。

固定优先级为：

1. **P0：近跌倒困难负例与恢复事件增强**。
2. **P1：坐站方向、边界和困难负例增强**。
3. **P2：步态 walking gate 和非步行负例增强**。
4. **P3：跌倒事件规则误报回放，暂不恢复 TCN 训练**。

自采数据不改变以下现状：

- 规则 baseline 继续作为运行主路径、安全覆盖和低质量输入 fallback。
- 不从短动作片段计算合法的连续背景 FP/hour。
- 不使用该批数据声称老人域、临床有效性或正式 test 泛化。
- 不修改或覆盖当前 `splitv3_e71a045eb58489f43dc5fd11`。

## 4. 阶段 G0：来源与标注门禁

### 4.1 实现来源专用导入器

新增 `self_collected_scf_mvp_v1` 专用 importer，不放松通用 CVAT converter 的命名契约。导入器必须：

1. 只接受与审计报告绑定的视频和脱敏 CVAT SHA-256。
2. 严格解析 `Pxx_Sxx_Exxx_<script>_<action>.mp4`。
3. 对 P02 执行经测试验证的坐标变换。
4. 对 P03 要求显式帧映射；无法解释的帧差不得自动偏移。
5. 以内容 SHA-256 合并重复泄漏组，P03 四组重复不得拆分。
6. 只写入 `generated/v2/self_collected_scf_mvp_v1_candidate/`，不覆盖根 v2/v3 标签。

### 4.2 人工复核

进入任何 loss 前必须完成：

- 参与者授权/同意引用和脱敏 subject profile。
- `Pxx` 与实际目标人的审计映射。
- 动作边界、目标框、质量标记的第二人复核。
- C03/C04/C05 的 onset、peak、recovery、`recovered_without_fall` 和联系动作。
- P03 四组重复的 session/场景条件裁决。

### 4.3 G0 验收

| 验收项 | 通过条件 |
|---|---|
| 输入完整性 | 262 个视频和 262 个 CVAT 任务全部绑定 SHA-256 |
| 转换确定性 | 两次全新构建的 candidate JSONL 逐字节一致 |
| 目标归属 | 用于 loss 的记录不再使用 `target_subject=unknown` |
| 重复治理 | 内容重复视频只属于一个保护组，不跨分区 |
| 帧对齐 | P02 坐标变换有 golden 测试；P03 不可解释的记录保持 `ignore` |
| 发布边界 | manifest、根 v2/v3 标签和当前 split 不变 |

## 5. 阶段 G1：冻结模型基线回放

在任何重训之前，用当前规则和 checkpoint 对 262 个视频执行一次固定回放，保存未调参的原始预测。

| 分支 | 回放对象 |
|---|---|
| 近跌倒 | seed 42/43/44 TCN + `near-fall-rule-v0.1` |
| 坐站 | seed 42 TCN + `sit-stand-risk-rule-v0.1` |
| 步态 | context v2 seed 42 + 步态规则 |
| 跌倒事件 | 仅规则主路径，不复用旧 split TCN |

回放报告至少按以下维度分层：

- 参与者、session、动作 ID、相机视角、低光、遮挡、旋转。
- 检测覆盖率、姿态有效率、主轨迹中断、有效 FPS/gap。
- 每个动作类别的预测数、误报数、拒识数和失败案例。

因输入是动作中心短片，本阶段不报告 FP/hour，不把 P01-P05 称为冻结 validation 或 test。

## 6. 阶段 G2：近跌倒增强

### 6.1 数据用法

优先使用以下六类显式负例：

- A02 -> `normal_turn`
- A03 -> `fast_but_controlled_sit`
- A05 -> `controlled_squat`
- A06 -> `controlled_bend`
- A08 -> `routine_support_contact`
- A10 -> `normal_step_adjustment`

C03/C04/C05 只有在恢复证据和 canonical event 双审通过后才作为正例候选。该批数据不包含可靠的 `exercise_or_stretch` 和 `progressed_to_fall`，因此不能单独使八类实际窗口门禁全部通过。

### 6.2 固定实验矩阵

| 实验 | 训练增量 | 目的 |
|---|---|---|
| E0 | 不加自采数据 | 当前 seed 42/43/44 基线 |
| E1 | 只加六类困难负例 | 验证误报是否下降 |
| E2 | E1 + 双审通过的 C03 | 验证绊绊恢复跨域增益 |
| E3 | E2 + 双审通过的 C04/C05 | 验证恢复子型扩展 |

每次标签、manifest 或 split hash 变化后都必须重建 dataset，并重跑 seed 42/43/44，不复用旧 checkpoint。

### 6.3 开发分区

首轮冻结开发分区（2026-08-12）：

- P01/P02/P04：只作 auxiliary train。
- P05：固定为 self-collected challenge validation，不进入 loss。
- P03：排除；帧对齐解决前不进入 loss 或 challenge。
- 重复内容以内容 SHA-256 绑定同一保护组。

执行结果：E1-E3 共完成 9 次训练，均通过现行 validation F1 回归门槛，但 P05 上困难负例改善伴随明显正例代理检出下降，三个实验均为 No-Go。规则和原 checkpoint 保持主路径；详见执行报告。

此分区只是开发 challenge 方案，不是正式 test。若后续修改分区，必须新建 split 版本，不覆盖旧产物。

### 6.4 G2 验收

- 现行 validation 事件 F1 较 E0 下降不超过 1 个百分点。
- self-collected challenge 的六类负例逐类报告误报数、分母和置信区间。
- 三个 seed 的改善方向一致，不只依赖单一 seed。
- 报告来源、参与者和 session 分层，排查相机/来源捷径。
- test 继续为 `null`，不读取 test 姿态或真值。

由于自采参与者少，challenge 指标只用于开发比较，不能升格为正式泛化指标。

## 7. 阶段 G3：坐站增强

### 7.1 数据用法

- A03 和 A04：用于站到坐/坐到站方向、presence 和 boundary head。
- A05/A06/A07：用于下蹲、弯腰、躺下困难负例。
- C05：在 near-fall 恢复事件复核后，用于坐站快速下降压力。
- 标注边界外继续使用 `label_span_mask`，不把未标片段自动当背景。

固定消融：

| 实验 | 训练增量 |
|---|---|
| S0 | 现行 seed 42 连续流基线 |
| S1 | S0 + A03/A04 精确边界 |
| S2 | S1 + A05/A06/A07/C05 困难负例 |

### 7.2 恢复主训练的前置条件

当前坐站阻塞清单明确要求：下一步不是直接增加 seed 或 epoch，而是先补至少 5 camera-hour 连续显式背景、困难负例和来源退化证据。`SCF_MVP_V1` 可解决困难负例的一部分，但不提供 5 camera-hour 连续背景。

因此：

1. 现在可完成标签候选、姿态提取、固定回放和 dataset 构建。
2. 在独立连续背景池补齐前，不恢复 seed 42 正式 pilot。
3. 只有 seed 42 达到 event F1 `>=0.75`、Recall `>=0.85`、困难负例误报 `<10%` 等现行绝对门禁后，才允许 seed 43/44。
4. 不用自采短片替代 FP/hour 分母。

## 8. 阶段 G4：步态和跌倒的有限利用

### 8.1 步态

该批没有 B01-B06 异常步态正例，因此不能提升 validation 异常段规模，也不能解除 `validation_scale`、`action_type_supervision` 或单一来源阻塞。

只允许：

- 使用 A01/A02/A03/A04/A05/A06/A07/A08/A10/C01/C02 作为非异常步态压力数据。
- 增强 walking gate，降低坐下、站起、弯腰、下蹲和躺下被误判为异常步态。
- 仅作 `auxiliary` train，建议沿用现行辅助 tier 权重 `0.35`。
- 对自采来源单列指标，防止模型通过相机/分辨率识别负类。

若现行 validation 最差来源指标回退，或质量/尺度捷径消融显示来源捷径增强，则不保留此增量。

### 8.2 跌倒事件

该批只有 1 条未复核 D03，不能当作跌倒正例增强。在[跌倒事件训练阻塞清单](../../../../reports/fall_risk/fall_event_blockers.md)解除前：

- 仅将 A03/A05/A06/A07/A08/C 类视频用于规则误报回放。
- 不恢复旧 candidate-clip TCN 训练。
- 不将该批数据写成“补齐 fall 正例”。
- 不改变 30 个独立 validation fall、7 类困难负例每类 20 个保护组、100 camera-hour 背景和老人域门禁。

## 9. 新版本分组与防泄漏契约

如果 G0 后允许候选数据进入开发训练，新版本必须满足：

- `subject_id`：经审核的 `p01`-`p05`。
- `source_group_id`：按参与者或更保守的来源组建立，不按 session 拆分。
- `sample_group_id`：以视频内容 SHA-256 和物理事件关系联合生成。
- 同一人、同一内容、同一物理事件的所有标签必须在同一 partition。
- 新建 split ID 和 assignments，不覆盖 `splitv3_e71a...`。
- 旧 checkpoint 只能作冻结基线，不作为新 split 的已完成训练证据。
- 自采 challenge 不命名为 `test`，不与封存 test 混淆。

## 10. 实验报告与验收指标

每个增强版本必须产出：

1. 输入 manifest、labels、assignments、split、配置和姿态缓存 SHA-256。
2. 两次全新 dataset 构建哈希对比。
3. E0/E1/E2/E3 或 S0/S1/S2 固定消融。
4. 规则、结构化 baseline 和 TCN 的同协议对比。
5. 按来源、参与者、session、动作、遮挡、低光、姿态质量和轨迹中断分层。
6. 每个困难负例的独立保护组数、误报数和失败案例。
7. 当前 validation 是否回退、最差来源是否回退和三 seed 稳定性。
8. `test_pose_read=false`、`test_evaluated=false` 的机器证据。

短片回放可用指标：

- 事件 Precision/Recall/F1，但必须同时报告独立事件数和参与者数。
- 逐类困难负例误报数/分母。
- boundary IoU、onset/offset/recovery 误差。
- 检测、跟踪、姿态和模型拒识率。

不可使用：

- 短片拼接的 camera-hour。
- 未标区间推断的 background negative。
- 帧级 accuracy 作为事件主结论。
- 只有单一参与者或单一来源的指标作为泛化证据。

## 11. 执行顺序和停止条件

| 顺序 | 任务 | 完成标准 | 停止条件 |
|---:|---|---|---|
| 1 | 来源专用 importer 和 candidate 生成 | G0 全部通过，两次构建一致 | 授权、P02 坐标或 P03 帧对齐无法审计 |
| 2 | 固定模型基线回放 | 262 条都有可追溯预测或明确拒绝原因 | 姿态/跟踪质量不足以构建可用窗口 |
| 3 | 近跌倒 E0-E3 | 旧 validation 不显著回退，困难负例误报下降，三 seed 一致 | 只在单一 seed/单一来源改善，或相机捷径增强 |
| 4 | 坐站 S0-S2 数据准备 | 边界和负例可确定性构建 | 5 camera-hour 连续背景未补齐时不恢复主 pilot |
| 5 | 步态 auxiliary 消融 | walking gate 误报下降且现行最差来源不回退 | 不提高最差来源或出现明显来源捷径 |
| 6 | 规则回归和交付报告 | 当前规则主路径、fallback 和 test 锁定不变 | 任何候选未通过绝对门禁却要求替换主路径 |

## 13. 2026-08-12 执行审查记录

本计划已执行到 G2 门禁，但不是执行完 E1-E3 训练。审查发现原“执行顺序”第 1 项把 candidate 构建和 G0 人工门禁通过写成同一个完成标准；实际工程上允许先生成完全隔离、`loss_eligible=false` 的 candidate，并在 G0 阻塞时继续做只读 G1 压力回放，但不得进入训练。

当前状态：

| 阶段 | 状态 | 证据 |
|---|---|---|
| G0 | candidate 构建完成，人工门禁 `blocked` | 262 个视频、786 条轨迹、294 个近跌倒候选；两次构建逐字节一致；可进入 loss 为 0 |
| G1 | 四分支冻结回放完成 | 262 段均完成步态规则/TCN、坐站规则/TCN、近跌倒规则/三 seed TCN 和跌倒规则回放 |
| G2 E0 | 完成 | 冻结 checkpoint 原始预测已保存，未调参 |
| G2 E1-E3 | `blocked`，未训练 | 授权、subject profile、双审、P03 帧映射/重复裁决、冻结 split 和 loss eligibility 未通过 |

回放发现近跌倒三 seed 对六类计划负例的短片触发率为 `75.0%/76.8%/75.9%`（有效窗口分母 112），P05 为三个 seed 全部 `27/27` 触发，提示严重自采域偏移或来源捷径。该结果只允许把现有 checkpoint 作为 E0 冻结诊断证据，不能接入主路径或声称已经泛化。完整结果见[SCF_MVP_V1 自采数据基线回放与近跌倒增强门禁报告](../../../../reports/fall_risk/self_collected_scf_mvp_v1/README.md)。
