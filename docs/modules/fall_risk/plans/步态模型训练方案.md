# 步态模型训练方案

更新时间：2026-07-28

状态：训练与评估方案。本文描述目标任务、数据使用、实验协议和模型替换门槛，不代表模型已经训练完成或达到部署要求。当前能力和实测状态仍以跌倒风险模块 README、代码及 `reports/` 下的实验产物为准。

## 1. 目标与边界

本方案面向跌倒风险算法固定路线中的“步态稳定性分析”分支，目标任务为：

```text
task = gait_instability_vs_normal_activity
```

模型消费经过检测、跟踪、姿态质量控制和时序平滑的关键点窗口，输出当前窗口的异常步态概率：

```text
cleaned pose window [T, 14, 5]
  -> gait model
  -> gait_risk_score in [0, 1]
```

其中：

- 负类 `0`：`A01 / normal_walk`。
- 正类 `1`：`B01 / slow_walk`、`B02 / dragging_walk`、`B03 / shuffling_walk`、`B04 / swaying_walk`。
- `gait_risk_score` 表示当前窗口出现可观察异常步态的模型分数，不表示未来跌倒概率，也不是临床诊断或医学量表。
- 步态模型只输出跌倒模块内部的局部分数、置信度和证据，不直接输出最终 `risk_level` 或跨模块综合风险。
- KINECAL 的 `NF` 对 `FHs/FHm` checkpoint 训练目标是回顾性跌倒史 proxy，与本任务不同，不得接入本任务运行路径。

## 2. 当前事实

### 2.1 已实现能力

仓库当前已经实现：

- 从 cleaned pose JSONL 构建固定 `[T,14,5]` 张量。
- 14 点骨架的骨盆中心化、躯干尺度归一化以及 `x/y/dx/dy/quality` 五通道输入。
- 轻量 TCN、类别加权交叉熵、AdamW、左右镜像增强、验证损失早停和 checkpoint 保存。
- 规则、LightGBM 和 EBM 共用同一窗口的数据对照入口。
- checkpoint 的任务、关节顺序、通道顺序和窗口长度校验。
- TCN 不可用或推理失败时回退到规则步态分支。

当前配置契约为：

```text
window_frames = 64
joint_count = 14
channels = [x, y, dx, dy, quality]
expected_task = gait_instability_vs_normal_activity
fallback_backend = rule_baseline
```

## 3. 现有数据盘点

### 3.1 当前可运行选择器

按现有 v2 选择逻辑，当前可选 762 个动作段：

| 类别 | 动作 | 动作段数 |
|---|---|---:|
| 正常 | A01 normal walk | 534 |
| 异常 | B01-B04 gait instability | 228 |
| 合计 | - | 762 |

默认 64 帧窗口、32 帧步长在不考虑姿态质量拒绝的情况下，理论上可生成约 4,928 个窗口；这些窗口高度相关，不能把窗口数当作独立样本量。

### 3.2 数据源分布

| 数据源 | 正常动作段 | 异常动作段 | 主要用途 |
|---|---:|---:|---|
| Pre_VFallp | 25 | 136 | 训练和开发阶段跨源验证 |
| LE2I | 191 | 71 | 训练和开发阶段跨源验证 |
| 抖音/B站整理 | 25 | 21 | 锁定外部压力测试，不进入候选模型训练 |
| CaucaFall | 60 | 0 | 正常行为 hard negative 或误报测试 |
| NTU RGB+D | 170 | 0 | 多视角正常行为误报压力测试 |
| UR Fall | 35 | 0 | 正常行为 hard negative 或误报测试 |
| TOAGA | 28 | 0 | 老人步行正常类压力测试 |

当前最重要的数据限制是：异常动作中存在大量 `subject_id=unknown`，类别、来源、视角和场景之间也存在相关性。模型可能学习数据来源或摄像头捷径，因此最终选择不得依据随机窗口或随机视频切分的单一高分。

### 3.3 v3 标签使用规则

正式训练数据应以 v3 标签及其现行 split/group 契约为事实源：

- `training_tier=primary`：进入主训练和正式评估候选。
- `training_tier=auxiliary`：只进入训练，默认样本权重为 primary 的 `0.25-0.5`，不得进入正式测试分母。
- `training_tier=ignore`：完全排除。
- 二分类父任务使用 `training_tier`；subtype 辅助头还必须检查 `action_type_training_tier`。
- `source_group_id` 和 `sample_group_id` 必须进入数据产物并参与防泄漏校验。
- 抖音/B站当前人员关系未知，整个来源池继续作为单一保守来源组处理，不把不同视频假设成不同人物。

## 4. 总体技术路线

第一轮保留二分类作为部署输出，但不把“纯二分类 TCN”直接视为最终最优模型。按以下层次逐步比较：

```text
规则步态特征 baseline
  -> EBM / LightGBM 结构化特征 baseline
  -> 轻量二分类 TCN
  -> 二分类 + subtype 辅助头的多任务 TCN
  -> 跨数据源稳健训练的多任务 TCN
  -> TCN + EBM/LightGBM 校准集成
  -> ST-GCN++ 强对照（数据和前序结果支持时）
```

模型选择依据是跨数据源最差表现、误报和校准，而不是网络复杂度。

## 5. 数据处理方案

### 5.1 姿态提取

研发阶段先固定与当前实时主线一致的 `YOLOv8-Pose + ByteTrack`，避免同时改变姿态后端和步态模型。当前可运行命令为：

```bash
conda run -n eldercare-ai python scripts/prepare/prepare_gait_pose_quality.py \
  --labels data/annotations/fall_risk/action_labels.jsonl \
  --output-dir data/processed/fall_risk/gait_pose_quality \
  --model yolov8n-pose.pt
```

该命令支持跳过已有输出，可断点续跑。正式运行前必须确认 editable 安装指向当前仓库：

```bash
conda run -n eldercare-ai python -m pip show elderly-monitoring-algorithms
```

每个姿态产物必须记录或可追溯：

- 原视频和标签 hash。
- 姿态模型、跟踪器、置信度和 IoU 配置。
- 坐标系统和 FPS/时间戳。
- 可用帧比例、核心关键点覆盖、插值比例、异常跳点和 ID 切换诊断。

### 5.2 时间规范化

不同数据源的帧率不同，正式数据集不能直接把“每帧位移”当作速度。数据准备需要增加基于 `timestamp_sec` 的时间重采样，并冻结：

- 目标有效 FPS。
- 允许的最大相邻时间 gap。
- 时间窗长度和目标帧数。
- 最小有效帧比例。
- 短缺失插值上限。

当前运行契约固定 64 帧，实时门禁要求 gait 分支有效 FPS 不低于 4 FPS。目标 FPS 和窗口秒数应在训练前通过数据覆盖审计确定，并保证训练与实时推理完全一致；在该契约冻结前，不用离线最佳窗口替换运行配置。

### 5.3 张量构建

现有输入张量为：

```text
shape = [64, 14, 5]
channels = [x, y, dx, dy, quality]
```

处理顺序：

```text
12 个 COCO 兼容关节
  -> 派生 pelvis center 和 shoulder center
  -> pelvis centering
  -> torso-scale normalization
  -> temporal delta
  -> quality mask
```

长期连续缺失、无有效躯干尺度或低于质量门禁的窗口直接拒绝，不使用全零或过度插值窗口伪装正常样本。

### 5.4 动作段与窗口权重

为了避免长视频支配训练：

- 同一动作段默认最多抽取 4 个窗口。
- 同一动作段所有窗口的总权重固定为 1。
- 相邻窗口不能跨 partition。
- batch 需要同时按类别和数据源均衡。
- auxiliary 样本再乘以 tier 权重。

建议样本权重为：

```text
sample_weight
  = tier_weight
  * 1 / windows_in_action_segment
  * class_balance_weight
  * source_balance_weight
```

具体权重只允许在内层验证集确定，不能看锁定外部测试结果后调整。

## 6. 数据划分与评估协议

### 6.1 禁止的切分方式

以下结果不能作为模型替换证据：

- 随机窗口切分。
- 同一原视频的窗口跨 partition。
- 已知同一人物或保守来源组跨 partition。
- 用测试集选择 epoch、阈值、融合权重或校准器。
- 把 auxiliary/ignore 样本放入正式测试分母。

### 6.2 现实条件下的主协议

本项目不以新增大规模真人数据作为当前训练前置条件。现有数据的推荐使用方式为：

```text
开发训练核心：Pre_VFallp + LE2I
开发 hard negative：CaucaFall + UR Fall
开发内层验证：Pre_VFallp 与 LE2I 轮流作为未见数据源
锁定平衡压力测试：抖音/B站来源池
锁定正常压力测试：NTU RGB+D + TOAGA
```

抖音/B站来源池在当前 v3 split 中整体位于 test，应保持锁定，不进入候选模型训练、阈值选择和融合器拟合。由于该来源池人员分组未知，其结果只能作为跨来源压力证据，不能冒充按受试者独立估计的性能。

开发阶段至少运行两轮：

| Fold | 训练 | 验证 |
|---|---|---|
| A | LE2I + 开发 hard negative | Pre_VFallp |
| B | Pre_VFallp + 开发 hard negative | LE2I |

候选配置按两个验证域中的最差 balanced accuracy 排序。模型和阈值冻结后，只运行一次抖音/B站平衡压力测试及 NTU/TOAGA 正常压力测试。

### 6.3 评估单位

必须同时报告：

- 窗口级指标：用于训练诊断。
- 动作段级指标：同一动作段窗口概率聚合后作为主要分类指标。
- 数据源级指标：分别报告，不用总体平均掩盖最差来源。
- 正常视频时长指标：每分钟或每小时误报次数。

动作段概率首版使用窗口概率均值；最大值、Top-K 均值和连续窗口确认只作为预注册对照，不能看测试结果后选择。

## 7. 基线与模型

### 7.1 规则、LightGBM 和 EBM

当前可运行命令：

```bash
conda run -n eldercare-ai python scripts/train/train_gait_tabular_baselines.py \
  --data data/processed/fall_risk/gait_window_v1/dataset.npz \
  --output-dir reports/fall_risk/gait_window_v1/tabular \
  --models rule,lightgbm,ebm \
  --seed 42
```

结构化模型消费速度、步频、步幅 proxy、左右不对称、横向摆动、躯干倾角、路径偏离、转身稳定性及质量特征。它们是小数据条件下的强对照，也是最终集成候选。

### 7.2 轻量二分类 TCN

现有模型包括：

- `1x1 Conv1d` 输入投影。
- dilation 为 `1/2/4/8` 的四个深度可分离时间残差块。
- GroupNorm、GELU 和 dropout。
- 基于质量 mask 的时间池化。
- 二分类线性头。

默认训练配置：

| 参数 | 值 |
|---|---:|
| epochs | 80 |
| batch size | 16 |
| hidden channels | 48 |
| kernel size | 5 |
| dilations | 1,2,4,8 |
| dropout | 0.20 |
| learning rate | 0.001 |
| weight decay | 0.0001 |
| patience | 15 |
| seed | 42 |

当前可运行命令：

```bash
conda run -n eldercare-ai python scripts/train/train_gait_tcn.py \
  --data data/processed/fall_risk/gait_window_v1/dataset.npz \
  --output-dir reports/fall_risk/gait_window_v1/tcn \
  --epochs 80 \
  --batch-size 16 \
  --hidden-channels 48 \
  --kernel-size 5 \
  --dilations 1,2,4,8 \
  --dropout 0.20 \
  --learning-rate 0.001 \
  --weight-decay 0.0001 \
  --patience 15 \
  --seed 42 \
  --device auto
```

该命令只有在准备好的 metadata 中 `task=gait_instability_vs_normal_activity` 时，才生成可被运行时任务校验接受的 checkpoint。

### 7.3 多任务 TCN

多任务 TCN 是纯二分类之后优先级最高的优化，不改变部署输出。目标结构为：

```text
shared TCN representation
  -> binary head: normal vs gait instability
  -> subtype head: A01/B01/B02/B03/B04
```

建议初始损失：

```text
L = L_binary + 0.3 * L_subtype
```

要求：

- binary head 使用所有合法父类标签。
- subtype head 只消费 `action_type_training_tier` 合法的样本。
- subtype 缺失或 auxiliary 时使用 mask/tier weight，不伪造具体动作真值。
- 质量字段继续作为输入 mask 和拒识依据，不直接训练“低质量等于异常”的预测头。

### 7.4 跨数据源稳健训练

在普通均衡采样之后比较 GroupDRO 或最差域损失：

```text
L_domain = max(L_Pre_VFallp, L_LE2I, L_hard_negative)
```

仅当它提高未见数据源的最差指标时保留。若类别和数据源高度相关，直接使用域对抗训练可能同时删除真实标签信号，因此不作为第一优先级。

### 7.5 TCN 与结构化模型集成

候选集成输入：

```text
p_tcn
p_lightgbm_or_ebm
p_rule
quality features
```

融合器采用受正则约束的 Logistic Regression 或预注册加权平均，在内层 out-of-fold 预测上拟合。测试集不得用于确定融合权重。

## 8. 数据增强

现有左右镜像增强继续保留，并逐项消融：

- 时间速度缩放。
- 按实测姿态误差分布加入小幅坐标噪声。
- 随机短时关键点缺失。
- 随机帧丢失后按正式时间规范重采样。
- 轻微旋转和尺度扰动。

增强必须遵守：

- 不改变标签语义。
- 不用过强速度变换把正常步态合成为异常步态。
- 保留或同步更新 quality mask。
- 只作用于训练分区。
- 每项增强通过单独消融证明收益。

## 9. 训练与调参协议

### 9.1 固定随机性

每个候选至少运行 `seed=42/43/44` 三个随机种子，报告均值、标准差和最差结果。单次最好成绩不能作为模型选择依据。

### 9.2 调参顺序

按以下顺序调参，避免无边界搜索：

1. 固定数据和 split，跑规则、LightGBM/EBM 与默认 TCN。
2. 比较窗口秒数/有效 FPS 契约，冻结输入。
3. 比较隐藏通道、dilation 和 dropout。
4. 加入动作段权重和数据源均衡。
5. 加入 subtype 辅助头。
6. 比较 GroupDRO。
7. 拟合集成器和校准器。
8. 最后才比较 ST-GCN++。

任何阶段都不得因测试结果不理想而回头修改测试分区。

### 9.3 早停与阈值

- 训练早停使用内层验证损失或预注册的验证域最差指标。
- 分类阈值在验证集确定，不固定假设 `0.5` 一定最优。
- 概率校准比较 temperature scaling、sigmoid 和 isotonic。
- 模型排序先看最差域 balanced accuracy，再看异常 recall、specificity、Brier score 和延迟。

## 10. 指标与报告

### 10.1 必报指标

分类指标：

- Accuracy。
- Balanced accuracy。
- Precision、Recall、Specificity、F1。
- ROC-AUC；正样本足够时补 PR-AUC。
- 混淆矩阵。

校准指标：

- Brier score。
- Log loss。
- ECE 和 reliability diagram。

部署指标：

- 正常视频每小时误报次数。
- 连续窗口确认后的事件级误报/漏报。
- 可用窗口比例和拒识率。
- CPU/MPS/CUDA 上的 P50/P95 推理延迟和内存。

### 10.2 分层指标

条件允许时分别报告：

- B01/B02/B03/B04 subtype。
- 数据源。
- 正面、侧面、斜视和未知视角。
- 低光、遮挡、低分辨率和关键点缺失。
- 助行器或辅助器具。

没有对应元数据的分层明确写为“不可评估”，不从文件名或背景主观推断。

### 10.3 置信区间

窗口不是独立单位。置信区间应优先按 `source_group_id` 或 `sample_group_id` 做 cluster bootstrap。对于只有单一保守来源组的抖音/B站数据，不能声称获得受试者级置信区间，只报告样本级探索结果和限制。

## 11. 实验矩阵

| 编号 | 模型 | 目的 | 启用条件 |
|---|---|---|---|
| E0 | 规则 baseline | 最低可解释对照 | 必跑 |
| E1 | LightGBM/EBM | 小样本结构化强对照 | 必跑 |
| E2 | 二分类 TCN | 当前主时序模型 | 必跑 |
| E3 | 多任务 TCN | 利用 B01-B04 subtype | subtype tier 合法 |

每个实验必须共享同一姿态输入、split、测试分母和指标实现。只改变实验表中指定因素。

## 12. 暂定验收门槛

以下门槛用于当前数据条件下的研发候选筛选，不是临床或正式产品标准：

```text
开发跨源验证平均 balanced accuracy >= 0.70
开发跨源验证最差 balanced accuracy >= 0.60
每个验证源 recall 和 specificity 均 >= 0.55
相对规则 baseline 平均提升 >= 0.05，或误报显著下降
三个 seed 结论方向一致
锁定正常压力集不存在不可接受的系统性误报
```

若 TCN 相对规则/EBM 的提升小于 3 个百分点且置信区间高度重叠，优先保留更简单模型。若内部指标异常高，例如随机视频切分 AUC 超过 0.95，先检查来源、演员、场景和相邻窗口泄漏，不直接判断模型有效。

## 13. 主链替换门槛

候选模型只有同时满足以下条件，才能将默认 `checkpoint: null` 替换为真实路径：

- checkpoint `task` 精确等于 `gait_instability_vs_normal_activity`。
- 数据、标签、split、配置和 checkpoint hash 完整记录。
- v3 tier/group 和跨分区泄漏校验通过。
- 与规则、LightGBM/EBM 使用同一协议完成比较。
- 锁定压力测试只在模型冻结后执行。
- 阈值和校准器只使用训练/验证数据确定。
- 低质量、模型错误和超时均能回退规则分支。
- 真实运行窗口的 FPS、时间 gap 和质量分布与训练契约兼容。
- 推理延迟和资源占用满足实时服务预算。
- 失败案例、限制和不可声明结论写入实验报告。

即使通过研发门槛，对外仍只能表述为“在现有多来源数据上取得初步跨来源稳健性证据”，不能表述为“已经证明适用于任意老人、家庭摄像头或临床跌倒预测”。

## 17. 风险与决策原则

| 风险 | 处理原则 |
|---|---|
| 类别与数据源相关 | 跨源验证、锁定来源池、数据源均衡 |
| 人物身份未知 | 使用保守来源组，不拆成独立人物 |
| 相邻窗口泄漏 | 动作段/样本组整体分区和权重归一化 |
| 正常类来源多、正类来源少 | 分源报告，不用总体平均掩盖最差域 |
| 姿态质量成为类别线索 | quality mask、分层评估和低质量拒识 |
| TCN 小数据过拟合 | 小模型、早停、多 seed、结构化模型对照 |
| 概率不可解释 | 独立校准、Brier/ECE 和 reliability diagram |
| 单窗口抖动 | 连续窗口确认、节流和规则 fallback |
| 高分来自数据泄漏 | 优先审计，不以复杂模型或高 AUC 自证有效 |

本方案的核心决策原则是：在现有数据无法证明任意家庭泛化时，不制造过强结论；通过保守分组、跨数据源压力测试、强 baseline 和失败分析，最大化已有数据能够提供的可信证据。
