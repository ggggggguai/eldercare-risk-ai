# 步态模型训练方案

更新时间：2026-08-03

状态：训练与评估方案。本文描述目标任务、数据使用、实验协议和模型替换门槛，不代表模型已经训练完成或达到部署要求。当前能力和实测状态仍以跌倒风险模块 README、代码及 `reports/` 下的实验产物为准。

## 1. 目标与边界

本方案面向跌倒风险算法固定路线中的“步态稳定性分析”分支，目标任务为：

```text
task = gait_instability_vs_normal_activity
```

模型消费经过检测、跟踪、姿态质量控制和时序平滑的关键点窗口，输出当前窗口的异常步态概率：

```text
cleaned pose window [T, 14, 5]
  -> gait model
  -> gait_risk_score in [0, 1]
```

其中：

- 负类 `0`：A01-A12 normal activity/hard negative。运行时当前没有可靠的 walking-only 前置门，因此坐下、起立、弯腰、下蹲、躺下和正常调整等动作必须进入负类压力，不能只用 normal walk 形成过于容易的任务。
- 正类 `1`：`B01 / slow_walk`、`B02 / dragging_walk`、`B03 / shuffling_walk`、`B04 / swaying_walk`。
- B01 `slow_walk` 只作为可观察功能风险 proxy；慢速本身不等于步态不稳，也不能解释为临床异常。正式报告必须单列 B01，并补做排除 B01 的敏感性分析。
- `gait_risk_score` 表示当前窗口出现可观察异常步态的模型分数，不表示未来跌倒概率，也不是临床诊断或医学量表。
- 步态模型只输出跌倒模块内部的局部分数、置信度和证据，不直接输出最终 `risk_level` 或跨模块综合风险。
- KINECAL 的 `NF` 对 `FHs/FHm` checkpoint 训练目标是回顾性跌倒史 proxy，与本任务不同，不得接入本任务运行路径。

## 2. 当前事实

### 2.1 已实现能力

仓库当前已经实现：

- 从 cleaned pose JSONL 构建固定 `[T,14,5]` 张量。
- 14 点骨架的骨盆中心化、躯干尺度归一化以及 `x/y/dx/dy/quality` 五通道存储；新训练默认不把连续 `quality` 送入编码器，只用于 mask 和时间池化。
- 轻量 TCN、类别加权交叉熵、AdamW、左右镜像/时间平移/关键点丢失/坐标扰动、验证损失早停和 checkpoint 保存。
- 基于现有 A/B 动作 ID 的 walking gate 与条件异常头；最终分数为 `P(walking) * P(abnormal | walking)`。
- 规则、LightGBM 和 EBM 共用同一窗口的数据对照入口。
- v3 标签、manifest、冻结 assignments 和 split report 的 fail-closed 哈希/字段校验。
- 固定时间重采样、动作段窗口上限、tier/动作段/类别/来源权重和 frozen 分区校验；旧 Fold A/B 重分配已禁止。
- 动作段聚合、验证集阈值选择、Brier/log loss/ECE、分源指标和正常时长误报指标。
- checkpoint 的任务、关节顺序、通道顺序、窗口长度、FPS、gap 和最少观测帧校验。
- 正式 v3 数据默认不读取 test；只有显式 `--evaluate-test` 才生成测试指标和预测。
- TCN 不可用或推理失败时回退到规则步态分支。

当前配置契约为：

```text
target_fps = 4.0
window_sec = 4.0
window_frames = 16
stride_frames = 8
max_gap_sec = 0.5
min_observed_frames = 10
joint_count = 14
channels = [x, y, dx, dy, quality]
expected_task = gait_instability_vs_normal_activity
fallback_backend = rule_baseline
```

## 3. 现有数据盘点

### 3.1 当前 v3 选择器与真实构建

按当前 v3 选择逻辑，可选 5,581 个动作段：

| 类别 | 动作 | 动作段数 |
|---|---|---:|
| 正常 | A01-A12 normal activity/hard negative | 5,169 |
| 异常 | B01-B04 observable functional proxy | 412 |
| 合计 | - | 5,581 |

固定 `4 FPS x 4 秒` 契约后，1,473 个动作段生成 2,097 个可用窗口，其中负类 1,609、正类 488；4,134 个候选窗口因观测帧不足被拒绝，56 个因步态质量不足被拒绝。同一源观测不允许复制到多个目标时间槽。窗口高度相关，不能把 2,097 当作独立样本量。

### 3.2 数据源分布

| 数据源 | 正常动作段 | 异常动作段 | 主要用途 |
|---|---:|---:|---|
| Pre_VFallp | 25 | 118 | 全部位于 frozen test，禁止训练和调参 |
| LE2I | 161 | 33 | 仅按 frozen assignment 使用 |
| 抖音/B站整理 | 17 | 12 | 锁定外部压力测试，不进入候选模型训练 |
| CaucaFall | 82 | 0 | 开发 hard negative |
| NTU RGB+D | 960 | 0 | 锁定正常压力测试 |
| UR Fall | 38 | 0 | 开发 hard negative |
| TOAGA | 27 | 0 | 锁定正常压力测试 |

表中为旧产物中成功生成至少一个窗口的动作段，不是原始标签数。Pre_VFallp 和 LE2I 的正常/异常计数由该产物按二分类标签统计；它不改变 Pre_VFallp 属于 test 的治理事实。

当前最重要的数据限制是：异常动作中存在大量 `subject_id=unknown`，类别、来源、视角和场景之间也存在相关性。模型可能学习数据来源或摄像头捷径，因此最终选择不得依据随机窗口或随机视频切分的单一高分。

### 3.3 v3 标签使用规则

正式训练数据应以 v3 标签及其现行 split/group 契约为事实源：

- `training_tier=primary`：进入主训练和正式评估候选。
- `training_tier=auxiliary`：只进入训练，当前 tier 权重固定为 `0.35`，不得进入 validation/test 分母。
- `training_tier=ignore`：完全排除。
- 二分类父任务使用 `training_tier`；subtype 辅助头还必须检查 `action_type_training_tier`。
- `source_group_id` 和 `sample_group_id` 必须进入数据产物并参与防泄漏校验。
- 抖音/B站当前人员关系未知，整个来源池继续作为单一保守来源组处理，不把不同视频假设成不同人物。

## 4. 总体技术路线

第一轮保留二分类作为部署输出，但不把“纯二分类 TCN”直接视为最终最优模型。按以下层次逐步比较：

```text
规则步态特征 baseline
  -> EBM / LightGBM 结构化特征 baseline
  -> 轻量二分类 TCN
  -> 二分类 + subtype 辅助头的多任务 TCN
  -> 跨数据源稳健训练的多任务 TCN
  -> TCN + EBM/LightGBM 校准集成
  -> ST-GCN++ 强对照（数据和前序结果支持时）
```

模型选择依据是跨数据源最差表现、误报和校准，而不是网络复杂度。

## 5. 数据处理方案

### 5.1 姿态提取

研发阶段固定与当前实时主线一致的 `YOLOv8-Pose + ByteTrack`。当前 2,125 个被选视频已全部命中通用共享姿态缓存，不再重复运行步态专用提取。正式输入为：

```text
data/processed/fall_risk/pose_quality_y8n_v1/cleaned/<video_id>.jsonl
```

缓存的创建与验收命令见跌倒风险模块 README。正式构建前必须确认 editable 安装指向当前仓库：

```bash
conda run -n eldercare-ai python -m pip show elderly-monitoring-algorithms
```

每个姿态产物必须记录或可追溯：

- 原视频和标签 hash。
- 姿态模型、跟踪器、置信度和 IoU 配置。
- 坐标系统和 FPS/时间戳。
- 可用帧比例、核心关键点覆盖、插值比例、异常跳点和 ID 切换诊断。

### 5.2 时间规范化

不同数据源的帧率不同，正式数据集不能直接把“每帧位移”当作速度。当前已按 `timestamp_sec` 冻结：

- 目标有效 FPS：4.0。
- 最大最近观测 gap：0.5 秒。
- 时间窗：4.0 秒、16 帧，步长 2.0 秒/8 帧。
- 最少观测：10/16 帧。
- 同一动作段最多 4 个窗口。

训练 checkpoint 保存完整输入契约；运行时按相同 source-time 网格重采样，并拒绝不足 10 个观测帧的窗口。比较其他 FPS/窗口只能作为新版本实验，不能静默改变当前数据或运行配置。

### 5.3 张量构建

现有输入张量为：

```text
shape = [16, 14, 5]
channels = [x, y, dx, dy, quality]
```

处理顺序：

```text
12 个 COCO 兼容关节
  -> 派生 pelvis center 和 shoulder center
  -> pelvis centering
  -> torso-scale normalization
  -> temporal delta
  -> quality mask（默认不作为分类内容）
```

长期连续缺失、无有效躯干尺度或低于质量门禁的窗口直接拒绝，不使用全零或过度插值窗口伪装正常样本。

### 5.4 动作段与窗口权重

为了避免长视频支配训练：

- 同一动作段默认最多抽取 4 个窗口。
- 同一动作段所有窗口的总权重固定为 1。
- 相邻窗口不能跨 partition。
- 训练权重需要同时控制类别和数据源质量；当前实现先做数据源均衡，再按有效训练质量计算类别权重。
- auxiliary 样本再乘以 tier 权重。

建议样本权重为：

```text
sample_weight
  = tier_weight
  * 1 / windows_in_action_segment
  * class_balance_weight
  * source_balance_weight
```

具体权重只允许在内层验证集确定，不能看锁定外部测试结果后调整。

类别权重不能直接按窗口数计算。实现必须先应用动作段、tier 和 source 权重，再令两类的有效权重总质量相等；否则长动作段或特定来源会在类别平衡后重新占优。

正式数据构建命令：

```bash
conda run -n eldercare-ai python scripts/prepare/prepare_gait_window_dataset.py \
  --output-dir data/processed/fall_risk/gait_window_v1
```

B01 分离实验必须使用显式目标 profile 并写入独立目录，不能覆盖完整标签数据：

```bash
conda run -n eldercare-ai python scripts/prepare/prepare_gait_window_dataset.py \
  --output-dir data/processed/fall_risk/gait_window_v3_observable_instability \
  --target-profile observable_instability_b02_b04
```

默认参数已经指向 v3 标签、manifest、冻结 assignments/split report 和共享姿态缓存。正式构建会同时校验三类输入哈希与 assignment 字段；任何不匹配都必须失败，不能退回随机切分。只有显式传入 v2 标签且不传 formal 输入时，才保留按组随机切分作为旧开发兼容路径。

## 6. 数据划分与评估协议

### 6.1 禁止的切分方式

以下结果不能作为模型替换证据：

- 随机窗口切分。
- 同一原视频的窗口跨 partition。
- 已知同一人物或保守来源组跨 partition。
- 用测试集选择 epoch、阈值、融合权重或校准器。
- 把 auxiliary/ignore 样本放入正式测试分母。

### 6.2 现实条件下的主协议

当前只允许使用 v3 split report 发布的 frozen train/validation。任何派生 scheme 可以排除样本，但不得把 frozen train、validation 或 test 重新分配到另一个有效 partition。Pre_VFallp 246 条 assignment 和抖音/B站来源池全部位于 test，均不得进入训练、早停、阈值选择、校准或预训练。

为利用其他动作标签，可在同一 frozen 非 test 范围内先训练共享时序编码器，再只迁移编码器到步态二分类头。A/B/C/D 动作不得直接改写为同一个步态二分类标签；坐站、功能受损、平衡丢失和跌倒动作只提供辅助表示监督。模型和阈值冻结且满足门禁后，才允许由测试集保管流程一次性解锁 test；当前不满足条件。

### 6.3 评估单位

必须同时报告：

- 窗口级指标：用于训练诊断。
- 动作段级指标：同一动作段窗口概率聚合后作为主要分类指标。
- 数据源级指标：分别报告，不用总体平均掩盖最差来源。
- 正常视频时长指标：每分钟或每小时误报次数。

动作段概率首版使用窗口概率均值；最大值、Top-K 均值和连续窗口确认只作为预注册对照，不能看测试结果后选择。

## 7. 基线与模型

### 7.1 规则、LightGBM 和 EBM

当前可运行命令：

```bash
conda run -n eldercare-ai python scripts/train/train_gait_tabular_baselines.py \
  --data data/processed/fall_risk/gait_window_v1/dataset.npz \
  --output-dir reports/fall_risk/gait_window_v1/tabular/frozen \
  --partition-scheme frozen \
  --models rule,lightgbm,ebm \
  --seed 42
```

旧产物若在 `partition_schemes` 中声明 Fold A/B，训练器也会逐样本与 frozen assignments 对照并拒绝重分配。

结构化模型消费速度、步频、步幅 proxy、左右不对称、横向摆动、躯干倾角、路径偏离、转身稳定性及质量特征。它们是小数据条件下的强对照，也是最终集成候选。

### 7.2 轻量层级 TCN

现有模型包括：

- `1x1 Conv1d` 输入投影。
- dilation 为 `1/2/4/8` 的四个深度可分离时间残差块。
- GroupNorm、GELU 和 dropout。
- 基于质量 mask 的时间池化。
- walking/non-walking 线性头。
- 只在 walking 窗口监督的条件异常二分类头。
- 推理时将两个概率相乘；旧 checkpoint 缺少门控字段时保持旧二分类行为。

默认训练配置：

| 参数 | 值 |
|---|---:|
| epochs | 80 |
| batch size | 16 |
| hidden channels | 48 |
| kernel size | 5 |
| dilations | 1,2,4,8 |
| dropout | 0.20 |
| learning rate | 0.001 |
| weight decay | 0.0001 |
| patience | 15 |
| seed | 42 |
| walking gate loss weight | 0.25 |
| quality usage | mask/pooling only |
| temporal shift | 1 frame |
| keypoint dropout | 0.05 |
| coordinate jitter std | 0.005 |

当前可运行命令：

```bash
conda run -n eldercare-ai python scripts/train/train_gait_tcn.py \
  --data data/processed/fall_risk/gait_window_v3_observable_instability/dataset.npz \
  --output-dir reports/fall_risk/gait_window_v4_hierarchical_masked/development-20260803/seed-42 \
  --partition-scheme frozen \
  --epochs 80 \
  --batch-size 16 \
  --hidden-channels 48 \
  --kernel-size 5 \
  --dilations 1,2,4,8 \
  --dropout 0.20 \
  --learning-rate 0.001 \
  --weight-decay 0.0001 \
  --patience 15 \
  --seed 42 \
  --pretrained-checkpoint reports/fall_risk/action_pretraining_v2_semantic5/development-20260803/encoder.pt \
  --freeze-encoder-epochs 8 \
  --device auto
```

该命令只有在准备好的 metadata 中 `task=gait_instability_vs_normal_activity` 时，才生成可被运行时任务校验接受的 checkpoint。正式 v3 数据默认写出 validation 指标而不读取 test。

### 7.3 全动作共享编码器预训练

现有实现采用分阶段多任务监督，不改变部署输出：

```text
所有合法非 test A/B/C/D 动作
  -> 五类语义辅助头训练 shared TCN encoder
  -> 只迁移 input_projection + temporal_blocks
  -> 新建 gait binary head 并微调
```

五类为正常移动、正常转换/活动、功能受损、平衡丢失和跌倒/跌倒后。具体动作 tier 非法、U01、ignore 和 test 均不进入预训练。

```bash
conda run -n eldercare-ai python scripts/prepare/prepare_gait_action_pretraining_dataset.py \
  --output-dir data/processed/fall_risk/action_pretraining_v2_semantic5

conda run -n eldercare-ai python scripts/train/pretrain_gait_action_tcn.py \
  --data data/processed/fall_risk/action_pretraining_v2_semantic5/dataset.npz \
  --output-dir reports/fall_risk/action_pretraining_v2_semantic5/development-20260803
```

微调时通过 `--pretrained-checkpoint .../encoder.pt` 显式启用迁移；可用 `--freeze-encoder-epochs` 做预注册的短期线性头 warm-up。当前实测改善校准但未改善 F1/误报，因此 checkpoint 只保留为开发产物。

### 7.4 跨数据源稳健训练

在普通均衡采样之后比较 GroupDRO 或最差域损失：

```text
L_domain = max(L_non_test_source_1, L_non_test_source_2, ...)
```

只允许使用 frozen train 内的数据源计算训练域损失；Pre_VFallp 当前属于 test，不能成为训练域。仅当方法提高 frozen validation 的最差来源指标时保留。若类别和数据源高度相关，直接使用域对抗训练可能同时删除真实标签信号，因此不作为第一优先级。

### 7.5 TCN 与结构化模型集成

候选集成输入：

```text
p_tcn
p_lightgbm_or_ebm
p_rule
quality features
```

融合器采用受正则约束的 Logistic Regression 或预注册加权平均，在内层 out-of-fold 预测上拟合。测试集不得用于确定融合权重。

## 8. 数据增强

现有实现默认启用以下 train-only 增强：

- 左右镜像。
- 最多 1 帧的非循环时间平移。
- 5% 随机关键点丢失。
- 标准差 0.005 的坐标扰动；扰动后按有效点对重新计算速度通道。

以下仍是待预注册对照，不是当前默认能力：

- 时间速度缩放。
- 按实测姿态误差分布加入小幅坐标噪声。
- 随机短时关键点缺失。
- 随机帧丢失后按正式时间规范重采样。
- 轻微旋转和尺度扰动。

增强必须遵守：

- 不改变标签语义。
- 不用过强速度变换把正常步态合成为异常步态。
- 保留或同步更新 quality mask。
- 只作用于训练分区。
- 每项增强通过单独消融证明收益。

## 9. 训练与调参协议

### 9.1 固定随机性

每个候选至少运行 `seed=42/43/44` 三个随机种子，报告均值、标准差和最差结果。单次最好成绩不能作为模型选择依据。

### 9.2 调参顺序

按以下顺序调参，避免无边界搜索：

1. 固定数据和 split，跑规则、LightGBM/EBM 与默认 TCN。
2. 比较窗口秒数/有效 FPS 契约，冻结输入。
3. 比较隐藏通道、dilation 和 dropout。
4. 加入动作段权重和数据源均衡。
5. 加入 subtype 辅助头。
6. 比较 GroupDRO。
7. 拟合集成器和校准器。
8. 最后才比较 ST-GCN++。

任何阶段都不得因测试结果不理想而回头修改测试分区。

### 9.3 早停与阈值

- 训练早停使用内层验证损失或预注册的验证域最差指标。
- 分类阈值在验证集确定，不固定假设 `0.5` 一定最优。
- 概率校准比较 temperature scaling、sigmoid 和 isotonic。
- 模型排序先看最差域 balanced accuracy，再看异常 recall、specificity、Brier score 和延迟。

## 10. 指标与报告

### 10.1 必报指标

分类指标：

- Accuracy。
- Balanced accuracy。
- Precision、Recall、Specificity、F1。
- ROC-AUC；正样本足够时补 PR-AUC。
- 混淆矩阵。

校准指标：

- Brier score。
- Log loss。
- ECE 和 reliability diagram。

部署指标：

- 正常视频每小时误报次数。
- 连续窗口确认后的事件级误报/漏报。
- 可用窗口比例和拒识率。
- CPU/MPS/CUDA 上的 P50/P95 推理延迟和内存。

### 10.2 分层指标

条件允许时分别报告：

- B01/B02/B03/B04 subtype。
- 数据源。
- 正面、侧面、斜视和未知视角。
- 低光、遮挡、低分辨率和关键点缺失。
- 助行器或辅助器具。

没有对应元数据的分层明确写为“不可评估”，不从文件名或背景主观推断。

### 10.3 置信区间

窗口不是独立单位。置信区间应优先按 `source_group_id` 或 `sample_group_id` 做 cluster bootstrap。对于只有单一保守来源组的抖音/B站数据，不能声称获得受试者级置信区间，只报告样本级探索结果和限制。

| 编号 | 模型 | 目的 | 启用条件 |
|---|---|---|---|

## 12. 暂定验收门槛

以下门槛用于当前数据条件下的研发候选筛选，不是临床或正式产品标准：

```text
开发跨源验证平均 balanced accuracy >= 0.70
开发跨源验证最差 balanced accuracy >= 0.60
每个验证源 recall 和 specificity 均 >= 0.55
相对规则 baseline 平均提升 >= 0.05，或误报显著下降
三个 seed 结论方向一致
锁定正常压力集 raw action-segment false positives <= 12/hour
两窗口连续确认后的 false alarms <= 2/hour
TCN-only CPU P95 <= 25 ms/window，MPS P95 <= 10 ms/window
模型常驻内存增量 <= 200 MiB，且 8 FPS 服务预算内无积压
```

延迟在项目指定固定硬件、batch size 1、预热后至少 1,000 次推理上测量。误报阈值是当前原型研发门槛，不是临床或正式产品 SLA；若压力集正常时长不足 2 小时，只报告计数和置信区间，不用小时率作放行依据。

若 TCN 相对规则/EBM 的提升小于 3 个百分点且置信区间高度重叠，优先保留更简单模型。若内部指标异常高，例如随机视频切分 AUC 超过 0.95，先检查来源、演员、场景和相邻窗口泄漏，不直接判断模型有效。

## 13. 主链替换门槛

候选模型只有同时满足以下条件，才能将默认 `checkpoint: null` 替换为真实路径：

- checkpoint `task` 精确等于 `gait_instability_vs_normal_activity`。
- 数据、标签、split、配置和 checkpoint hash 完整记录。
- v3 tier/group 和跨分区泄漏校验通过。
- 与规则、LightGBM/EBM 使用同一协议完成比较。
- 锁定压力测试只在模型冻结后执行。
- 阈值和校准器只使用训练/验证数据确定。
- 低质量、模型错误和超时均能回退规则分支。
- 真实运行窗口的 FPS、时间 gap 和质量分布与训练契约兼容。
- 推理延迟和资源占用满足实时服务预算。
- 失败案例、限制和不可声明结论写入实验报告。

即使通过研发门槛，对外仍只能表述为“在现有多来源数据上取得初步跨来源稳健性证据”，不能表述为“已经证明适用于任意老人、家庭摄像头或临床跌倒预测”。

## 17. 风险与决策原则

| 风险 | 处理原则 |
|---|---|
| 类别与数据源相关 | 跨源验证、锁定来源池、数据源均衡 |
| 人物身份未知 | 使用保守来源组，不拆成独立人物 |
| 相邻窗口泄漏 | 动作段/样本组整体分区和权重归一化 |
| 正常类来源多、正类来源少 | 分源报告，不用总体平均掩盖最差域 |
| 姿态质量成为类别线索 | quality mask、分层评估和低质量拒识 |
| TCN 小数据过拟合 | 小模型、早停、多 seed、结构化模型对照 |
| 概率不可解释 | 独立校准、Brier/ECE 和 reliability diagram |
| 单窗口抖动 | 连续窗口确认、节流和规则 fallback |
| 高分来自数据泄漏 | 优先审计，不以复杂模型或高 AUC 自证有效 |

本方案的核心决策原则是：在现有数据无法证明任意家庭泛化时，不制造过强结论；通过保守分组、跨数据源压力测试、强 baseline 和失败分析，最大化已有数据能够提供的可信证据。
