# 近跌倒模型训练方案

更新时间：2026-08-02

> 文档性质：拟议的训练、评估与替换方案，不是当前实现状态或实验结果。当前能力以[模块 README](../README.md)、[算法工程架构](../../../architecture/算法工程骨架.md)和[任务清单](../../../tasks/README.md)为准。

## 1. 目标、范围与非目标

目标是在“跟踪 -> 姿态 -> 质量控制”之后训练一个可校准的近跌倒事件模型，识别短时失衡后恢复且未形成跌倒的事件，输出局部 `near_fall_event_score`、证据窗口和置信信息。模型只服务 `fall_risk` 模块内部，不直接给出临床结论，不新增综合模块，也不改变 [`AlgorithmEvent`](../../../interfaces/算法事件输出接口.md) 契约。

本方案不训练最终风险融合、不绕过上游质量控制、不把异常分数直接解释为近跌倒概率，也不以计划中的模型替代当前规则主路径。正式替换前必须同时通过数据、效果、延迟、稳定性和复现门禁。

## 2. 当前事实与就绪度

|---|---|---|

| 姿态质量 | 已输出平滑坐标、有效性、插值/跳变信息和 `usable_for_near_fall` | `src/elderly_monitoring/modules/fall_risk/pose_quality.py` |

| v2 到 v3 | v2 中 14 条 `near_fall` 未自动升级为训练正例；迁移明确禁止把 C03-C05 或未标注背景自动当正/负样本 | `reports/fall_risk/training-labels-v3-migration.json`、`src/elderly_monitoring/modules/fall_risk/training_labels_v3.py` |

## 3. 任务与标签定义

现行语义以[标签字典](../data/跌倒风险标签字典.md)、[标注规范](../data/数据集标注规范.md)和 v3 校验代码为准。

| 角色 | 可进入监督的条件 |
|---|---|
| 正例 | `task_type=near_fall_event`、`label_role=positive`、`event_type=near_fall`、`event_outcome=recovered_without_fall`；必须记录 `onset_frame`、`recovery_frame`，不得有 impact，且完成双人复核或仲裁 |
| 普通负例 | 明确观察到完整窗口且无近跌倒，显式标记 `hard_negative_type=background`；不得从未标注背景、LE2I `0/0` 或动作目录名自动生成 |
| 困难负例 | 必须逐窗确认 `normal_turn`、`normal_step_adjustment`、`routine_support_contact`、`fast_but_controlled_sit`、`controlled_squat`、`controlled_bend`、`exercise_or_stretch`、`progressed_to_fall` |
| 忽略 | `U01/uncertain`、严重遮挡、离屏、多人对象不确定、边界或恢复证据不足；从 loss 和正式分母排除，但保留失败分析 |

`onset` 是失衡、急停、快速下沉或突然扶物开始；`recovery` 是重新稳定的首个可靠边界。若失去支撑并进入倒地过程，则标记为 `progressed_to_fall` 负例或对应 fall 任务事件，不能继续作为 near-fall 正例。正常坐下、弯腰、下蹲、转身和日常扶物只有在“可控且无失衡恢复过程”时作为负例；跟踪丢失、相机运动和遮挡不能伪装成正常负例。

## 4. 数据与训练门禁

| 门禁 | 必须满足的解除条件 |
|---|---|
| 来源 | manifest、原始标注路径和 SHA-256 完整；真人采集具备授权、脱敏和退出删除规则 |
| 正例 | 安全演绎或真实事件经逐窗双审/仲裁，恢复边界和 `physical_event_id` 完整；覆盖不同人、机位、恢复类型和质量层级 |
| 负例 | train/validation/test 均有 primary 正例和负例；八类 hard negative 在目标任务中均非空 |
| 质量 | primary 不含 `target_status=uncertain`、严重质量标记或 ineligible 资产；保留 confidence、mask 和插值来源 |
| 校验 | v2 事实源可追溯，v3 `valid=true`、`training_ready.near_fall_event=true`，split hash 与全部输入一致 |
| 冻结 | 协议负责人预注册样本充分性、主指标、阈值选择和盲测职责后，才将 split/评估协议冻结 |

代码门禁只要求各分区正负例非空和困难负样本覆盖完整，这是必要条件，不是样本充分性的证明。本方案不设置无证据的固定样本数；独立受试者、来源组、机位和事件多样性必须在冻结评审中单独批准。

## 5. 无泄漏划分

训练使用动作与事件共用的 `data/splits/fall_risk/training_labels_v3/`，不得用旧 v2 `near_fall_event_v1` 直接训练 v3 模型。分区以 `subject_id` 为优先；未知人员按 `source_group_id` 保守成组，并联合 `content_sha256`、`sample_group_id`、`physical_event_id` 阻止同一原视频、相邻裁剪、多视角事件及派生姿态跨区。任何标签或 manifest 变化后必须先重建 split，再校验绑定 hash。

开发阶段可沿用配置中的 70/15/15 比例做链路调试，但它不是正式比例。测试集冻结后不参与超参数、阈值、校准器或失败驱动的数据增补；跨来源评估至少分别报告训练已见来源、未见来源、老人域/非老人域和不同机位结果。

## 6. 拟议输入契约

首轮主输入拟议为因果姿态窗口 `[T,V,C]`：

- `V=10`，固定顺序为左右肩、腕、髋、膝、踝；不根据缺失点动态改变关节数。
- `C=8`，候选通道为身体尺度归一化的 `x,y`、一/二阶时间差分 `dx,dy,ddx,ddy`、质量分和 `valid_mask`；时间戳及插值来源作为并行元数据。
- `T` 不预先伪冻结。验证集比较覆盖约 1.5-3 秒事件上下文的候选窗口，并按有效 FPS 重采样；长缺失保留 mask，不用插值骨架冒充观测。
- 坐标以髋中心平移、躯干尺度归一化，保留原视角标识；只用训练集估计归一化统计量。

在线指标只能使用当时及过去帧。若离线对照使用双向平滑或 recovery 后上下文，必须单列为非因果上限，不能冒充实时延迟。

## 7. 模型路线

| 路线 | 定位 | 输出与约束 |
|---|---|---|
| 现行规则 | 必保留的 baseline、候选窗口生成器和安全 fallback | 原有解释因子、事件窗口和质量拒识 |
| 轻量因果 TCN | 拟议主候选 | 窗口级 near-fall logit，并增加 `recovered_without_fall` / `progressed_to_fall` 辅助头；参数量、感受野和延迟由验证实验冻结 |
| ST-GCN++ | 受控强对照 | 使用相同 joint/motion/mask 和完全相同 split；只有在独立事件与骨架拓扑覆盖充分时启用 |
| MS-TCN++ | 条件性对照 | 仅在 onset/peak/recovery 能形成可靠逐帧相位监督时比较，不从粗事件窗口伪造精确相位标签 |

推荐级联为“质量门控 -> 规则高召回候选 -> TCN 分类与恢复约束 -> 校准 -> 规则安全覆盖”。ST-GCN++ 若没有稳定增益或部署成本超预算即停止，不为模型复杂度本身扩展主链。

## 8. 训练设计

1. 先复现规则 baseline，再训练仅坐标 TCN，随后依次加入 motion、quality/mask 和辅助 outcome 头做消融。
2. 主损失拟议采用类别加权 BCE 或 focal loss；辅助 outcome/边界损失只在字段可靠时启用。权重只由 train 估计，validation 选择，test 禁止参与。
3. sampler 以事件/泄漏组为单位平衡，禁止把同一事件的重叠窗口当成独立样本放大。困难负样本先均匀覆盖，再按冻结模型的误报类型做下一轮训练集挖掘。
4. 允许小幅坐标噪声、尺度/平移、连续帧丢失、有效 FPS 降采样和左右镜像；禁止时间反转、跨事件拼接、改变恢复结局或抹平峰值的增强。
5. 固定随机种子、数据/split hash、配置和 checkpoint；按预注册主指标早停。超参数搜索只在 train/validation 内进行，并保存每次运行的完整配置和失败状态。

## 9. 评估协议

现有评估器已支持一对一事件匹配、Precision、Recall、F1、event PR-AUC、边界 IoU、onset/检测延迟、连续视频 `fp_per_camera_hour`、恢复召回、错误恢复率和按组 bootstrap；以 `src/elderly_monitoring/modules/fall_risk/evaluation.py` 为准。`configs/evaluation/near_fall_event_v1.provisional.yaml` 中的 `0.5` 阈值、容差和搜索窗都是开发默认值，必须由协议负责人在看 test 前冻结。

正式报告需在同一冻结 split 上比较规则、TCN 和 ST-GCN++，并给出阈值曲线、95% CI、按来源/机位/质量分层及逐例失败包。长视频无合法负时长时不得报告传统 FPR；优先报告每摄像机小时误报。Brier、ECE/reliability diagram、恢复边界绝对误差及遮挡、低帧率、轨迹中断、相机运动鲁棒性属于拟议扩展，未实现前必须标记缺口。核心消融包括去 motion、去 quality/mask、去 outcome 头、去规则候选和仅规则。

## 10. 主路径替换门禁

| 门禁 | 通过条件 |
|---|---|
| 数据 | 第 4 节全部满足，真实 split 和评估协议冻结 |
| 效果 | 冻结 test 上主指标优于规则，并同时满足预注册的 near-fall recall、误报、恢复正确性和校准约束；阈值不得事后挑选 |
| 延迟 | 目标硬件端到端 P50/P95、吞吐、内存和启动时间在预注册预算内，且使用因果输入 |
| 稳定性 | 低质量、低 FPS、gap、ID switch 和模型异常均可拒识或降级，不产生伪 `0.0` 正常分 |
| 复现 | 独立环境按冻结 hash 重跑得到一致结论，checkpoint 与任务/输入契约匹配 |

数值门槛当前没有正式依据，均为待预注册项。任一门禁未通过，规则继续作为主路径，模型只可离线或影子运行。

## 11. 推理集成与 fallback

模型校准概率拟议映射为现有 `near_fall_event_score`，同时保留 `model_version`、输入质量、证据窗、阈值版本和规则解释因子。该分数只是局部事件证据，最终仍由跌倒模块内部融合生成 `module=fall_risk` 事件。

当窗口不足、`usable_for_near_fall=false`、关键点覆盖不足、轨迹切换、checkpoint/契约不匹配、输出非有限值或推理异常时，模型分支返回 `unavailable` 或 `inference_error`；融合 mask 关闭该分支，并按现行策略使用规则 fallback。模型阴性不得压制规则识别到的强跌倒安全覆盖。

## 12. 可复现实验产物

每次实验保存：代码提交标识、环境、manifest/标签/split/config SHA-256、`split_id`、随机种子、输入通道顺序、训练日志、最佳和最终 checkpoint、阈值曲线、校准器、指标 JSON、资源指标及失败案例，统一写入拟议目录 `reports/fall_risk/near_fall_event/<run_id>/`。

现有可复现入口只有 v3 迁移、split 构建、标签校验和 `scripts/evaluate/evaluate_fall_events.py`；均须通过 `conda run -n eldercare-ai python ...` 执行。近跌倒数据准备、训练和预测 CLI 尚不存在，后续接口必须在实现任务中另行设计，不能把拟议命令写成当前能力。

## 13. 分阶段实施

| 阶段 | 交付物 | 退出条件 |
|---|---|---|
| A 数据就绪 | 双审正例、显式负例、八类 hard negative、更新后的 v3 报告 | `training_ready.near_fall_event=true` 且人工充分性评审通过 |
| B 最小训练链 | tensor 缓存、TCN、checkpoint、单元与小数据过拟合测试 | 固定输入可确定性复现，mask/分组无泄漏 |
| C 对照评估 | 规则与 TCN 的同 split 指标、消融和失败包 | validation 上完成阈值与校准选择 |
| D 候选扩展 | ST-GCN++，有可靠相位标签时再加 MS-TCN++ | 只保留有稳定收益且成本可接受的候选 |
| E 影子验证 | 实时只记录不改变告警的模型输出、延迟和分层误报 | 长视频与目标硬件预算通过 |
| F 替换评审 | 冻结 test 一次性结果、复现包、回滚方案 | 第 10 节全部通过后才切换主路径 |

## 14. 风险、阻塞与停止条件

- 当前首要阻塞是 near-fall 训练正负例为 0，而不是模型结构选择。
- 表演性近跌倒可能产生域偏差；必须保留真实老人域、机位和恢复方式分层，不能以窗口数量掩盖独立事件不足。
- 支撑接触仅凭腕部姿态仍是 proxy；没有家具/墙面证据时不得升级为确定接触。
- 若补标仍无法覆盖恢复边界、困难负样本或 test 独立来源，停止监督模型替换，仅继续规则校准和数据建设。
- 若增强删除事件峰值、模型依赖未来帧、误报分母不合法或 test 被用于调参，实验结论作废并重新冻结协议。

## 15. 完成定义

- [ ] 来源完整、双审且无泄漏的数据门禁通过，正式 split 和协议冻结。
- [ ] 规则、TCN 和受控对照使用相同输入版本、split 和事件评估口径。
- [ ] 指标、校准、延迟、鲁棒性、失败案例和复现产物齐全，无合成结果冒充正式效果。
- [ ] 低质量与异常路径均有显式拒识、fallback 和回归验证。
- [ ] 只有全部替换门禁通过后才更新模块当前状态；否则继续标记为拟议模型。
