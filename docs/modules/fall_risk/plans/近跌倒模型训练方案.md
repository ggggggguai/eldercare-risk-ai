## 1. 执行结论

- **条件允许开发训练**：`fall_event` P0 不自动授权本分支；近跌倒必须先通过自己的标签/hash、实际窗口覆盖和 test 锁定审计，才可运行明确标记为 `development_provisional` 的 train/validation 复现。当前标签门禁为 `valid=true`、`training_ready.near_fall_event=true`，但它本身不等于数据集或正式训练就绪。
- **开发训练已完成**：当前 `splitv3_e71...` 的 train/validation 数据已确定性重建，seed `42/43/44` 的 `development_provisional` checkpoint、指标和 validation 原始预测均已生成；结果见[开发训练报告](../../../../reports/fall_risk/near_fall_event_v1/README.md)。
- **不能开始**：正式 validation 发布、test 解锁、告警驱动 shadow、规则主路径替换。阻塞项是 split/协议未 frozen、v2 formal 未通过、连续背景和老人域缺失、合法误报分母与一次性 test 流程未建立。
- **推荐主候选**：现行单头 recovery-aligned causal TCN。规则 `near-fall-rule-v0.1` 保留为候选生成器、安全覆盖、解释分支和低质量/异常 fallback。ST-GCN++ 只作条件性对照。
- 当前三 seed 事件 F1 `0.9933-0.9967` 只属于当前 split 的候选窗口 validation；由于 validation 负类只有快速可控坐下一类，它不是连续视频、老人域或正式模型效果。

## 3. 任务定义

### 3.1 输入契约

- 输入固定为 8 FPS、3 秒、`T=24`、`V=10`、`C=8`。关节顺序为双肩、双腕、双髋、双膝、双踝；通道为 `x,y,dx,dy,ddx,ddy,quality,valid_mask`，见[输入契约](../../../../src/elderly_monitoring/modules/fall_risk/near_fall_training.py#L14)与[训练配置](../../../../configs/training/near_fall_event_v1.yaml#L5)。
- 使用 `x_smooth/y_smooth`、`valid=true` 且非 jump outlier 的点；以髋中心平移、训练窗躯干中位尺度归一化，统计量只由 train 拟合，见[张量构建](../../../../src/elderly_monitoring/modules/fall_risk/near_fall_training.py#L124)。
- 质量要求：至少 12 个观测帧、usable ratio `>=0.60`、joint coverage `>=0.70`、mean quality `>=0.30`、采样匹配 gap `<=0.20s`。
- 正例窗口严格结束于 `recovery_frame`；负例从明确标注窗口内因果采样，最多每事件 4 窗。test 标签只计数，不读取姿态，见[窗口锚点](../../../../src/elderly_monitoring/modules/fall_risk/near_fall_training.py#L932)与[test 锁定](../../../../src/elderly_monitoring/modules/fall_risk/near_fall_training.py#L416)。

### 3.2 输出契约

- 训练输出是“显式负例/恢复确认近跌倒”二分类概率。
- shadow 应记录 `raw_probability`、校准后的 `near_fall_event_score`、`status=valid|unavailable|inference_error`、拒识原因、checkpoint/calibrator/hash 和 `confirmation_timing=recovery_frame`。
- 模型不直接预测规则子类型；`event_type=near_fall` 由事件状态机赋予，规则子类型单独保留为候选证据。

### 3.3 训练与运行语义

- 正例是 `event_type=near_fall`、`event_outcome=recovered_without_fall`、有合法 `onset_frame/recovery_frame`、无 impact 且完成双审或仲裁的 primary 标签。
- 负例必须是显式 primary 负例，包括八类 hard negative 和经人工确认的 `background`；不得把未标注背景自动当成 negative。
- `progressed_to_fall` 在当前二分类任务中是负例。现行 checkpoint 没有 outcome auxiliary head，[配置说明](../../../../configs/training/near_fall_event_v1.yaml#L43)明确记录了这一点。

### 3.4 非目标

该模型不承担连续事件定位、onset-time 提前预警、跌倒检测、近跌倒/跌倒 outcome 多头分类、最终风险融合或临床结论。连续事件边界由候选生成和状态机负责；当前模型只在观察到恢复后确认候选。

## 5. 实验矩阵

| 路线 | 定位 | Seed | 主要比较 | 停止条件 |
|---|---|---|---|---|
| `near-fall-rule-v0.1` | 固定 baseline、候选生成、安全覆盖、fallback | 确定性 | 事件 Recall、FP/hour、恢复约束、延迟 | 永不删除；只允许版本化校准 |
| 结构化 Logistic | 必跑低容量监督 baseline；使用规则几何/质量特征 | `42/43/44` | PR-AUC、F1、Brier/ECE、来源稳定性 | 若明显依赖来源或不优于规则则不进 shadow |
| LightGBM | 非线性强对照，不进入默认运行链 | `42/43/44` | 同 Logistic，加复杂度/过拟合 | 三 seed 无稳定增益或校准/延迟更差即停止 |
| Isolation Forest | 可选单类诊断；只能用显式审查的正常/负例训练 | `42/43/44` | anomaly ranking、固定召回下误报 | 无合法正常训练集、无法校准或误报高即停止；异常分数不得直接称概率 |
| causal TCN | **主候选**，恢复后确认 | `42/43/44` | 事件 PR-AUC、固定召回下 FP/hour、校准、恢复正确性 | 三 seed/分层无稳定优于 Logistic 和规则的增益则不进入 P5 |
| ST-GCN++ | P3 后的可选骨架拓扑对照 | `42/43/44` | 同 TCN，加 P95 延迟、内存 | 没有跨 seed 稳定增益或超资源预算即停止，不加入运行主链 |

Random Forest 不加入矩阵：其角色与 LightGBM 重叠且缺少明确工程收益。主链只保留规则加一个胜出的 TCN，不并行堆叠多种模型。

## 6. 评估协议

- 主结论必须来自一对一匹配的**事件级** Precision、Recall、F1、event PR-AUC；窗口指标只用于训练诊断。
- 误报报告 `FP/camera-hour`，分母只能来自 `continuous_monitoring_eligible=true` 且有有效 duration 的视频，见[现有实现](../../../../src/elderly_monitoring/modules/fall_risk/evaluation.py#L1239)。
- 每人每天误报需要新增合法 `person_id + monitoring_period + exposure_days`。当前 evaluator 只有 `fp_per_household_day`，在 person-day 字段形成前该指标必须为 `null`，不得用 clip 数代替。
- 延迟拆成：`recovery-onset` 的不可避免观察时长、`confirmation-recovery` 的模型/系统延迟、`alert-onset` 的总延迟。当前模型不能报告正的“提前预警时间”。
- 连续状态机报告事件边界 IoU、重复事件率、恢复召回、错误恢复率，以及 `progressed_to_fall` 被误确认为 near-fall 的比例。TCN 单独的候选窗口不能声称具备边界 IoU。
- 校准报告 raw/calibrated Brier、ECE、reliability diagram、阈值曲线；阈值按预注册目标 Recall 后最小化误报上界。
- 95% CI 按 subject/source protection group bootstrap；正式 frozen evaluator 至少要求 `10,000` 次 bootstrap，见[评估实现](../../../../src/elderly_monitoring/modules/fall_risk/evaluation.py#L327)。
- 分层至少包括：来源、老人/非老人域、场景/机位、遮挡与低光、有效 FPS/gap、跟踪中断、八类 hard negative。小样本分层必须同时给出计数和探索性标记。
- 禁止以帧级 accuracy、窗口 accuracy 或旧 NTU validation F1 作为正式结论。

## 8. Shadow 接入方案

```text
cleaned pose + sampling gate
  -> near-fall-rule-v0.1 高召回候选
  -> 3 秒因果模型窗口
  -> TCN 恢复后确认
  -> recovered_without_fall / 未进入 fall-state 约束
  -> 校准概率与强规则安全覆盖
  -> 跌倒模块内部风险融合
```

P5 期间融合仍消费规则结果，模型只旁路记录。通过 P6 后，模型可控制普通候选确认，但不得压制 `fall_event/long_static` 强安全覆盖；`near_fall-rule-v0.1 >= 0.70` 的强规则覆盖和回滚路径继续保留。

### 8.1 降级规则

- TCN 输入少于 24 帧、8 FPS 契约不满足、gap 超限、质量不足、ID switch、checkpoint/hash 不匹配、非有限输出、超时或异常：模型返回 `unavailable/inference_error`，使用规则结果。
- 规则也不可用：`near_fall_event_score=null`、fusion mask 关闭，不写成 `0.0` 正常。
- TCN 合法阴性只否决普通 near-fall 候选，不否决跌倒/长静止安全分支。

### 8.2 并行记录字段

至少记录事件/人员/轨迹/epoch ID，规则状态、分数、类型、版本和证据；模型 raw/calibrated 分数、状态、原因、checkpoint/calibrator/hash；窗口时间、恢复时间、质量/采样摘要；fall-state 约束；rule/model disagreement；当前实际融合来源；模型和端到端 P50/P95 延迟、内存和异常计数。

已有总延迟硬预算为 `1000 ms`，见[模块配置](../../../../configs/modules/fall_risk.yaml#L36)。对本模型应从 recovery 可观测时刻开始统计；P95 判定方式和 shadow 暴露时长仍须 P0 预注册。回滚必须只需将 checkpoint 置空或关闭 shadow 开关即可恢复纯规则，不改事件 schema 或历史记录。

| 门禁 | 可判定通过条件 | 当前 |
|---|---|---|
| 开发训练 | `valid=true`、near-fall gate true、hash 全匹配、无 leakage、train/validation 二类非空、实际窗口覆盖审计完成、test 姿态不读取、当前 split dataset 可重复生成 | **条件 Go**：只能标记为 `development_provisional`；不代表 formal、frozen validation 或 shadow 就绪 |
| 冻结 test | v2/v3 来源治理获批；split 与协议 `frozen`；阈值/分层/样本充分性门槛非空；合法 exposure；clean worktree；验证报告 hash 绑定；指定 test 保管人和 acknowledgement | **No-Go** |
| shadow 接入 | P4 checkpoint/calibrator/hash 冻结；当前 split 三 seed 结果通过；连续事件 runner、拒识/fallback、并行字段和回归测试完成；连续背景与老人域 validation 达标 | **No-Go** |
| 替换规则主路径 | 一次性 frozen test 在预注册 Recall、FP/hour、FP/person-day、恢复正确性、校准、分层、延迟与稳定性上全部通过；规则覆盖、回滚演练和独立复现完成 | **No-Go** |

任何数值门槛仍为“待预注册”时，门禁自动判失败，不能用“趋势较好”替代。

## 10. 最终行动清单

最终结论：**近跌倒分支审计通过后，最多做到当前 v3 split 上锁定 test 的 `development_provisional` 训练；当前 validation 不能用于正式发布或反复选模。补齐实际 hard-negative、连续背景、跨来源和老人域后才能进入 shadow；只有 frozen 协议下一次性 test、校准、误报分母、延迟和回滚全部通过后，模型才可接管普通近跌倒确认，规则仍保留为候选、安全覆盖和 fallback。**
