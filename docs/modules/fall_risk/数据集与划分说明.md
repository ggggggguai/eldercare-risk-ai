# 跌倒风险模块数据集与划分说明

更新时间：2026-08-24

## 结论

当前比赛正式交付版本为 `fall-risk-competition-v1-20260819`。正式运行中使用的神经网络模型包括：

- 步态 TCN：seed 43；
- 坐站 TCN：seed 42；
- 跌倒事件 TCN：seed 42、43、44 三 seed 集成。

近跌倒、个体基线和最终风险融合仍使用规则或统计实现，并保留模型不可用时的规则 fallback。正式版本的冻结事实源是 `configs/modules/fall_risk_release_v1.yaml`。

当前训练数据不是把所有视频随机打散后划分，而是先建立统一的 v3 训练视图，再按人员、来源、视频、事件和样本等泄漏保护组进行确定性分组。

### 2. 各正式模型实际使用的训练数据

#### 步态 TCN

- 输入：统一 v3 标签和全视频姿态缓存。
- 任务：`gait_instability_vs_normal_activity`。
- 主数据集：`2,372` 个姿态窗口。
- Train/Validation：`1,849 / 523` 个窗口，保护组为 `114 / 7`。
- Test：未读取、未生成姿态窗口、未评估。
- SCF_MVP_V1 只作为 action encoder 和 walking gate 的 auxiliary 数据；不作为 conditional abnormal head 的正负监督。
- 在此之前有 action pretraining 数据：`2,619` 个窗口，Train/Validation 为 `1,849 / 737`，只使用非 test 数据。

正式运行 checkpoint 为 gait seed 43，但该模型的研究评估仍标记为 `development_provisional`，不能据此宣称 test 或老人域泛化验证完成。

#### 坐站 TCN

- 输入：统一 v3 动作标签、显式背景和困难负例，以及全视频姿态缓存。
- 主数据集：`11,373` 个因果窗口。
- Train/Validation：`10,081 / 1,292` 个窗口，保护组为 `133 / 37`。
- SCF_MVP_V1 的 `298` 条受审标签为 auxiliary、train-only，并进行降权。
- Test：未读取姿态、特征和评估结果。

#### 跌倒事件 TCN

- 输入：统一 v3 `fall_event` 监督和全视频姿态缓存。
- 治理监督：`7,701` 条开发监督，覆盖 `5,338` 个视频；Train/Validation 为 `5,888 / 1,813`。
- 物化数据集：`7,504` 个 `[32, 17, 20]` 因果窗口。
- Train/Validation：`5,721 / 1,783` 个窗口。
- Train 正/负窗口：`1,442 / 4,279`；Validation 正/负窗口：`394 / 1,389`。
- SCF_MVP_V1 的 `298` 条监督全部位于 train。
- Test 标签共 `3,730` 条，但没有读取 test 姿态、真值或指标。

正式运行使用 seed 42、43、44 三个 checkpoint 的平均概率；训练评估结论仍为 `development_provisional / No-Go`，正式交付冻结不等于补齐了 test 或连续老人域证据。

#### 近跌倒、个体基线和风险融合

- 近跌倒正式运行主分支仍是规则，不使用近跌倒 TCN checkpoint。
- 近跌倒 TCN 曾做过开发性训练，但属于历史候选；其数据和指标不能写成当前正式模型效果。
- 个体基线当前使用统计方法，需要连续个人历史和风险真值后才能建立新的模型 release。
- 最终风险融合当前是跌倒模块内部的规则融合，不是另一个训练数据集或综合模型。

## 二、统一 v3 数据怎么划分

### 1. 总体比例和数量

统一 split 的目标比例是：

```text
Train      70%
Validation 15%
Test       15%
```

当前实际数量如下：

| 分区 | Assignment | 资产 | 说明 |
|---|---:|---:|---|
| Train | 11,815 | 3,919 | 用于模型训练 |
| Validation | 3,718 | 1,429 | 用于开发期早停、阈值和模型比较 |
| Test | 3,730 | 1,318 | 保持隔离，当前研究报告未读取 |
| 合计 | 19,263 | 6,666 | 跨分区泄漏为 0 |

### 2. 分组原则

划分方法为 `deterministic_group_level_supervision_balance`，使用固定 seed：

```text
fall-risk-training-labels-v3-20260721
```

划分时优先保证以下对象不会跨分区：

- 同一人员；
- 同一来源或保守来源组；
- 同一视频；
- 同一物理事件；
- 同一动作/事件样本组；
- 可追溯的来源动作组。

因此，某个数据集全部落在 train 或某个来源组全部落在同一分区，是为了防止同源内容泄漏，不是随机划分错误。

### 3. 按任务查看

以下数量仍是 assignment 数量：

| 任务 | Train | Validation | Test | 合计 |
|---|---:|---:|---:|---:|
| 动作语义 `action` | 5,995 | 1,784 | 1,833 | 9,612 |
| 跌倒事件 `fall_event` | 2,662 | 828 | 769 | 4,259 |
| 近跌倒事件 `near_fall_event` | 3,158 | 1,106 | 1,128 | 5,392 |
| 合计 | 11,815 | 3,718 | 3,730 | 19,263 |

统一 v3 的训练就绪状态为：

- `fall_event=true`；
- `near_fall_event=true`；
- `action_type=false`。

这里的 `true` 只表示标签结构、引用和监督 split 通过当前机器门禁，不表示正式 test、老人域泛化或临床有效性已经验证。
