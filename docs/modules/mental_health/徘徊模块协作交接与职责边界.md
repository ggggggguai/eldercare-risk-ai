# 徘徊模块协作交接与职责边界

更新时间：2026-08-18

状态：与 `M0-CAM-5D` 五日算法闭环同步

## 1. 本轮协作目标

本轮只负责算法侧：

```text
video/tracking
  -> automatic episode
  -> trajectory shape
  -> optional multimodal context
  -> daily report
  -> personal baseline
  -> handoff JSON/JSONL
```

后端、前端、账号、权限、设备管理、推送和业务处置由其他团队在算法交付后接入，不属于本轮完成门。

## 2. 当前统一决策

- B01+B02 均为可反复使用的 development 数据；
- 可以共同调分段器、边界 refinement、送模策略、camera 预处理、binary threshold 和必要的轻量 camera 模型；
- 居家视频是素材到位后的补充真实场景输入；缺少视频或人工标签不阻塞 context、日报、基线和 handoff core；
- 全部视频、截图、标注和内部研发权益默认完整授权，不再要求额外 consent/receipt 审批；
- 仍使用匿名 person/session/setup/video ID，原始媒体不进入 Git；
- shape 与 purpose/context 分层；
- 困难行为不单独训练轨迹模型，多模态模型只做上下文解释；
- C4、sealed、PORTABLE 和跨人统计不阻塞五日交付。

## 3. 角色与交付

| 角色 | 输入 | 主要工作 | 交付 |
|---|---|---|---|
| 数据/拍摄 | C6C/居家 MP4、视频清单 | 素材到位时提供可播放视频和 person/session/setup/video binding；标签可后补 | Git 外视频、清单、可选 CVAT XML |
| Tracking | MP4、sidecar | 运行共享 detector/ByteTrack，保留质量状态 | tracking JSONL、media sidecar、运行摘要 |
| 分段器 | tracking、sidecar、B01/B02 truth | 调整状态机、边界 refinement、QC 与 auto acceptance | proposals、selected profile、metrics、failures |
| Shape 模型 | episode interval、tracking | 80 点准备、binary/four-class 推理、必要的轻量 camera 调整 | episode results、model/config identity |
| Context reviewer | wandering-like/uncertain episode、三帧 | 判断电话/找东西/清洁/锻炼等目的上下文 | context reviews；失败为 unknown/unavailable |
| 日级/基线 | episode/context、person/timezone/presence | 按日聚合、3/7/14 日 readiness、偏离计算 | daily reports、baseline profiles/deviations |
| 算法交付 | 全部上游输出 | 运行编排、schema、manifest、回归、说明 | handoff bundle 和运行命令 |
| 后端/前端团队 | handoff bundle | 持久化、API、UI、业务动作 | 本轮不实现 |

## 4. 交接契约

### 4.1 数据到 tracking

必须提供：

```text
person_id
session_id
setup_id
source_video_id
timezone
video path/media ref
```

授权状态默认通过，不需要额外 receipt。技术上仍检查视频可解码、时长、FPS、画面移动和目标人物范围。

### 4.2 Tracking 到 episode

必须提供完整 camera scope、timestamp、bbox、confidence 和 technical quality。不得把短时 `track_id` 当成业务 person ID。

### 4.3 Episode 到 shape

每条 proposal 必须对应一条 result 或明确 error。`proposed+uncertain` 可通过 QC 送模；rejected 不调用模型。uncertain 保持可见，不作为人工 accepted boundary。

### 4.4 Shape 到 context

只传 episode identity、三帧引用/联系图和必要质量摘要。多模态结果不能覆盖 shape、truth 或 boundary。

### 4.5 Episode 到日报/基线

必须显式绑定 person、session、timezone 和 presence。日报按自然日切分；历史不足写 warming/null，不填充伪造零值。

### 4.6 算法到后端

最小交付：

```text
handoff_manifest.json
episode_results.jsonl
context_reviews.jsonl
daily_reports.jsonl
baseline_profiles.jsonl
baseline_deviations.jsonl
run_summary.json
```

后端只需消费稳定 schema；本轮不要求算法仓库提供 HTTP 服务。

## 5. 允许自主处理

执行 AI 可以在徘徊范围内自主处理：

- B01/B02 参数网格和重复回放；
- boundary/QC/refinement 的局部实现；
- camera preprocessing、threshold calibration、轻量 binary-head 或 domain adapter 实验；
- CLI、schema、manifest、测试、文档和 fresh output；
- 路径、timeout、断点、性能和普通环境问题；
- 居家视频的 smoke 和失败降级；
- 居家输入未到位时使用 B01+B02/fixture 完成 input-independent core，并记录 pending 状态；
- 多模态 provider adapter 及无 provider fallback；
- 真实日报/baseline 的薄 adapter。

## 6. 必须暂停的情况

只有以下情况暂停并请求负责人：

- 需要修改人工 shape truth、类别定义或 purpose truth；
- 需要跨 technical hard break 合并；
- 需要覆盖/删除历史证据或原始媒体；
- 需要修改跌倒风险或其他模块；
- 需要修改共享环境定义、push、对外发布；
- 需要把 development 结果声明为临床、跨人泛化或正式产品效果。

缺少居家 MP4、居家人工标签、独立 participant/setup、C4 sealed、receipt 或后端/前端不再是本轮暂停条件。
