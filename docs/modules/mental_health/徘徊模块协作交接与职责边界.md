## 1. 角色和最小交付

| 角色 | 主要职责 | 最小交付 |
| --- | --- | --- |
| 项目负责人 | 确认目标、数据授权、隐私、发布和能力声明 | 授权记录、范围裁决、最终接受或拒绝 |
| R1 徘徊模型 | TCN + Transformer 训练、评估、错误分析和推理接口 | config、checkpoint、predictions、metrics、短报告 |
| R2 检测跟踪 | 从授权视频生成 bbox tracklet，记录遮挡、fragment 和 ID switch | tracking JSONL、质量报告、setup 元数据 |
| R3 平台与身份 | 提供视频会话、稳定业务身份、调度和持久化接口 | 会话/身份/时间契约、联调记录 |
| R4 心理评分 | 决定 episode/day evidence 如何进入心理健康基线和评分 | 字段映射、阈值政策和回归证据 |
| R5 数据采集 | 组织同意、匿名编号、脚本采集、episode 标注和裁决 | session manifest、annotations、review 记录 |
| R6 展示与复核 | 消费算法结果并提供趋势或人工复核界面 | fixture 对齐的展示与复核记录 |
| R7 测试 | 核对 split、指标、重载、数据隔离和摄像头评估程序 | 测试记录、失败案例、sealed 运行记录 |
| R8 最终验收 | 复核证据等级、性能结论和对外表述 | 验收结论、限制和签字 |

任何角色都不能用自己的输出代替另一个角色的真值或签署。例如，R2 的轨迹质量不是行为标签，R1 的预测不是人工真值，R8 的文档审阅也不是摄像头数据授权。

## 2. 输入输出边界

```text
授权视频
  → R2: detection / tracking / QC
  → R5: episode annotation + purpose context
  → R1: train / evaluate / infer
  → R7: split and metric verification
  → R8: evidence-level acceptance
```

### 2.1 R2 → R1：轨迹与质量

R2 提供可回放的 bbox tracklet、时间戳、track 标识、setup、遮挡/断裂/ID-switch 统计和输入版本。R2 不负责把轨迹标成 direct、pacing、lapping 或 random，也不提供心理结论。

### 2.2 R5 → R1：人工 episode 真值

R5 按技术文档2的摄像头标签协议交付匿名 participant/session/setup、episode 起止、可见轨迹形态、purpose context、可评分状态和复核结论。标注者不得查看模型预测后再修改标签。

轨迹形态和行为目的必须分开。目的性 pacing 仍可标为 `observable_pattern=pacing`，同时用 purpose/context 字段说明它是困难负例；不得为了提高指标改成 direct。

### 2.3 R1 → R7/R8：模型结果

R1 至少交付：

- 可读训练配置和 Git commit；
- 数据/split 版本与 seed；
- best checkpoint 和 fresh reload 证明；
- validation 或 sealed predictions；
- macro-F1、逐类 recall、混淆矩阵及原始样本数；
- 摄像头结果需要 episode 指标、eligible negative person-hours、覆盖率和延迟；
- 已知失败、适用范围和下一项性能短板。

## 3. 每次交接的统一格式

每次交接只需一份短记录：

```text
任务：
输入与版本：
代码 commit / 配置：
运行环境：
输出位置：
实际指标或验证结果：
已知限制：
下一责任人及动作：
```

不要在本文追加逐次运行日志。当前任务更新到任务表，实验数据进入对应 `reports/mental_health/` 报告。

## 4. R1 的执行自主权

执行权限和环境规则以仓库根 `AGENTS.md` 为准；本节只用于说明 R1 与其他角色的责任边界，不建立第二套执行规则。

R1 或其执行 AI 可以在 `mental_health.wandering` 范围内自主：

- 修复命令、路径、timeout、日志、checkpoint/resume 和局部测试；
- 修复模型、训练器、评估器或数据适配中的普通代码问题；
- 调整实验配置、学习率、batch size、线程和独立运行目录；
- 对普通失败进行诊断、修正、复测并继续；
- 在不覆盖旧结果的前提下创建新实验和新候选。

普通工程错误不需要逐次请示，也不要求为每次尝试同步全部文档。最终是否接受只看技术文档2定义的闭环、指标和证据边界。

## 5. 必须请负责人决定的事项

只有以下情况需要暂停：

1. 改变标签含义、split、人工裁决、训练数据范围或科学目标；
2. 使用 frozen test、SmartCare official/raw 或 sealed camera 数据进行训练、调参、选组件或错误分析；
3. 删除、覆盖、移动或混用既有数据、模型、原视频和正式报告；
4. 修改共享 `environment.yml`、共享依赖锁、跌倒模块、公共心理评分或其他协作者目录；
5. 真人视频的用途、同意、访问、保留、退出删除或隐私边界尚未确认；
6. push、发布、对外声称目标摄像头、真实老人或临床效果；
7. 从轨迹分类直接接入日级心理风险主链或改变 `AlgorithmEvent` 契约。

“负责人”默认指提出目标并有权确认范围的项目用户；涉及真人数据时还包括项目指定的数据/合规责任人。

## 6. 摄像头数据协作

摄像头 C0/C1 可与模型 M0 并行，但必须满足：

- 项目负责人先确认采集用途、同意、匿名化、保存和退出删除；
- 原视频不进入 Git；
- pilot 全部属于 development，不冒充 sealed；
- 同一 participant/session/take 不跨 development 与 sealed；
- R2 只提供轨迹和 QC，R5 提供 episode 真值，R1 不反向改标签；
- 没有独立真值时只报告工程链、覆盖率、断裂和延迟，不报告准确率或召回率。

详细采集、标注和指标分母见技术文档2第 10 节。

## 7. 最终验收边界

验收按证据等级分别结论，不能互相替代：

1. **公开轨迹模型**：监督训练、保存、fresh reload 和固定 validation 指标闭环；
2. **目标机位工程 pilot**：授权视频可以稳定生成可标注轨迹和模型输出；
3. **目标场景 sealed 评估**：独立人员/场次数据上的 episode 指标、误报率、覆盖率和延迟；
4. **心理健康主链**：稳定 person identity、episode/day 聚合和心理评分策略另行验收；
5. **发布/对外声明**：由 R8 按最终证据和限制签署。

公开轨迹达到 95% 不能写成摄像头、真实老人或临床效果达到 95%。脚本化授权成人 pilot 也不能写成自然老人场景验证。
