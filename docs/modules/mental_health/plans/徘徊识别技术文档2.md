版本：3.1（五日算法闭环路线）

更新时间：2026-08-18

状态：现行技术路线

> 当前执行任务以 [M0-CAM-5D 快速交付总任务书](M0-CAM-5D快速交付总任务书.md) 及其 T0-T5 子任务为准。本文保留模型、数据、状态和接口的技术约束；早期 EP1B/EP2A/C4 研究路线只用于解释历史报告，不再阻塞五日算法 MVP。

## 1. 目标与边界

本专项的短期目标是把已验证的轨迹 shape 候选接成可运行的算法闭环：

```text
C6C/本地摄像头视频
  -> tracking
  -> Camera QC
  -> automatic episode boundary
  -> complete episode 80-point trajectory
  -> TopoWander shape classification
  -> optional multimodal purpose/context review
  -> session evidence
  -> daily report
  -> rolling personal baseline
  -> backend-facing JSON/JSONL
```

本仓库本轮只交付算法 runner、模型输出、日报/基线结果和对接契约，不实现后端、前端、账户、权限、设备管理、消息推送或工单流程。后端按 `module=mental_health` 消费算法结果。

所有当前和后续提供的视频、截图、标注和内部研发使用默认已获得完整授权，不把授权、receipt 或隐私审批作为本轮阻塞。仍保留匿名身份、原视频不进 Git、输出不覆盖和可追溯的技术卫生要求。

## 2. 当前开发事实

### 2.1 模型

- 主模型为 TCN + semantic patch + relation-aware Transformer 的 `TopoWanderMPT`。
- 完整 episode 默认弧长重采样为 80 点；模型时间通道保持关闭。
- 主摄像头指标是 `direct_or_non_wandering` 对 `wandering_like` 的 binary；四类 `direct/pacing/lapping/random` 是诊断输出。
- 当前 fixed primary 是公开轨迹上已固化的候选；先复用，再按 T2 的条件判断是否需要 camera normalization、threshold calibration、轻量 binary-head fine-tune 或 camera-domain adapter。
- 电话、找东西、清洁、锻炼等困难行为不单独建立轨迹分类模型。

### 2.2 摄像头代码

现有底座包括：

```text
camera_adapter.py
camera_qc.py
camera_primary_inference.py
camera_episode_inference.py
camera_episode_import.py
camera_episode_boundary.py
camera_episode_boundary_evaluation.py
camera_episode_proposal_inference.py
camera_episode_proposal_review.py
camera_daily_summary.py
camera_baseline_preview.py
camera_baseline_deviation_preview.py
```

EP1A/EP1B/EP2A 的实现、测试和历史报告均保留。MVP-2S/3S/3D 的 producer/loader 目前主要是 synthetic contract；五日任务通过 real-development adapter 显式绑定真实 person/session/timezone 后复用其计算原语，不把 synthetic 状态直接改写成真实证据。

### 2.3 B01/B02 的新用途

B01 和 B02 统一视为 camera development 数据，可以反复用于：

- boundary 参数和细粒度边界 refinement；
- proposal status 与送模策略；
- camera 预处理和 binary 识别校准；
- 失败案例、context trigger 和日报聚合回归。

旧 B02 frozen-video holdout、旧 v1 proposed-only 结果和 v2 post-hoc 结果全部保留为历史报告。它们不再作为当前代码停止条件，也不再被宣称为独立泛化或临床证据。

### 2.4 居家视频

居家视频是补充真实场景输入，不是 input-independent 算法实现的前置条件。当前没有可用于定量验收的已标注居家视频，按以下规则执行：

1. 居家 MP4 未到位时，用 B01+B02 和确定性 fixture 完成 context、daily、baseline 和 handoff，记录 `home_input_status=awaiting_input`；
2. 居家 MP4 到位但没有人工标签时，直接完成一次 truth-free 全链 smoke，只报告工程结果，不计算 accuracy/F1；
3. 独立人工标签到位后，才补边界、shape 或 context 的 development 定量复核；
4. 如果依据该视频继续调参，明确把它记录为 development，不将同一运行称为独立验收；
5. 居家输入或标签暂缺不阻塞 W5D-03 core、W5D-04 或 W5D-05，也不能被写成算法 run error。

单段居家视频可证明工程链能运行，不能证明跨人泛化、长期误报率、临床效果或稳定七日基线。

## 3. Episode 分段规范

### 3.1 粗分段

状态机复用现有 Camera QC 与 technical hard break：

- 0.5 秒 bucket 作为主统计尺度；
- 持续位移打开候选；
- 持续静止/dwell 软关闭；
- 短暂停、犹豫、转向、折返和闭环默认保持同一 episode；
- 长 gap、ID switch、stream epoch、camera movement 和 track end 形成技术硬断；
- shape、purpose 和冻结模型不得参与 boundary producer。

### 3.2 细粒度 refinement

为提高 B01/B02 和居家视频的边界分辨率，允许在粗边界附近约 2 秒范围内：

- 使用原始 tracking timestamp；
- 使用约 0.25 秒的局部 bucket；
- 对 opening/closing 做 hysteresis 和最小持续时间修正；
- 保留粗边界和细化边界两个字段，便于失败回溯。

不得为了分数跨越 technical hard break、覆盖人工 truth 或把 uncertain 伪装成 accepted boundary。

### 3.3 运行状态

```text
auto_accepted: boundary/QC 条件满足，允许进入高置信统计
uncertain:     原 proposal endpoint/status/reason 保留，允许送模并进入候选统计
rejected:      QC 或技术硬断失败，不调用 shape
error:         工程异常，保留错误码和输入身份
```

`uncertain` 不是人工接受边界。日报必须同时输出 high-confidence 与 uncertain candidate，不能删除 uncertain 来美化 recall/F1。

## 4. Shape 推理规范

每条 proposal 必须对应一条 result，至少含：

```text
episode_id
source_video_id
target_track_id
start_sec/end_sec_exclusive/duration_sec
proposal_status/run_status
qc_status/qc_reason_codes
binary probabilities/predicted_label
four_class probabilities/predicted_label
candidate_id/model_state/config identity
quality_flags
```

推理顺序：

```text
proposal
  -> interval track isolation
  -> accepted-observation QC
  -> 80-point preprocessing
  -> frozen shape forward
  -> binary + four-class result
```

形态与目的严格分离：打电话来回走仍是 `pacing`，目的字段可以是 `purposeful`；模型不能仅凭轨迹推断目的。

## 5. 模型调整决策树

五日开发优先修分段器，但允许根据 B01/B02 的真实结果投入模型调整：

1. 先在 oracle boundary 上测 binary，判断问题来自边界还是 shape head。
2. 若 oracle binary 已达到工程门，保持 fixed primary，只调 segmenter/QC/threshold 的运行策略。
3. 若 oracle binary 不足，先修 bbox-height/缺口处理、归一化和阈值校准。
4. 仍不足时才做轻量 binary-head fine-tune 或 camera-domain adapter。
5. 任何新 candidate 都使用 video-grouped development 复核，保留 fixed primary fallback、model identity、config identity 和回滚说明。
6. 不为每类困难行为单独训练模型；由上下文 reviewer 处理目的性解释。

## 6. 多模态上下文层

### 6.1 触发

只对以下 episode 触发：

- binary 预测为 `wandering_like`；
- boundary/shape 为 uncertain 但需要复核；
- 负责人指定的失败案例。

### 6.2 输入

默认抽取 episode 开始、中间、结束三帧，形成：

- 完整场景联系图；
- 人物 crop；
- 时间戳和 episode id；
- tracking/QC 摘要。

### 6.3 输出

```text
context_label = phone_call | searching | cleaning | exercise
                | social | other | unknown
status = ready | unavailable | error
confidence
rationale
provider/model
frame_refs/frame_sha256
```

多模态结果只写 `purpose/context`，不改 shape、boundary、truth、threshold 或模型类别。调用失败时主链继续并写 `unknown/unavailable`。

## 7. 日级证据与个人基线

### 7.1 日报

每个 `person_id + local_date + timezone` 至少输出：

- presence 和 tracking/QC coverage；
- episode count/duration；
- 四类 shape 与 binary wandering-like count/duration；
- high-confidence/uncertain/unavailable/error 分层；
- count/hour、duration/hour、night ratio；
- context label counts；
- quality flags 和 source episode refs。

### 7.2 基线

沿用现有 3/7/14 日统计规则：

```text
1-2 usable days -> warming_up
3-6 usable days -> initial_ready
>=7 usable days -> stable_ready
reference window -> latest 14 usable days
```

缺 coverage、presence、reference 或 identity 时输出 null/status，不填充伪造零值。单段居家视频只能得到 `warming_up`。

### 7.3 风险边界

五日 MVP 输出 evidence、baseline readiness 和 deviation preview；不得把 shape 或 context 直接改名为医学诊断。是否生成业务 `AlgorithmEvent(module=mental_health)` 由后端对接契约另行决定，本轮只提供可映射字段。

## 8. 数据与标注

- 当前视频全部默认授权；不新增授权审批门。
- B01/B02 可重复使用和反复调参；不再称当前 B02 为不可回调 holdout。
- 居家视频是素材到位后的 truth-free smoke/开发输入；未到位记 `awaiting_input`，未标注也可运行，继续调参时必须记录其 development 身份。
- shape truth 与 purpose truth 分开；不按文件名或模型预测改 CVAT truth。
- `person_id` 来自显式采集/运行绑定；`track_id` 仅是短时轨迹标识。
- 原始视频、截图和外部模型响应放在 Git 外；manifest 只记录引用和 hash。

## 9. 五日执行顺序

```text
T0 交付契约与运行基线
  -> T1 B01+B02 分段器联合优化
  -> T2 自动 episode + shape 识别闭环
  -> T3A 基于 B01+B02/fixture 的三帧多模态 context core
  -> T4 日报 + 滚动个人 baseline
  -> T5 算法对接包与整体验收

居家 MP4 到位后
  -> T3B truth-free smoke + 可选人工标签 development 复核
```

每项的输入、输出、完成门和命令见 [M0-CAM-5D 快速交付总任务书](M0-CAM-5D快速交付总任务书.md)及 T0-T5 子任务书。

## 10. 五日完成标准

完成不等于达到研究发布或临床标准，而是：

1. B01/B02 无人工中间修改即可重复跑通；
2. 分段器有明确 development profile、覆盖率和失败清单；
3. 每条 proposal 有唯一 result 或 error；
4. B01+B02 能完成 context 工程链，居家输入缺席有明确 pending 状态且不阻塞 handoff；
5. wandering-like 可生成 context review 或可解释 unavailable；
6. 真实 person/session/timezone 可生成日报和 baseline readiness；
7. 一条命令或清晰命令序列可生成 handoff bundle；
8. 相关测试通过，输出不覆盖，失败可复现。

居家 MP4 到位后仍应补做一次完整 truth-free smoke，但它是追加证据，不是上述代码闭环完成的前置门。未运行前只能写 `home_smoke_pending`，不能声称已经通过居家验证。
