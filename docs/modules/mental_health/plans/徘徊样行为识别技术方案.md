# 徘徊样行为识别技术方案（老师意见修订版）

更新时间：2026-08-04

> 本文吸收老师提出的“平台接入与隐私控制—轨迹质量门控—形态识别与日级研判—分级关怀与人工复核”闭环要求，是可以照着实现的唯一开发手册。它描述目标模型、数据处理、训练、验证、算法接入和比赛交付顺序；凡是标为“目标”或“待实现”的内容，都不能当作仓库当前已有能力。徘徊识别只为 `mental_health` 模块提供行为证据，不直接诊断抑郁、焦虑、痴呆或其他疾病。

## 0. 先记住六个结论

1. 本文是实施路线，不维护容易过期的“当前已实现清单”。接手开发前先读取[心理健康模块 README](../README.md)和[当前任务](../../../tasks/README.md)，再用代码与测试核对；不要从目标目录树或后续步骤反推现有能力。
2. 本项目只有一条递进路线：手工特征 + Random Forest 和纯 TCN 是必须完成的对照门槛，`TopoWander-MPT` 是唯一目标模型和唯一候选部署模型。它不是把普通 Transformer 直接套在坐标上，而是显式建模短时运动、折返、回访、环绕和轨迹质量。
3. 摄像头主路径采用“无地面锚点的形状域适配”：只用人体检测框底边中心，不要求人体骨架、地面控制点、房间测量、用户标注或 homography；它学习近似的轨迹形状一致性，不恢复真实米制距离。
4. 高级增强的重点是让同一轨迹经过平移、尺度、方向、轻度透视和跟踪噪声后仍保持类别语义。扩散模型、跨类别 Mixup、SMOTE 和任意点打乱不进入这条路线。
5. 模型窗口不能直接产生心理风险等级。窗口先合并为 episode，再生成日级徘徊证据，最后由现有 `mental_health` 个人基线和评分管线生成 `AlgorithmEvent(module=mental_health)`。
6. 公开轨迹和合成污染用于训练及算法基准；比赛最终还要安排少量授权固定摄像头离线烟测。没有人工 episode 真值时只报告覆盖、断裂、拒识和延迟，不能报告准确率、召回率或误报率。



## 1. 唯一开发路线

```text
公开轨迹数据                         授权固定摄像头 MP4/可解码视频流
  ↓                                    ↓
安全转换 + source manifest           media sidecar + 授权/setup 记录
  ↓                                    ↓
TrajectorySample v1                  YOLO person + ByteTrack
  ↓                                    ↓
公开索引缺口规则                     bbox-bottom tracklet + Camera QC
  ↓                                    ↓
公开数据专用 PreprocessingInput       bbox 高度补偿 → CameraWindowInput
                 \                    /
                  来源隔离后的共享纯函数核心
  ↓
按人员/会话/来源先划分，再切窗
  ↓
质量控制 + T=80 重采样
  ↓
共享无锚点形状归一化 + 14 通道
  ↓
训练期随机投影/跟踪污染 + clean/corrupted 一致性
冻结压力测试使用预先保存的污染；真实推理不执行随机增强
  ↓
局部 TCN stem
  ↓
运动语义 patch token
  ↓
带回访/反向/邻接关系偏置的轻量 Transformer
  ↓
分层分类头 + prototype/energy 拒识 + 温度校准
  ↓
pattern=direct/pacing/lapping/random + status=ok/uncertain/unavailable/inference_error
  ↓
片段合并为 episode
  ↓
日级次数、时长、夜间比例、质量和个人基线偏离
  ↓
WanderingDailyEvidence：作为独立行为证据写入 mental_health 的 routine_irregularity/risk_factor_details
  ↓
AlgorithmEvent(module=mental_health)
  ↓
由业务端展示趋势卡片并执行家属/服务端人工复核
```

这是一条连续路线，不设置互相竞争的多套实现方案。Random Forest 和纯 TCN 是必须完成的实验对照，用来回答“新组件是否真的带来收益”，不会成为产品主路径或运行 fallback。地面锚点标定、Pose 骨架和大规模实拍不是训练前置条件；少量授权固定摄像头烟测是比赛落地证据门槛，但不能改变 bbox-only 输入契约，也不能与公开轨迹随机混合训练。

### 1.1 老师路线在本项目中的四个比赛阶段

为避免老师材料中的 `STEP 1–4` 与本文内部编码步骤混淆，统一称为“比赛阶段 A–D”：


| 比赛阶段        | 核心工作                                                 | 必须交付的证据                          |
| ----------- | ---------------------------------------------------- | -------------------------------- |
| A：数据与输入契约   | 安全转换、人工复核、固定 split；摄像头外部责任只做边界说明，具体 sidecar 在步骤 7 实现 | 数据卡、来源哈希、异常报告、split 哈希、摄像头责任边界指引 |
| B：最小模型闭环    | QC、无锚点归一化、手工特征 + Random Forest、纯 TCN、分层分类            | 同 split 对照指标、质量拒识样例、最小可运行推理 CLI  |
| C：鲁棒模型与前置研判 | TopoWander-MPT、污染模拟、自监督、校准/OOD、episode、日级证据和个人基线     | 消融、鲁棒性、校准/拒识报告和算法侧趋势卡片 JSON      |

### 1.2 本仓库负责到哪里

本仓库负责从可解码视频或轨迹文件到标准算法事件的闭环：输入契约、检测/跟踪复用、徘徊识别、质量状态、episode、日级证据、个人基线接入、离线 Demo 和测试报告。萤石账号/token、直播地址签发、家属 App、社区后台、消息推送和工单处置由业务后端或展示工程负责；本仓库只提供 `AlgorithmEvent`、演示 JSON 和接口说明，不另建前端或通知系统。

## 4. 任务定义



### 4.1 模型输入

一个样本是一个单人的连续轨迹窗口：

```text
X = [p1, p2, ..., pT], T = 80
pi = 某一时刻的坐标、运动派生量、可用性和质量
```

模型只接收已经通过人体检测与跟踪获得的单人轨迹。它不直接接收原始 RGB 视频，也不负责人物身份长期重识别。

### 4.2 模型输出

输出必须拆成互不混淆的字段：

```text
status = ok | uncertain | unavailable | inference_error
observable_pattern = direct | pacing | lapping | random | null
reason_codes = [...]
```

四种 `observable_pattern` 的含义：

- `direct`：方向明确、接近目的性移动；
- `pacing`：在相近端点之间反复往返；
- `lapping`：围绕区域或路线重复绕行；
- `random`：方向、回访和覆盖呈无明显目的的复杂移动。

状态规则：

- 正常完成且属于已知形态：`status=ok`，`observable_pattern` 为四类之一；
- 数据质量足够但不属于已知分布或证据不足：`status=uncertain`，`observable_pattern=null`；
- 有效点太少、严重断裂、ID 切换、相机移动或坐标不可用：`status=unavailable`，`observable_pattern=null`；
- 实现或运行异常：`status=inference_error`，`observable_pattern=null`。

`purposeful_repetitive_activity` 只属于未来独立的上下文 gate，当前无锚点 bbox-only 路线默认不输出，也不要求用户补标；它不是第五个轨迹形状类别或 `status`。`unknown` 是训练数据契约中的标签，也不能当成运行状态。

### 4.3 分层标签，而不是直接做四分类

采用两个监督头：

1. 二分类头：`direct` 对 `wandering-like`；
2. 子类型头：仅在 wandering-like 样本上区分 `pacing/lapping/random`。

最终概率：

```text
P(direct)  = 1 - P(wandering)
P(pacing)  = P(wandering) × P(pacing | wandering)
P(lapping) = P(wandering) × P(lapping | wandering)
P(random)  = P(wandering) × P(random | wandering)
```

这样可以利用 SmartCare 的二分类标签，而不伪造它没有提供的三种子类型标签。

### 4.4 输出归属


| 层                  | 允许输出                              | 不允许输出            |
| ------------------ | --------------------------------- | ---------------- |
| 窗口模型               | 轨迹形态概率、质量、`uncertain/unavailable` | 心理风险等级、疾病名称、关怀动作 |
| episode/日级聚合       | 行为次数、时长、夜间比例、覆盖率、类型分布             | 把一次窗口当作心理异常      |
| `mental_health` 管线 | 数字 `risk_level=0..4`、置信度、枚举建议动作   | 医学诊断、跨模块综合风险     |
| 外部展示/业务端           | 把标准事件映射成趋势卡片和人工复核流程               | 改写算法字段、冒充算法验证    |


只有存在上游稳定、非空业务 `person_id` 时，日级证据才可写入跨日个人基线。摄像头 `track_id` 只在当前视频或 stream epoch 内表示短时关联，不能代替 `person_id`。

## 6. 步骤 4：公开轨迹预处理与输入通道

本节只处理步骤 3 冻结的公开轨迹，不接摄像头、不实现 bbox 高度补偿，也不接现有心理评分管线。它的目标是把 1,790 条非 sealed 原始轨迹确定性地变成可追溯的 QC 记录、`T=80` 形状视图和 14 通道；步骤 7 再把经过 Camera QC 的 bbox tracklet 接到同一个形状/通道核心。

### 6.1 输入损坏与质量不足必须分开

处理顺序固定为：

1. 逐项校验第 2.2 节列出的两个来源 JSONL、`split.json`、`split.sha256` 文件、canonical `split_sha256`、assignments 和 split config 哈希；任何不一致都使整个构建失败；
2. 交叉核对 `sample_id/source_dataset/input_role/split/label/supervision_eligible`，禁止现场随机划分；
3. 只读取 train/validation/test 的 1,790 条轨迹，sealed 20 条不得进入预处理输入或输出；
4. schema、非有限坐标、非法 mask 或标签契约属于输入损坏，整个构建失败，不能悄悄跳过；
5. 合法样本若有效点少于 8、轨迹退化或存在无法安全处理的长缺口，保留记录并输出 `preprocess_status=unavailable` 与结构化 `reason_codes`；
6. `ready` 样本再执行去除连续零长度段、重采样、形状归一化、通道和拓扑量计算；
7. 每个产物写回 `parent_sample_id` 和步骤 3 的原 split，不生成新的 split。

当前公开输入没有 mask 缺口，也没有逐点时间。实现仍需用合成单测覆盖 mask，并固定为以下唯一顺序：

1. `valid_input_point_count` 只统计原始 `point_mask=1` 的观测点；少于 8 时立即保留记录并输出 `unavailable/too_few_valid_points`，插值点不能用来凑够 8 点；
2. 去掉首尾 `point_mask=0` 的未观测位置；内部连续缺口不超过 2 个索引时，使用两侧最近观测点做索引域线性插值，超过 2 个时输出 `unavailable/unresolved_internal_gap`；
3. 修复点在输入顶点级记 `quality=0.5`，原始观测点记 1；累计弧长重采样时，坐标线性插值，目标点质量取包围它的两个输入顶点质量最小值；
4. 修复后可用于重采样的位置 `point_mask=1`。步骤 4 的 ready 轨迹都重采样为完整 80 点，因此最终 `point_mask` 应全为 1；通道构造器仍必须用合成 mask 覆盖 `point_mask=0` 时其余通道清零的通用规则；
5. 保存被首尾裁掉的 `trimmed_edge_point_count` 和被内部插值修复的 `interpolated_input_point_count`，使任何修复都可追溯。

摄像头按真实秒数判断 1.5 秒缺口、切 tracklet 和处理 ID switch 的逻辑留在步骤 7，不能用公开数据的“点数”阈值冒充摄像头时间阈值。

`preprocessing.py` 另外定义只在模块内部使用的 `PreprocessingInput`，字段至少为：

```text
sample_id / source_dataset / input_role / split / labels
coordinate_system / points[N,2] / point_mask[N]
point_times_sec[N] or null / point_quality[N]
```

公开 `TrajectorySample v1` 先按上面的索引规则修复缺口，再适配到它。当前代码中的 `PreprocessingInput` 明确只允许 WanderingPatterns/SmartCare 及其固定 split，因此步骤 7 不放宽这个类，也不把摄像头记录伪装成公开样本。摄像头 tracklet 先按真实时间完成 Camera QC、缺口处理和 bbox-height compensation，再进入新的内部 `CameraWindowInput`；它只调用 `arc_length_resample()`、`robust_isotropic_normalize()`、`build_raw_features()`、`compute_topology()` 和 `apply_feature_stats()` 等步骤 4 已有纯函数。两条来源专用路径都从“缺口处理已经完成”之后共享数学核心，不让两点索引规则与 1.5 秒摄像头规则重复执行。两个内部输入对象都不是新的持久化公共 schema，也不修改 `TrajectorySample v1`。

### 6.2 三种坐标语义不能混写

- `resampled_source_points`：对原来源坐标按累计弧长重采样到 80 点。WP 仍是 `source_native`，SmartCare 仍是 `image_normalized`；该数组必须同时保存 `input_coordinate_system`。
- `image_normalized_points`：当前只有 SmartCare 可以提供，并且必须与其 `resampled_source_points` 逐点相同；WP 没有画布宽高，必须写 `null`，不能用样本自身 x/y min-max 伪造图像坐标。
- `shape_normalized_points`：所有 `ready` 样本均生成，只用于形状模型；`unavailable` 样本写 `null`。

公开数据没有 bbox height，因此步骤 4 直接令局部补偿增益为 1，只实现下面的稳健中心和单一各向同性尺度：

```text
c_x = median(x_valid)
c_y = median(y_valid)

span_x = Q95(x_valid) - Q05(x_valid)
span_y = Q95(y_valid) - Q05(y_valid)
scale = sqrt(span_x^2 + span_y^2)

q_i = (p_i - [c_x, c_y]) / scale
```

Q05/Q95 统一使用 `numpy.quantile(..., method="linear")`。全部几何计算使用 `float64`。固定 `scale_epsilon=1e-8`；`scale <= scale_epsilon` 时输出 `unavailable/insufficient_motion`，不能只靠 epsilon 把静止抖动放大。平移和正的统一缩放应得到相同的 `q_i`；独立 x/y 拉伸后的结果必须与原结果明显不同，证明算法保留了长宽比。这里不是“拒绝一条长方形轨迹”，而是禁止归一化器把任意长方形强制拉回正方形。

固定数值单测容差：平移/正统一缩放后的 shape 最大绝对误差 `<=1e-6`；直线的最大 `abs_curvature <=1e-7`；对测试夹具将 x 轴乘 2、y 不变后，shape 与原 shape 的最大绝对差必须 `>=1e-3`。这些只是确定性实现容差，不是数据筛选阈值。

### 6.3 14 个逐点通道

每个 `ready` 样本先输出严格 `[80,14]` 的 `raw_features`：


| 编号  | 通道                         | 含义                                 |
| --- | -------------------------- | ---------------------------------- |
| 1–2 | `x, y`                     | shape-normalized 坐标                |
| 3–4 | `dx, dy`                   | 相邻位移，不是速度                          |
| 5   | `step_length`              | 位移长度                               |
| 6–7 | `sin_heading, cos_heading` | 朝向                                 |
| 8–9 | `sin_turn, cos_turn`       | wrap 到 `[-π,π]` 的转角                |
| 10  | `abs_curvature`            | 相邻有效位移得到的局部弯曲强度                    |
| 11  | `normalized_dt`            | 可信时间存在时的相邻时间间隔                     |
| 12  | `time_available`           | 当前公开数据固定为 0                        |
| 13  | `point_mask`               | 点是否可用于特征和 loss                     |
| 14  | `quality_score`            | 公开 observed 点为 1、索引插值点为 0.5、无效点为 0 |


冻结以下边界约定，避免不同实现得到不同 tensor：

- 第一个点的 `dx/dy/step_length/heading/turn/curvature/dt` 全部为 0；
- 零长度位移没有合法朝向，`sin_heading=cos_heading=0`，不能用 `cos=1` 假装朝向为 0°；
- 曲率在边界点、零长度段或缺失邻点处为 0；
- `point_mask=0` 的位置除 mask 通道本身外，其余 13 个通道全部为 0；模型 loss/attention 还必须显式使用 mask，不能只把它当普通数值特征；
- 当前 1,790 条公开轨迹全部没有真实时间，所以全部 `normalized_dt=0`、`time_available=0`，不能从点序伪造 2 Hz、速度或持续时间。

逐点公式也固定，避免两个实现产生不同通道：

```text
step_epsilon = 1e-8
d_i = q_i - q_(i-1), i >= 1
s_i = ||d_i||_2
heading_i = atan2(dy_i, dx_i)                  if s_i > step_epsilon
turn_i = wrap_pi(heading_i - heading_(i-1))   if d_i 与 d_(i-1) 都有效
abs_curvature_i = abs(turn_i)                 # 无量纲离散曲率代理
wrap_pi(a) = ((a + pi) mod (2*pi)) - pi       # 区间 [-pi, pi)
```

`d_i` 只有在相邻两个点 mask 均为 1 时有效；`turn_i` 只有在相邻两段位移均有效时有效。无效 heading/turn 的正弦和余弦都置 0；有效直线转角为 0，因此其 `sin_turn=0, cos_turn=1`。第 0 点全部差分通道为 0，第 1 点没有前一段有效方向，因此 turn/curvature 相关通道也为 0。

将来只有在配置和模型 artifact 都声明 `temporal_features_enabled=true` 时才启用时间通道：先对窗口内所有相邻、可靠且严格为正的 `dt_i=t_i-t_(i-1)` 求中位数 `median_positive_dt`，再令 `normalized_dt_i=clip(dt_i/median_positive_dt, 0, 4)`、`time_available_i=1`；其他位置两通道为 0。非递增时间在进入这里前即失败或由 Camera QC 切断。

### 6.4 拓扑诊断初值

`topology.py` 在 shape 视图上输出连续量和确定性诊断，固定参数为 `reversal_direction_span=2`、`reversal_angle_deg=120`、`reversal_merge_gap=2`、`revisit_index_gap=8`、`revisit_radius=0.10`、`max_revisit_links=5`：

- 反向事件：对 `i=2..77` 计算进入向量 `v^-_i=q_i-q_(i-2)` 和离开向量 `v^+_i=q_(i+2)-q_i`；涉及点都有效且两向量范数大于 `step_epsilon` 时才计算夹角。夹角至少 120°即为候选；按索引排序后，相邻候选索引差 `<=2` 的合并为一个事件，事件代表取夹角最大的候选，平局取较小索引；
- 累计绕转：使用第 6.3 节所有有效 `turn_i`，输出 `absolute_winding=abs(sum(turn_i))/(2*pi)`；
- 回访候选：枚举所有 `j-i>=8` 且 `||q_j-q_i||_2<0.10` 的有效点对，输出完整的 `revisit_pair_count`；诊断连线按 `(distance,i,j)` 排序后贪心选择、端点不复用，最多保留 5 条，并另存 `selected_revisit_links`；
- 直线、人工 pacing 和单闭环夹具必须分别验证零反向/低曲率、预设反向位置和绕转误差。

这些是步骤 4 的固定工程初值，用于单测、图形核查和后续手工特征；它们不是临床阈值，也不在 validation/test 上反复调到“看起来最好”。

### 6.5 训练统计和当前有效数量

只用 `preprocess_status=ready` 的 train 轨迹中 `point_mask=1` 的位置计算一基编号通道 1–10 的中位数和 IQR：

Q25/Q50/Q75 统一使用 `numpy.quantile(..., method="linear")`，固定 `iqr_epsilon=1e-8`。每个通道使用：

```text
IQR = Q75_train - Q25_train
denominator = IQR if IQR > iqr_epsilon else 1.0
z = (x - Q50_train) / denominator
```

一基编号通道 11/12 分别是 `normalized_dt/time_available`，按自身时间规则处理；通道 13/14 分别是 `point_mask/quality_score`，保留 `[0,1]` 语义。这四个通道都不做 IQR 标准化。换成代码零基索引即 10/11 为时间、12 为 mask、13 为质量。validation/test 不参与统计。`feature_stats.json` 必须绑定 split/config/input 哈希，记录零 IQR 通道和 `temporal_features_enabled=false`，供步骤 6 和推理复用。

每条 ready 记录同时保存两个矩阵，禁止只写一个含义不明的 `features`：

- `raw_features`：第 6.3 节定义的原始 14 通道，用于检查和复算；
- `model_features`：只对 `raw_features` 的通道 1–10 使用上述 train 统计做变换，通道 11–14 原样复制；标准化后再次执行 mask 清零。

步骤 6 的时序模型只消费 `model_features`，诊断图和拓扑量使用未标准化的 `shape_normalized_points/raw_features`。这样既不让 validation/test 泄漏进统计，也不会把标准化后的数值误当作几何坐标。

当前预期为：train 原始 1,272 条，其中 SmartCare 15 条 `<8` 点输出 unavailable，因此 train-ready 为 1,257 条；validation-ready 278 条，WP test-ready 240 条。所有 1,790 个 ID 都必须出现在步骤 4 索引中，质量门只能改变 `preprocess_status`，不能改变 split 或让样本静默消失。

## 7. 公开训练轨迹与摄像头轨迹的无锚点形状域适配



### 7.1 固定技术决策

本路线不要求用户在地面放锚点、测量房间、画 ROI、标行为或校正骨架，也不恢复真实米制坐标。系统只要求视频本身能被人体检测和短时跟踪，随后把公开轨迹与摄像头轨迹都转换到同一个近似形状空间。

唯一主链为：

```text
公开干净轨迹
  → 来源坐标归一化
  → 随机相似/投影变换
  → 通用摄像头观测污染
  → 无锚点形状归一化
                                  \
                                   → clean/corrupted masked-denoise 与一致性训练
                                  /
摄像头视频或跟踪 JSONL
  → YOLO person + ByteTrack
  → bbox 底边中心
  → 画面宽高归一化
  → camera QC
  → bbox 高度辅助局部尺度补偿
  → 无锚点形状归一化
```

这里的目标是“同一种轨迹形状经过不同画布、拍摄位置和轻度透视后，模型仍给出相近表征”，不是把摄像头像素精确还原成平面图坐标。公开数据上的结论仍命名为 `shape_benchmark`；在没有目标摄像头封存视频时，不能称为已完成真实摄像头泛化验证。

### 7.2 需要处理的差异与本路线边界


| 差异                       | 无锚点处理                      | 仍不能解决的内容           |
| ------------------------ | -------------------------- | ------------------ |
| 画布大小和坐标原点                | 宽高归一化、平移消除                 | 真实米制位置             |
| 人物远近造成的尺度变化              | bbox 高度辅助的局部位移补偿           | 精确深度和真实步速          |
| 摄像头朝向                    | 全角度旋转增强、方向关系特征             | 摄像头外参              |
| 轻度俯视和透视                  | 随机投影增强、clean/corrupted 一致性 | 某个房间的精确 homography |
| FPS 和漏帧                  | 真实时间聚合、mask、短缺口插值          | 长遮挡中未观察到的真实路径      |
| 检测框抖动                    | 相关噪声、平滑底边偏移、denoise        | 严重误检和错误身份拼接        |
| track fragment/ID switch | 切断轨迹、拒识                    | 跨视频长期人员身份          |
| 目的相同形状                   | `uncertain` 和非诊断表述         | 找东西与无目的游走的可靠区分     |
| 跨摄像头                     | 每个视频独立归一化                  | 跨机位 XY 拼接和房间距离     |


必须接受以下事实：二维轨迹相同的“无目的来回走”和“打电话来回走”在输入上可能完全等价。更深的网络不能恢复输入中不存在的目的，因此模型输出的是 `pacing/lapping/random` 等可观察形状证据，不是心理或医学诊断。

### 7.3 摄像头输入固定为 bbox-only

摄像头主路径只复用人体检测和跟踪，不依赖 `PoseObservation`：

```text
scripts/collect/run_fall_tracking.py
  → TrackObservation JSONL
  + media sidecar
  → wandering.camera_adapter
  → wandering.camera_qc
  → bbox-height compensation
  → CameraWindowInput
  → 步骤 4 已验收的 source-neutral shape/channel 函数
  → 步骤 4 冻结 feature_stats
```

当前 `TrackObservation` 已有 `frame_id/track_id/bbox/track_confidence/timestamp_sec`，但没有画面宽高、稳定视频标识、device/epoch、来源哈希或相机运动状态。必须从有限 MP4 元数据或受信上游生成 sidecar，不能根据 bbox 最大值猜宽高。步骤 7 的 `wandering-media-v1` 固定至少包含：

```json
{
  "schema_version": "wandering-media-v1",
  "source_video_id": "video-0001",
  "source_group_id": "session-0001",
  "device_id": "camera-unknown",
  "setup_id": "fixed-setup-0001",
  "stream_epoch": "video-0001",
  "media_ref": "relative/or/deidentified/video.mp4",
  "source_sha256": "...",
  "tracking_jsonl_sha256": "...",
  "video_width": 1920,
  "video_height": 1080,
  "nominal_fps": 25.0,
  "duration_sec": 300.0,
  "capture_started_at": null,
  "timezone": null,
  "coordinate_system": "pixel_xyxy_top_left",
  "detector": {"backend": "ultralytics_yolo", "model": "yolov8n.pt", "version": "..."},
  "tracker": {"backend": "bytetrack", "config": "bytetrack.yaml", "version": "..."},
  "fixed_camera_assumed": true,
  "camera_motion_state": "not_checked",

```

`media_ref` 只能是相对 POSIX 路径或去标识引用；sidecar、日志和 manifest 禁止保存萤石账号、token、签名直播 URL、请求头或本机绝对路径。`camera_motion_state` 只允许 `stable/moved/not_checked`：`moved` 使该 setup/epoch 全部窗口 `unavailable`；`not_checked` 可以用于合成契约测试或有限工程烟测，但必须写 `camera_motion_not_verified`，不能宣称系统已经从 bbox 自动检测相机移动。仅靠 tracking JSONL 无法可靠恢复背景运动，后续若增加 MP4 背景运动检测，结果仍通过这个字段进入同一 QC，不另开推理路线。

`authorization_status` 只允许 `synthetic_fixture`、`authorized_camera_engineering_smoke`、`authorized_camera_labeled_evaluation`，并分别一一映射到同名证据范围中的 `synthetic_camera_contract`、`authorized_camera_engineering_smoke`、`authorized_camera_labeled_evaluation`。`denied`、空值、拼写错误和任何未知值必须在 adapter 层失败关闭，禁止用“非 synthetic 即已授权”的兜底映射。

对像素 bbox `b_i=[x1_i,y1_i,x2_i,y2_i]`，固定计算：

```text
u_i = ((x1_i + x2_i) / 2) / video_width
v_i = y2_i / video_height
h_i = (y2_i - y1_i) / video_height
p_i = [u_i, v_i]
```

`p_i` 是图像中的落脚代理点，`h_i` 是相对人体框高度。两者都不是地面真实坐标。禁止使用 bbox 中心作为主轨迹点，因为蹲起或框高度变化会让中心产生明显假位移。

原始 tracklet 必须保存为 `wandering-bbox-tracklet-v1`，至少包括：

```text
schema_version/tracklet_id/segment_index
source_video_id/source_group_id/device_id/setup_id/stream_epoch/track_id
frame_width/frame_height/source_fps
frame_indices/point_times_sec/bbox_xyxy_norm
bbox_bottom_points/bbox_heights/detection_confidence
observed_mask/interpolated_mask/quality_flags
media_ref/source_sha256/tracking_jsonl_sha256
```

原始 bbox tracklet 必须一直保留用于审计。Camera QC 通过后，先使用其中的 bbox height 完成第 7.4 节补偿，再把 `corrected_points + point_times_sec + observed_mask + point_quality` 适配为内部 `CameraWindowInput` 并调用步骤 4 的 source-neutral 纯函数；不得修改已冻结的 `TrajectorySample v1/PreprocessingInput` 去塞 bbox height，也不得在补偿前丢掉 height。`track_id` 只在当前 tracking session 内有效，分组键固定为：

```text
(source_group_id, source_video_id, device_id, setup_id, stream_epoch, track_id)
```

相同数字的 `track_id` 不能跨视频合并；ID 改变默认产生新 tracklet，不自动猜测它仍是同一个人。

### 7.4 无锚点形状归一化公式

这一节是训练轨迹与摄像头轨迹对齐的核心，训练和推理必须调用同一实现。

#### 第一步：图像或来源画布归一化

- 摄像头轨迹使用第 7.3 节的 `[0,1]^2` bbox-bottom 坐标；
- SmartCare 使用已知画布宽高归一化；
- WanderingPatterns 先减来源坐标中位数，再使用下面的稳健尺度；
- 不同数据源都不能分别对 x/y 做独立 min-max 拉伸。



#### 第二步：bbox 高度辅助的局部尺度补偿

只对具有 bbox 高度的摄像头或模拟摄像头轨迹执行：

```text
height_i = rolling_median(h_i, valid_only)
height_ref = median(height_i)
gain_i = clip(height_ref / height_i, 0.5, 2.0)

r_0 = p_0
r_i = r_(i-1) + gain_i × (p_i - p_(i-1))
```

人物越远时 bbox 通常越小，`gain_i` 会适度放大被透视压缩的局部位移；人物越近时反之。该补偿只产生“相对身体尺度下的移动”，不能解释成米。为防止坐下、弯腰或检测框突变造成误补偿：

- bbox 高度先做 5 点滚动中位数；
- 只在 bbox 合法、检测置信度合格且高度变化不过快的点使用；
- `gain` 必须截断到配置范围；
- 高度不可用时固定 `gain=1` 并降低 `quality_score`；
- 高度突变与轨迹瞬移同时发生时切断，不尝试修复。

公开干净轨迹没有 bbox 高度，直接令 `r_i=p_i`。公开轨迹生成投影视图时，由投影器同步生成平滑的虚拟 bbox 高度场，再走完全相同的补偿代码。

高度补偿只负责生成 `corrected_points` 和质量信息；之后必须直接复用步骤 4 已验收的稳健中心、单一各向同性尺度、弧长重采样和 14 通道实现，步骤 7 不得另写一份归一化公式。

#### 第三步：稳健中心和各向同性尺度

对有效的 `r_i`：

```text
c_x = median(r_i.x)
c_y = median(r_i.y)

span_x = Q95(r_i.x) - Q05(r_i.x)
span_y = Q95(r_i.y) - Q05(r_i.y)
scale = sqrt(span_x^2 + span_y^2)

q_i = (r_i - [c_x, c_y]) / max(scale, epsilon)
```

`q_i` 即 `shape_normalized`。使用单个各向同性尺度是为了保留环路长宽比和往返方向；不得用两个不同分母把每条轨迹强行拉成正方形。

若有效移动范围低于当前输入域冻结的 `minimum_motion_extent`，不放大静止抖动，而是输出 `status=unavailable`、`reason_codes=["insufficient_motion"]` 并绕过分类头。`epsilon` 只防止数值除零，不能让静止窗口进入分类器；不要新增 `normal_transit` 类别来掩盖质量不足。

#### 第四步：不在推理时强制 PCA 旋转

闭环和随机轨迹的主方向不稳定，PCA 还存在正负号翻转。因此推理时不把轨迹强制旋转到某个方向；方向不变性由训练时全角度旋转、转角/曲率通道和 relation bias 学习。这样比每个窗口单独估计“正方向”更稳定。

### 7.5 无锚点随机投影生成器

公开干净轨迹在训练集内生成一个对应的“伪摄像头观测”视图：

```text
clean shape
  → 随机旋转/平移/统一缩放到虚拟画布
  → 轻度各向异性缩放和剪切
  → 随机 projective warp
  → 视野边缘裁切
  → 生成平滑虚拟 bbox 高度场
  → 第 7.6 节跟踪污染
  → 第 7.7 节 QC
  → 第 7.4 节无锚点归一化
  → corrupted shape
```

初始训练范围固定为：


| 参数            | 训练范围            | 说明        |
| ------------- | --------------- | --------- |
| 旋转            | `[-180°, 180°]` | 消除机位朝向依赖  |
| 统一缩放          | `[0.70, 1.30]`  | 模拟画面占比    |
| x/y 比例        | `[0.85, 1.15]`  | 只允许轻度各向异性 |
| shear         | `[-0.10, 0.10]` | 模拟斜视      |
| projective 系数 | `[-0.12, 0.12]` | 模拟轻度远近压缩  |
| 可见范围裁切        | `0%–15%`        | 模拟进出画面    |
| 虚拟 bbox 高度    | `[0.06, 0.60]`  | 只作为相对尺度代理 |


投影器使用显式、可记录的 3×3 矩阵，而不是调用不可解释的图像模型生成坐标：

```text
H = [[sx, kx, tx],
     [ky, sy, ty],
     [px, py,  1]]

[x'_i, y'_i, w_i] = H × [x_i, y_i, 1]
u_i = x'_i / w_i
v_i = y'_i / w_i
virtual_height_i = clip(h0 / abs(w_i), 0.06, 0.60)
```

`w_i` 太小或符号翻转时直接拒绝该投影。虚拟高度与同一投影分母绑定，而不是再独立随机一条无关曲线；随后只加入小幅相关高度噪声。这样能够形成“远处轨迹压缩、人体框也变小”的一致模拟关系。

这些值是无目标相机数据时的工程初值，不是假装从目标房间测得的真值。每次增强保存随机矩阵、参数、seed 和接受/拒绝原因。投影后必须通过类别语义检查器；若唯一闭环被剪掉、pacing 反向点消失或 direct 被扭成多次折返，丢弃该增强。

训练使用轻度和中度投影；高强度投影只进入压力测试。不要让模型通过“学会所有畸形轨迹”来掩盖不合理输入。

### 7.6 通用摄像头观测污染

没有目标摄像头人工轨迹时，不拟合所谓精确 `corruption profile`，而是建立版本化的通用污染族，并报告模型对不同严重程度的敏感性。


| 污染               | 训练初值             | 压力测试          | 处理原则                   |
| ---------------- | ---------------- | ------------- | ---------------------- |
| AR(1) 相关抖动 `rho` | `0.6–0.9`        | 同训练           | 比独立白噪声更接近框漂移           |
| 归一化噪声 `sigma`    | `0.002–0.012`    | `0.012–0.030` | 同时限制最大单点偏移             |
| 随机漏点             | `0%–8%`          | `8%–20%`      | mask 保留缺失              |
| 连续缺失块            | `1–6` 个 2 Hz 点   | `6–16` 点      | 超过 QC 上限直接 unavailable |
| 底边偏移             | bbox 高度的 `0%–4%` | `4%–10%`      | 模拟脚点被框底扰动              |
| 时间抖动             | `±0.08 s`        | `±0.20 s`     | 时间仍须严格递增               |
| 量化分辨率            | 360p/720p/1080p  | 低分辨率组合        | 先量化再归一化                |
| 边界截断             | `0%–10%`         | `10%–25%`     | 保留 truncated flag      |


固定生成 low/medium/high 三档 manifest。训练从 low/medium 采样；validation 只使用冻结参数；high 用于 OOD/QC。严重瞬移、两人轨迹拼接和 ID switch 不作为类别保持增强，只生成应被 `camera_qc` 拒绝的故障样本。

公开跟踪数据将来可用于调整这些通用范围，但在没有目标机位数据时仍不能把它写成“目标摄像头实测分布”。

### 7.7 Camera QC 与统一窗口

固定运行规格：

```text
视频输入：建议至少 15 FPS
跟踪记录：保留 frame_id、timestamp、bbox、confidence、track_id
轨迹聚合：2 Hz
窗口：40 秒 = 80 点
stride：20 秒
长事件：在 episode 层合并相邻窗口
```

以视频相对时间 `0.0 s` 为固定网格原点，`bucket_index=floor(timestamp_sec/0.5)`；不能按每条轨迹的首个点重新对齐。每个 0.5 秒桶先删除置信度低于 `0.25` 或 bbox 非法的记录，再用 `track_confidence/sum(track_confidence)` 对合法 bbox-bottom 和 bbox height 做确定性加权平均，不是机械地每 N 帧抽一帧。桶时间固定为桶中心；同一 `(scope, track_id, frame_id)` 重复或同轨时间倒退直接失败。模型点质量不直接使用检测器概率：实际观测桶固定 `point_quality=1.0`，短缺口插值桶固定 `0.5`，检测置信度单独保存在 QC 字段，避免改变步骤 4 已冻结的质量通道语义。

窗口固定从全局 `0,20,40,... s` 网格取 `[start,start+40)`，每窗恰好 80 个桶。候选窗先保存原始 detection 数、observed bucket 数、有效比例、最长连续空桶、置信度和边界标记；首尾空桶不外推，内部连续空桶最多 3 个时才对 point/height 做时间线性插值，4 个及以上先切断 tracklet。对同一份合法、按时间有序的输入重复运行，不得改变桶、窗口 ID 或窗口内容。

摄像头时间始终用于分桶、Camera QC、缺口判断、窗口起止和 episode 合并，但能否进入模型通道由模型 artifact 决定。步骤 5/6 基于当前公开数据得到的 artifact 必须写 `temporal_features_enabled=false`；调用这类 artifact 时，即使摄像头时间可信，`model_features` 零基索引 10 的 `normalized_dt` 和索引 11 的 `time_available` 仍强制为 0，索引 12 始终是 mask。只有使用带可信时间或版本化时间增强的数据重新训练、冻结验证并发布新的 `temporal_features_enabled=true` artifact 后，才允许按第 6.3 节给模型非零时间通道，禁止直接改变旧模型输入语义。

以下情况必须切断 tracklet 或输出 `unavailable`：

- video/device/stream epoch/track ID 改变；
- frame 或 timestamp 不递增；
- 画面宽高、坐标系或视频源改变；
- bbox 非法、越界或高度接近零；
- gap 超过配置上限；
- 相邻位移除以 bbox 高度后仍出现异常大跳跃；
- bbox 高度与位置同时突变；
- tracker 目标 lost/ambiguous；
- 多人交叉后出现 ID switch 疑点；
- 固定相机发生明显移动、变焦或云台转动。

相机运动检测可以由算法侧视觉 QC 自动比较背景特征或参考帧完成，不要求用户放锚点；若无法可靠判断，则配置中声明 `fixed_camera_assumed=true`，发生明显全局漂移的片段输出 `unavailable`。

步骤 7 v1 的 Camera QC 初值固定在 `wandering_camera_v1.yaml`，用于合成故障与工程链测试，不是假装从目标摄像头标定得到：

- 有效点比例不少于 `0.75`；
- 最长连续缺口不超过 `1.5 s`；
- 至少 8 个有效原始点；
- 不存在明确 ID switch 或无法解释的 jump；
- 首尾 bucket 均有真实观测，不做边缘外推；
- `motion_extent_body = Q05–Q95 corrected-point 对角范围 / median(smoothed_bbox_height)` 不少于 `0.25`；
- `step_rate_body = ||p_i-p_(i-1)|| / median(h_i,h_(i-1)) / dt` 大于 `3.0 body-heights/s` 时切断并记 `suspected_id_switch`；
- 相邻平滑高度比大于 `1.8` 且同期位移大于 `0.75 body-heights` 时切断并记 `height_position_discontinuity`。

缺口统一按 0.5 秒 bucket 的空桶数定义：`gap_seconds = consecutive_missing_bucket_count × 0.5`。因此连续 3 个空桶恰为 `1.5 s`，允许插值；连续 4 个空桶为 `2.0 s`，必须切段。不得用缺口两侧两个真实观测的 timestamp 差代替这个量，因为 3 个空桶两侧的观测间隔会是 `2.0 s`，会把允许的边界样本误拒绝。

高度使用 5 点居中滚动中位数，边缘缩短窗口；补偿增益仍固定截断到 `[0.5,2.0]`。这些是保守的开发初值，不是产品通用阈值，也不能用公开 test 或无真值摄像头输出来调高分。将来若授权 camera development 数据支持修改，必须发布新的 camera config/version 并保留 v1 结果。公开无逐点时间的轨迹只按点序或弧长重采样，`time_available=0`；不能给它们伪造 2 Hz 速度。

### 7.8 进入目标模型后的增强训练协议

只有步骤 5 的 RF、步骤 6 的纯 TCN、步骤 7 的 Camera QC/最小离线链全部通过各自门槛后，才执行本节。RF 和纯 TCN 不使用下面的自监督、relation bias、prototype 或 clean/corrupted 一致性。

#### 训练阶段 I：公开轨迹自监督预训练

每条 development-train 轨迹生成：

```text
clean view
corrupted view A
corrupted view B
```

执行曲率感知 masked-denoise：

- clean 学习局部运动和拓扑结构；
- corrupted 预测对应的 clean 位移、转角、曲率和 patch 关系；
- A/B 的 embedding 和分类分布保持一致；
- mask、时间可用性和质量通道一起参与；
- severe corruption 只训练拒识/QC，不训练四类标签。



#### 训练阶段 II：成对监督微调

每个 batch 从 24 条按类别平衡的原始样本产生 24 个 clean 和 24 个随机 corrupted 视图：

```text
24 public clean labeled
24 paired projected/corrupted labeled
```

损失固定为：

```text
L = 1.00 × L_binary
  + 0.80 × L_subtype
  + 0.20 × L_prototype
  + 0.15 × L_view_consistency
  + 0.20 × L_masked_reconstruction
  + 0.20 × L_clean_denoise
```

- `L_binary/L_subtype` 学习 direct 与三种 wandering-like 形状；
- `L_prototype` 保持类别簇；
- `L_view_consistency` 约束 clean/corrupted 的 embedding 和概率；
- `L_clean_denoise` 要求受污染视图恢复 clean 运动语义；
- SmartCare 二分类样本只计算它确实拥有的二分类监督。

本路线不使用 CORAL、DANN、目标域伪标签、测试时在线更新或把 domain ID 当输入，因为当前没有可靠目标域标签，强行对齐比保守的形状不变性更容易产生错误。

#### 训练阶段 III：校准和冻结

- 所有归一化统计、增强范围、prototype、温度和拒识阈值只使用 development train/validation；
- WanderingPatterns 没有可靠 participant ID 时只做固定轨迹级 `shape_benchmark`；
- SmartCare 官方 20 条保持封存，最终只运行一次；
- 测试结果按 clean、low、medium、high corruption 分开报告；
- 不把合成的多个窗口当作新增独立人员或独立轨迹。



### 7.9 Anchorless Compatibility Report

每次 adapter、归一化、增强或模型版本变化，都生成一份无锚点兼容性报告。

步骤 7 只交付输入契约、确定性不变性手算/单测和注入故障拒绝的工程子集；污染严重度曲线在步骤 8 生成，prototype/energy、校准与 `uncertain` coverage 在步骤 12 生成。未实现的栏位写 `not_run` 和原因，不能用零值冒充通过。

#### A. 输入契约

```text
source/video/tracklet count
width/height/fps coverage
bbox validity and confidence
valid-point ratio and longest gap
duplicate sample/group count
validation_scope = public_shape_benchmark
                 | synthetic_camera_contract
                 | synthetic_camera_corruption
                 | authorized_camera_engineering_smoke
                 | authorized_camera_labeled_evaluation
```



#### B. 归一化不变性

- 平移前后 `shape_normalized` 最大误差；
- 统一缩放前后最大误差；
- 旋转前后预测一致率；
- bbox 高度补偿启用/关闭的轨迹差异；
- 同一 clean 轨迹的多投影视图 embedding cosine similarity。

平移和统一缩放应满足数值级确定性测试；旋转和投影属于学习不变性，必须报告分布，不能用单个示例代替。

#### C. 污染严重度曲线

对 clean/low/medium/high 分别报告：

```text
macro-F1 / balanced accuracy
clean-corrupted label agreement
confidence change
prototype distance / energy
uncertain-unavailable coverage
```

建议初始开发门槛：mild 一致率不低于 `0.95`，medium 不低于 `0.90`，medium macro-F1 相对 clean 下降不超过 `0.10`；这些门槛必须在看封存测试前冻结。

#### D. 注入故障拒识

分别注入长缺口、瞬移、ID 拼接、bbox 高度突变和相机全局移动，报告 QC 检出率。建议 severe 故障进入 `unavailable` 的比例不低于 `0.90`，否则先修 QC，不扩模型。

#### E. 跨来源结果

- WanderingPatterns clean 与 corrupted；
- SmartCare 主集 validation；
- SmartCare 官方封存 20 条；
- 每类混淆矩阵、校准和拒识；
- Random Forest 与纯 TCN 对照。

报告必须根据实际门禁填写，未完成时不得提前写成“已验证”。模板为：

```text

```



### 7.10 无用户标注的分层运行输出

本节描述步骤 12–13 完成后的目标运行契约。步骤 7 尚无校准/OOD gate，只输出 `wandering-camera-prediction-v1` 的 `ready/unavailable/inference_error` 和四组对照概率，不能提前把 `ready` 改写为下面的最终 `ok/uncertain`。

最终用户不需要选择房间、画路线、放锚点或标记“正在徘徊”。算法运行时分三层产生可观察证据，不能把三个层级压成一次窗口告警。

窗口层 `WanderingWindowResult`：


运营规则：

- 移动范围不足：`status=unavailable`，`reason_codes` 包含 `insufficient_motion`，不伪造 `normal_transit` 类别；
- 轨迹形状清楚且质量合格：`status=ok`，输出 direct/pacing/lapping/random 概率；
- 质量合格但不属于已知形状：`status=uncertain`，`pattern=null`；
- 长缺口、ID switch、异常跳跃或相机移动：`status=unavailable`，`pattern=null`；
- 没有自动化任务上下文时，`purpose_context=unknown`，不得让用户补标，也不得凭 XY 猜目的；
- `wandering_like` 只表示可观察的徘徊样形状证据，不直接生成抑郁、痴呆或其他诊断。

`WanderingWindowResult`、`WanderingEpisode` 和基线前的 `WanderingDailySummary` 都不含 `risk_level` 或自由文本 `action`。只有日级证据进入现有心理健康基线与评分管线后，才能产生数字 `risk_level=0..4` 和枚举 `recommended_action`。当前心理模块映射为 `0→record_only`、`1→observe`、`2→remind_user`、`3/4→manual_review`；老师材料中的展示等级与人工复核文案不作为代码契约。若后续确需修改，必须作为全心理模块策略变更单独评审，不能由徘徊子模块自行改写。

## 8. 第三阶段目标模型：TopoWander-MPT

进入本节前必须同时满足：split 已冻结；RF 和纯 TCN 能在同一协议下复现；已有二分类、四分类混淆矩阵和失败案例；Camera QC 与无锚点归一化通过测试。TopoWander-MPT 只有在相同 split、seed 集合和评估预算下证明相对两个基线的稳定增益，才有资格成为候选运行 artifact；网络更复杂本身不是创新有效的证据。

### 8.1 为什么不是普通 CNN、LSTM 或 Transformer

- 1D CNN/TCN 擅长局部转向和短期往返，但对“隔很久又回到同一区域”的关系表达不足。
- 普通 Transformer 能看长关系，却必须从小数据中自己学会哪些点表示折返、回访和环绕，容易过拟合。
- 徘徊类别的关键不是单个点，而是“局部运动语义 + 相隔较远片段之间的拓扑关系”。

因此，模型先用 TCN 学局部运动，再把轨迹变成语义 patch，并把回访、反向和空间邻近关系直接作为 attention bias。

### 8.2 张量尺寸

默认配置：

```text
输入                   [B, 80, 14]
TCN 输出               [B, 80, 96]
patch length = 8
patch stride = 4
patch 数量              19
语义拼接后投影          [B, 19, 96]
加入 CLS token          [B, 20, 96]
Transformer 输出        [B, 20, 96]
CLS 表征                [B, 96]
```



### 8.3 局部 TCN stem

使用 3 个残差块：


| 块   | kernel | dilation | channels | dropout |
| --- | ------ | -------- | -------- | ------- |
| 1   | 3      | 1        | 64       | 0.10    |
| 2   | 3      | 2        | 96       | 0.10    |
| 3   | 3      | 4        | 96       | 0.10    |


每块结构：

```text
LayerNorm → depthwise temporal conv → GELU
→ pointwise conv → dropout → residual
```

卷积前将 `point_mask` 应用于输入，卷积后再次屏蔽无效位置，避免 padding 形成伪运动。

### 8.4 运动语义 patch

每 8 个点、步长 4 形成一个 patch。除 TCN pooled embedding 外，计算以下可解释语义：

- patch 路径长度；
- 首尾净位移；
- 路径效率 `net_displacement / path_length`；
- 平均与最大转角；
- 累计绝对曲率；
- 反向次数；
- 对历史 patch 的最近回访距离；
- 局部覆盖面积；
- 停留比例；
- 有效点比例和平均质量。

语义向量经小型 MLP 投影后与 TCN embedding 相加，而不是把人工特征直接送进最终分类器。

### 8.5 关系偏置 Transformer

使用 2 层、4 头、`d_model=96`、MLP ratio 2、dropout 0.10 的轻量 Transformer。

对任意 patch `i,j`，构造关系特征：

1. 时间距离桶；
2. 是否相邻；
3. 两个 patch 中心的空间距离；
4. 时间相隔较远但空间接近的 `revisit`；
5. 平均朝向近似相反的 `reverse-heading`；
6. 是否落在相同局部区域；
7. 两个 patch 的最低质量。

关系 MLP 输出每个 attention head 的 bias：

```text
attention(i,j) =
softmax((Qi · Kj) / sqrt(d) + relative_time_bias + relation_bias + quality_bias)
```

这一步是模型的核心创新组件。它让模型有明确通道区分：

- `pacing`：相同路径上的远时反向；
- `lapping`：持续转向、空间闭合和重复绕行；
- `random`：多区域回访但缺少稳定周期；
- `direct`：高路径效率、较少回访和反向。



### 8.6 分层分类头

`CLS` 表征进入：

- `binary_head: 96 → 64 → 1`；
- `subtype_head: 96 → 64 → 3`；
- `projection_head: 96 → 64`，供 prototype loss 和未知拒识使用。

初始总损失：

```text
L =
1.00 × L_binary
+ 0.80 × L_subtype
+ 0.20 × L_prototype
+ 0.15 × L_view_consistency
+ 0.20 × L_masked_reconstruction
+ 0.20 × L_clean_denoise
```

说明：

- `L_subtype` 只对有 pacing/lapping/random 标签的样本计算；
- `L_view_consistency` 约束同一 clean 轨迹的投影/污染视图预测和 embedding 一致；
- `L_masked_reconstruction` 重建被掩码的运动语义；
- `L_clean_denoise` 让 corrupted 视图恢复对应 clean 的位移、转角、曲率和 patch 关系；
- 权重是起始配置，后续只能依据 validation 和消融调整，不能用 test 调。



### 8.7 未知样本拒识

闭集 softmax 总会选一个类别，因此增加两类证据：

1. prototype distance：表征到预测类中心是否过远；
2. energy score：整体 logits 是否像训练分布。

validation 上确定两个阈值。满足以下任一条件输出 `uncertain`：

- 最大校准概率低于阈值；
- prototype distance 过大；
- energy score 超出已知分布范围；
- 两个增强视图预测严重不一致。

如果输入质量不合格，应在模型前输出 `unavailable`，不要让拒识头替质量控制背锅。

## 9. 第三阶段增强：曲率感知掩码预训练

先在训练划分内做自监督预训练，再监督微调。validation/test 绝不参与预训练。

### 9.1 掩码策略

每条轨迹掩盖 25%–35% patch：

- 多数从低/中显著 patch 采样，防止任务只剩“猜直线”；
- 少量主动掩盖一个高显著 patch，让模型学习从上下文重建折返或环路；
- 不同时掩盖所有高显著证据；
- 无效 patch 不计入重建损失。



### 9.2 显著度

patch 显著度由以下量归一化加权：

```text
saliency =
0.35 × curvature
+ 0.25 × reversal
+ 0.25 × revisit
+ 0.15 × local_coverage_change
```



### 9.3 重建目标

不重建每个原始像素或完全精确坐标，而重建：

- 位移和转角统计；
- 路径效率；
- 曲率；
- 反向与回访关系；
- patch embedding。

这样更接近分类所需语义，也减少模型记住数据源坐标风格的风险。

## 10. 第三阶段增强：只做语义保持的数据增强



### 10.1 总规则

- 先划分，再增强；增强只在 train 内发生。
- 所有随机参数写入 augmentation manifest，保证可复现。
- 坐标、mask、时间和派生特征必须联合变换。
- 增强后重新计算所有派生通道，不能直接扭曲旧特征。
- 每条增强轨迹都通过类别语义检查器；失败就丢弃该增强，不改标签硬塞进训练。



### 10.2 几何增强

几何增强分两层。第一层在虚拟图像坐标中执行第 7.5 节的相似变换、剪切、投影和视野裁切，再经过同一无锚点归一化器；第二层只对 `shape_normalized` 做小幅语义保持扰动：

- 随机旋转：`[-180°, 180°]`；
- 镜像：x 或 y 轴，概率 0.5，但保持 winding 的绝对值；
- 各向同性缩放：`[0.85, 1.15]`；
- 小平移：归一化范围内 `[-0.05, 0.05]`；
- 轻微各向异性缩放：两个轴 `[0.90, 1.10]`，比例不能过大。

`image_normalized` 只用于 adapter/QC 回放，不作为房间语义输入。所有投影参数必须作用于原始点、虚拟 bbox 高度、mask 和边界状态，再重新计算 `shape_normalized` 与 14 个通道。

### 10.3 时间增强

有真实逐点时间时：

- 单调速度扭曲：全局倍率 `[0.8, 1.25]`；
- 分段平滑 time warp：3–5 个控制点，导数始终为正；
- 轻微起止裁剪后重新采样，但必须保留至少一个类别关键结构。

没有时间戳的数据只做索引域重采样，`time_available` 保持 0，不能借增强制造速度标签。

### 10.4 通用跟踪观测噪声

正式训练使用第 7.6 节的版本化 low/medium 污染族。基础相关噪声为：

```text
noise[t] = rho × noise[t-1] + epsilon[t]
rho ∈ [0.6, 0.9]
sigma ∈ [0.002, 0.012]  # 归一化坐标，训练范围
```

它比每点独立高斯抖动更接近检测框底边的缓慢漂移。同时加入：

- 随机点缺失：0%–8%；
- 连续遮挡块：1–6 个 2 Hz 点；
- 与 bbox 高度成比例的底边偏移；
- 分辨率量化、时间抖动和轻度边界截断；
- 低质量区间：降低 `quality_score` 并置相应 mask；
- 短缺口按真实预处理规则插值。

没有目标机位数据时，这些参数只代表“需要覆盖的合理扰动范围”，不代表目标摄像头实测误差。必须报告 low/medium/high 严重度曲线。严重瞬移、轨迹拼接和 ID switch 不作为类别保持增强，而作为质量控制与 OOD 测试样本。

### 10.5 曲率与拓扑引导增强

先为每条轨迹计算：

- 路径效率 `E = 净位移 / 总路程`；
- 反向次数：稳定行进后朝向变化超过 120°；
- 累计绕转 `W = |Σ unwrap(turn)| / 2π`；
- 回访率：时间距离足够远的点对中，空间距离小于阈值的比例；
- 覆盖熵：网格访问分布的熵；
- 端点区域重复率。

然后应用以下局部增强：

- 在低曲率、非关键段做弹性弯曲；
- 对关键转弯点做小幅控制点扰动；
- 对非关键直线段压缩或拉伸；
- 对回访段整体平移很小距离，但保留回访关系；
- 对一个语义片段做 cutout，供自监督重建，不直接用于有监督分类。



### 10.6 类别语义检查器

增强后必须满足：


| 类别      | 必须大致保持的证据                  |
| ------- | -------------------------- |
| direct  | 较高路径效率；不能新增多次稳定反向或闭环       |
| pacing  | 至少保留两次方向反转或端点往返；端点区域仍重复    |
| lapping | 累计绕转绝对值和闭合/回访仍明显；不能剪掉唯一环路  |
| random  | 多转向、空间覆盖或非周期回访仍存在；不能变成规律往返 |


检查不是用一套阈值重新标注，而是比较“增强前后相对变化”：

```text
ratio_after / ratio_before 在允许范围内
关键事件数量不跌破类别最低保真条件
增强后不触发另一类别的强冲突条件
```

所有被拒绝增强的原因计数并写入报告，方便发现参数过强。

### 10.7 拓扑约束程序化轨迹

为补充极少见形状，可从类别模板生成：

- pacing：两个端区之间的带噪多次往返；
- lapping：椭圆、矩形或非规则闭环的重复绕行；
- random：受边界约束的相关随机游走，带若干非周期回访；
- direct：少量平滑弯曲但整体进度明确。

程序化样本每个 batch 不超过 20%，始终带 `synthetic=true`，不能进入 validation/test，也不能单独支撑性能结论。它只帮助正则化，也不能被写成真实摄像头证据。

### 10.8 本路线明确不用

- SMOTE：对展平轨迹插值会产生不连贯路径；
- 跨类别 Mixup/CutMix：会混合互斥的拓扑语义；
- 任意点顺序打乱：破坏时间因果；
- 无上限独立高斯噪声：制造锯齿和虚假转向；
- x/y 分别 min-max：会改变长宽比和类别几何；
- 把 bbox 高度补偿解释成真实深度或米制距离；
- 用自动生成的相机参数冒充地面标定结果；
- GAN/扩散生成：当前样本与验证规模不足以证明生成轨迹保持标签，复杂度也不能补足目标摄像头证据。



## 11. 数据划分：必须在切窗和增强之前

| SmartCare 开发池 190 条                | 原 `source_group_id` 是 `dd/MM/yyyy HH:mm` 小时时间戳，190 条恰好是 190 个单例            | 严格解析后派生 `smartcare_day:YYYY-MM-DD` 自然日替代组，整日进入同一分区 | 自然日不是 `person_id` 或真实采集 session，不能声称跨人或跨 session 无泄漏 |
| SmartCare official validation 20 条 | 已有固定 ID 和文件哈希                                                              | 20 条全部直接写入 `sealed_external_test`                  | 不能在训练、早停、阈值、校准、可视化抽检或模型选择时读取其轨迹和标签                   |
| 未来授权摄像头视频                          | 需要稳定 `person_id/source_group_id + session`；短时跟踪还需 video/device/epoch/track | 在步骤 7 和步骤 14 单独建立开发/封存清单                           | 不能把临时 `track_id` 当跨日身份，也不能与公开轨迹随机混分                  |


为什么不能直接按 SmartCare 当前 `source_group_id` 分组：它精确到小时，每条开发轨迹的值都不同，效果等同于逐样本随机划分，不能防止同一自然日的相邻采集进入两边。自然日只是当前字段不足时的保守替代；开发池还存在跨多日连续采集块，因此报告中必须使用“自然日替代组不重叠”，不能写“SmartCare 无泄漏”。

WanderingPatterns 原目录中的两份 pickle 字节数和 SHA-256 相同，是同一来源的重复副本。步骤 3 只读取已验收的单份 `samples.jsonl`，不得把两份 pickle 当成两个独立数据源或跨源测试集。

### 11.2 唯一固定分配


| 数据源                                | `train`                         | `validation`                   | `test`    | `sealed_external_test`         |
| ---------------------------------- | ------------------------------- | ------------------------------ | --------- | ------------------------------ |
| WanderingPatterns 1,600 条          | 1,120；每类 280                    | 240；每类 60                      | 240；每类 60 | 0                              |
| SmartCare 开发池 190 条                | 152；normal 73、wandering-like 79 | 38；normal 17、wandering-like 21 | 0         | 0                              |
| SmartCare official validation 20 条 | 0                               | 0                              | 0         | 20；normal 10、wandering-like 10 |
| 合计                                 | **1,272**                       | **278**                        | **240**   | **20**                         |


具体算法固定如下：

1. WanderingPatterns 使用 `seed=20260731`。在 `direct/pacing/lapping/random` 每个类别内部，按 `SHA256("20260731:wandering_patterns:" + sample_id)` 从小到大排序；每类前 280 条进入 train，接着 60 条进入 validation，最后 60 条进入 test。不要依赖 Python 集合顺序或现场 `random.shuffle`。
2. SmartCare 严格按 `%d/%m/%Y %H:%M` 解析开发池时间，只取自然日。validation 固定为 `2020-09-20` 与 `2020-10-07` 两日，共 38 条；其他 8 个开发日全部进入 train，共 152 条。这一选择在模型训练前冻结，约为 80%/20%，且 validation 包含一个相对 9 月主采集期更晚的日期。
3. SmartCare 开发池不设内部 test；WanderingPatterns test 只回答四类公开轨迹形状识别，正式名称为 `public_shape_benchmark`。
4. SmartCare official validation 的 20 个 ID 全部且只进入 `sealed_external_test`。只有二分类模型、预处理、阈值和校准全部冻结后才允许一次性评估；它不参与四类子类型头，因为其 `pattern_label=unknown`。
5. WP 可用于 `direct` 对 `wandering-like` 二分类和四类形状监督；SmartCare 只计算二分类损失，四类损失必须用 mask 排除。

各分区的职责固定为：

- `train`：拟合模型、计算训练期统计量、生成训练增强和自监督视图；
- `validation`：早停、超参数、阈值与校准，不更新模型参数；
- `test`：模型方案冻结后评估一次 WanderingPatterns `public_shape_benchmark`；
- `sealed_external_test`：全部开发冻结后评估一次 SmartCare 外部二分类结果。

不同来源、不同任务的结果分表报告，不能把 WanderingPatterns test 与 SmartCare sealed 指标合并成一个准确率。

### 11.3 完全重复与形状近邻怎么处理

步骤 3 先做确定性审计，再写 split：

1. 对原始点序列计算前向和时间反向的规范哈希。完全相同或完全反向且标签相同的轨迹必须绑定到同一分区；如果标签冲突，立即失败并列出 sample ID，不能自动改标签。
2. 对 WanderingPatterns 另做“形状近邻诊断”：弧长重采样到 32 点，减去中心并除以单一 Frobenius 范数，在前向/反向、旋转和镜像中取最小“归一化 full-Procrustes 距离”；固定报告 `<0.02`、`<0.05` 两档的总对数、同类/跨类对数和跨分区对数。实现没有再除以 `sqrt(32)`，因此不要称作逐点 RMS。
3. 近邻阈值只用于暴露模板相似性，不用于强行聚类或改写本节固定分配。当前只读预审在 `<0.05` 下发现 9,061 对近邻，其中 9,055 对同类，而且阈值会形成上百条轨迹的大连通块；强制整块分配会让四类精确比例失效，也没有人员语义依据。这个数值必须由步骤 3 的正式程序重新生成；如果不能复现，停止验收并检查距离定义和输入哈希。
4. 因此 WanderingPatterns 的 test 永远只称 `shape_benchmark`。split 报告必须同时给出跨分区近邻数量和此限制，不能只写“ID 无交集”后宣称严格无泄漏。
5. SmartCare 开发池至少报告完全重复、反向完全重复、自然日分布和标签分布。官方文件先整文件校验哈希，步骤 3 随后只流式提取 `sample_id` 用于写入 sealed 分区；不得把它的坐标或标签交给形状诊断、可视化、阈值选择或模型代码。

同一原始轨迹切出的所有窗口，以及它的 clean、projected、corrupted 和 synthetic 派生视图，都必须保留 `parent_sample_id` 并继承同一 split。增强视图不增加独立样本数，不参与 bootstrap 的独立单位计数。

#### 5.2 固定 26 维手工特征

特征 schema 固定为 `wandering-handcrafted-features-v1`。只读取 ready 记录的未标准化 `shape_normalized_points/raw_features/topology`；所有计算使用 `float64`、`epsilon=1e-8`、`numpy.quantile(method="linear")`，标准差使用 `ddof=0`。设 shape 点为 `q_i`，有效位移长度为 `s_i`，有效转角为 `theta_i`：


| #   | 特征                             | 固定定义                                                                     |
| --- | ------------------------------ | ------------------------------------------------------------------------ |
| 1   | `path_length`                  | `sum(s_i)`                                                               |
| 2   | `net_displacement`             | 首末 shape 点欧氏距离                                                           |
| 3   | `path_efficiency`              | `net_displacement / max(path_length, epsilon)`                           |
| 4   | `step_length_mean`             | 有效 `s_i` 均值                                                              |
| 5   | `step_length_std`              | 有效 `s_i` 总体标准差                                                           |
| 6   | `step_length_max`              | 有效 `s_i` 最大值                                                             |
| 7   | `heading_resultant_length`     | 有效单位朝向向量均值的模                                                             |
| 8   | `abs_turn_mean`                | `abs(theta_i)` 均值                                                        |
| 9   | `abs_turn_std`                 | `abs(theta_i)` 总体标准差                                                     |
| 10  | `abs_turn_max`                 | `abs(theta_i)` 最大值                                                       |
| 11  | `abs_turn_p90`                 | `abs(theta_i)` 的线性 P90                                                   |
| 12  | `cumulative_abs_turn`          | `sum(abs(theta_i))`                                                      |
| 13  | `turn_direction_coherence`     | `abs(sum(theta_i)) / max(sum(abs(theta_i)), epsilon)`；无有效转角时 0           |
| 14  | `absolute_winding`             | 直接读取步骤 4 topology                                                        |
| 15  | `reversal_count`               | `len(reversal_events)`                                                   |
| 16  | `reversal_rate`                | `reversal_count / max(有效转角数, 1)`                                         |
| 17  | `reversal_angle_mean_deg`      | 反向事件角度均值；无事件时 0                                                          |
| 18  | `revisit_pair_count`           | 步骤 4 topology 的回访点对数                                                     |
| 19  | `revisit_pair_density`         | 回访点对数除以所有 `j-i>=8` 的有效点对数                                                |
| 20  | `nearest_far_distance_clipped` | 所有 `j-i>=8` 点对的最小距离，上限截为 0.10                                            |
| 21  | `convex_hull_area`             | 确定性单调链凸包面积；共线时 0                                                         |
| 22  | `radius_of_gyration`           | 点到均值中心平方距离的均值再开方                                                         |
| 23  | `spatial_anisotropy`           | 二维总体协方差特征值的 `(lambda_max-lambda_min)/max(lambda_max+lambda_min,epsilon)` |
| 24  | `valid_point_ratio`            | 有效 mask 比例                                                               |
| 25  | `mean_quality`                 | quality 通道均值                                                             |
| 26  | `min_quality`                  | quality 通道最小值                                                            |


禁止把 `source_dataset`、sample ID、输入点数、来源坐标、绝对 x/y 均值、`model_features`、时间通道或图像画布作为模型特征。当前 24–26 可能是常量，仍保留稳定 schema，并在报告中列为零方差特征；不能为了让 RF 看起来更复杂而偷偷删除或替换。

人工直线、pacing、闭环和回访夹具必须验证公式。这里分两层测试：handcrafted extractor 直接接收 shape 点时，整条 26 维向量必须对平移、旋转、镜像和时间反向在 `1e-6` 容差内不变；“来源点 → 步骤 4 稳健中心/各向同性尺度 → 26 维特征”的端到端链路还必须对正统一缩放不变。不能要求直接缩放 shape 点后的向量不变，因为 `path_length`、`net_displacement`、`convex_hull_area` 和 `radius_of_gyration` 按定义会改变。任何 ready 记录产生 NaN/Inf 都立即失败，不做中位数填补。

#### 5.3 两个固定监督任务

四分类类别顺序固定为：

```text
0 direct
1 pacing
2 lapping
3 random
```

它只使用 `pattern_supervision_eligible=true` 的 WP ready 记录。SmartCare 的 `pattern_label=unknown` 不能进入四分类特征表、fit 或指标。

二分类类别顺序固定为：


它使用全部 `binary_supervision_eligible=true` 的 ready 记录。训练时不同时设置 `class_weight`，而是固定采用“来源 × 类别”四组等总权重：

```text
sample_weight_i = N_train / (4 * N_(source,label))
```

当前精确权重为：


| 来源/类别         | 样本数 | 单样本权重          |
| ------------- | --- | -------------- |
| WP / 0        | 280 | `1.1223214286` |
| WP / 1        | 840 | `0.3741071429` |
| SmartCare / 0 | 63  | `4.9880952381` |
| SmartCare / 1 | 74  | `4.2466216216` |


四组各占总训练权重的四分之一；四分类本身每类 280，统一权重为 1。指标始终按真实样本无权重计算，并按来源分别报告。

#### 5.5 development 与 frozen WP test 受控分阶段

development 阶段只用 train 拟合两个任务的 5 个 seed 模型，validation 只做评估，不参与 fit、参数或 seed 选择。development feature table 只保存 train+validation 的 1,535 条 ready 记录；配置、特征 schema、data index、模型、validation 预测/指标和 semantic fingerprint 全部写完后生成不可覆盖的 development manifest。训练命令最后必须打印该 manifest 的 SHA-256，作为后续 evaluator 由项目负责人显式传入的信任根；evaluator 不能“先读任意 manifest，再相信它里面对自己的说明”。

随后才允许显式执行 `frozen_wp_test`：evaluator 必须先绑定 development manifest 文件哈希，加载原样的 train-only 模型，再首次对 240 条 WP test 提取手工特征、预测和计算指标。development 阶段虽已为 bundle 完整性解析过这些行，但不得产生 test feature table、预测、指标或选择信号。evaluator 不得重新训练、改阈值或修改 feature schema。SmartCare official 20 条在步骤 5 始终封存。

固定主指标：

- 四分类：WP validation macro-F1；
- 二分类：`mean(WP validation macro-F1, SmartCare validation macro-F1)`，即来源等权的 source-macro macro-F1；
- balanced accuracy 同时报告，但混合 validation 总体 accuracy 不能替代分来源结果。

每个 cohort 都报告混淆矩阵、accuracy、macro-F1、balanced accuracy 和逐类 precision/recall/F1。二分类另报 AUROC、AUPRC、sensitivity、specificity、Brier 和将概率截到 `[1e-15,1-1e-15]` 后的 NLL。WP test 与 SmartCare validation 绝不合并；WP test 只能称 `public_shape_benchmark`，报告必须重申 `<0.05` 有 4,054 对跨分区形状近邻、不是人员级泛化。

步骤 5 不设置“F1 必须达到多少”才能完成。它是对照基线：即使效果差，只要协议无泄漏、结果真实、可复现且失败分析齐全，也可以关闭步骤 5；禁止为了提高分数重切 split、删除困难样本或开启 official 调参。

#### 6.2 两个任务使用两个完全独立的 TCN

每个 seed 必须训练两个从随机初始化开始、互不共享参数/优化器/checkpoint 的模型，五个 seed 共 10 个模型：

1. `four_class`：只看 WP，输出 `direct/pacing/lapping/random`；
2. `binary`：看 WP+SmartCare，输出 `direct_or_non_wandering/wandering_like`。

不能用“一个共享 trunk + 两个头”。如果共享 trunk，SmartCare 二分类损失会改变 WP 四分类表示，而步骤 5 的 RF 四分类只用 WP，二者不再是相同监督口径的公平对照。

四分类模型内部使用固定分层头：一个 `wandering_gate` logit 判断 direct 与 wandering-like，一个三分类 `subtype` logit 只区分 `pacing/lapping/random`。设 `g=sigmoid(gate)`、`s=softmax(subtype)`，最终四类概率固定重构为：

```text
P(direct) = 1 - g
P(pacing) = g * s[pacing]
P(lapping) = g * s[lapping]
P(random) = g * s[random]
```

单样本联合 NLL 固定为：direct 使用 `-log(1-g)`；三种 wandering 使用 `-log(g)-log(s[真实子类])`。代码用数值稳定的 `binary_cross_entropy_with_logits` 和 `cross_entropy` 实现，不能先手工 sigmoid/softmax 后直接取 log。四分类所有 train 样本权重为 1，不再人为设置 gate/subtype 的额外系数。二分类模型使用一个 sigmoid logit、阈值固定 0.5，并逐样本复用步骤 5 的“来源 × 类别”四组等总权重；loss 归约固定为 `sum(weight_i * BCE_i) / sum(weight_i)`。两个任务都不得用 test 分数改 seed、阈值或结构。

#### 6.3 唯一输入和 mask 传播规则

模型唯一数值输入是步骤 4 ready 记录的 `model_features: float32[B,80,14]`，另取 `point_mask: float32[B,80]` 作为显式 mask；不读取 RF 的 26 维特征、来源、sample ID、原点数、绝对坐标或图像画布。输入校验必须拒绝错误 shape、非二值 mask、NaN/Inf 和全 0 mask。

14 通道按零基索引解释：索引 10 是 `normalized_dt`，索引 11 是 `time_available`，当前冻结 artifact 中二者都为 0；索引 12 是 `point_mask`，必须与外部 mask 完全相同；索引 13 是 `quality_score`。文档其他地方所说“时间两通道”均指索引 10/11，不包括索引 12 的 mask。

进入 projection 前先把 mask=0 位置的全部 14 通道清零；每个残差块的主支和残差相加后再次乘 mask；最后只对有效位置做 masked mean pooling。测试必须证明：任意修改 masked slot 的 14 个输入值都不改变输出。当前公开 ready 样本的 mask 全为 1，所以“部分 mask 可运行”只是接口/单元测试契约，不能写成已在真实缺失轨迹上验证的鲁棒性。

#### 6.4 固定纯 TCN 结构

两个独立模型使用同一结构定义，但参数不共享：

```text
[B,80,14]
  -> 逐点 1x1 projection，14 -> 64
  -> pre-LN depthwise temporal residual block，64 -> 64，kernel=3，dilation=1
  -> pre-LN depthwise temporal residual block，64 -> 96，kernel=3，dilation=2
  -> pre-LN depthwise temporal residual block，96 -> 96，kernel=3，dilation=4
  -> masked mean pooling，得到 [B,96]
  -> 任务头
```

每个 block 的固定顺序是 `LayerNorm(channel) -> GELU -> depthwise Conv1d -> pointwise 1x1 Conv1d -> GELU -> dropout(0.10) -> residual add -> mask`；通道改变时残差支使用无偏置 1x1 projection。卷积是非因果 same padding，不使用 BatchNorm。四分类模型有 `96->64->1` gate 头和 `96->64->3` subtype 头；二分类模型只有 `96->64->1` 头。隐藏层均为 GELU 和 dropout 0.10，最后一层不加激活。步骤 6 不加入 patch、attention、relation bias、自监督、prototype、energy 或数据增强。

#### 7.3 严格输入 schema 与 fail-closed 规则

`wandering-media-v1` 使用本文“摄像头输入固定为 bbox-only”一节给出的完整字段。tracking 兼容输入只读取：

```text
frame_id / track_id / bbox / track_confidence / timestamp_sec
```

忽略但保留审计事实：上游 `person_id` 只是 `prefix + track_id`，`center` 是 bbox 中心，`speed_px_per_sec` 是 bbox 中心像素速度。它们不能覆盖 bbox-bottom、不能成为业务 `person_id`、不能跨视频拼接。

适配前逐行验证：JSON 对象、字段类型、有限数值、`frame_id` 和 `track_id` 都是非负整数、`0<=confidence<=1`、`0<=x1<x2<=video_width`、`0<=y1<y2<=video_height`、同轨 frame/timestamp 严格递增、无重复 `(scope,track_id,frame_id)`。sidecar 必须与 tracking 文件 SHA、宽高、坐标系和有限媒体 SHA 一致；任一 schema/hash/尺寸/路径问题使整个 CLI 失败，不能跳过坏行后继续产生“完整”报告。

`tracking_input.jsonl` 固定为校验后的规范化审计副本，不是来源文件的原始字节副本：先对来源 tracking 文件原始字节计算 SHA-256 并与 sidecar 的 `tracking_jsonl_sha256` 核对；通过全部校验后，只保留上述 5 个消费字段，按完整隔离键、`timestamp_sec`、`frame_id` 确定性排序并用 canonical JSONL 写入 `tracking_input.jsonl`。manifest 分别记录 `source_tracking_sha256` 和 `normalized_tracking_sha256`；后者同时由产物表绑定。两者不得混写，也不得为了规范化而回写来源文件。

完整隔离键固定为：

```text
(source_group_id, source_video_id, device_id, setup_id, stream_epoch, track_id)
```

adapter 不跨键排序、插值或合并。track ID 改变自然产生新轨迹；同一 ID 的异常跳跃只能记 `suspected_id_switch`，不能声称识别出所有真实 ID switch。`camera_motion_state=moved` 使对应 setup/epoch 全部不可用；`not_checked` 只作为质量 flag，不冒充已检测稳定。

#### 7.4 固定处理顺序

严格按下面顺序实现，不能先归一化再做 Camera QC：

1. 拒绝已存在输出目录，加载 exact camera config，并验证第 2.5 节全部冻结依赖；
2. 验证/规范化 sidecar 和 tracking JSONL，计算 bbox-bottom `[(x1+x2)/2/W, y2/H]` 与归一化 bbox height `(y2-y1)/H`；
3. 按完整隔离键建轨迹；时间倒退、明确相机移动、hard jump 或 height-position discontinuity 形成硬边界；
4. 以视频 `0.0 s` 为原点做 0.5 秒 bucket；过滤低置信度记录后，以置信度权重对 bucket 内 bbox-bottom/height 做确定性平均；候选时间覆盖仍由过滤前的合法原始观测决定，低置信度 bucket 只变成未观测，不得收缩或删除候选窗；
5. 按连续空桶数处理缺口：3 个空桶恰为 `1.5 s`，仍保留；4 个及以上空桶形成硬边界。不得用两侧观测时间差判定。随后从全局 `0,20,40,... s` 和过滤前观测覆盖构造 `[start,start+40)` 候选窗，计算原始 detection 数、observed ratio、最长空桶和边缘覆盖；首尾低置信度或全低置信度轨迹仍须生成候选窗并输出 `unavailable/unobserved_window_edge`，不能静默消失；
6. 只对窗内最多 3 个连续内部空桶做时间线性插值；不对窗口首尾外推，保留 observed/interpolated mask 和计数；
7. 用 5 点滚动中位数平滑 bbox height，按前文“无锚点形状归一化公式”中的递推公式计算并截断 gain，得到 `corrected_points`；
8. 在 shape 归一化前计算 `motion_extent_body`，不足 `0.25` 输出 `unavailable/insufficient_motion`，不得调用模型；
9. 对 ready 窗口调用 `arc_length_resample()` 得到 80 点及传播后的质量，再调用 `robust_isotropic_normalize()`；
10. 调用 `build_raw_features(..., point_times_sec=None, temporal_features_enabled=False)` 和 `compute_topology()`；
11. 验证步骤 4 `feature_stats.json` 后调用 `apply_feature_stats()` 得到真正的 `model_features`，不得让未标准化 `raw_features` 直接进入 TCN；
12. 断言 `shape=[80,2]`、`raw/model_features=[80,14]`、值有限、ready `point_mask=[1]*80`、索引 10/11 全 0、索引 12 等于 mask、索引 13 在 `[0,1]`。

`CameraWindowInput` 只是步骤 7 内部 dataclass，用于携带 corrected points、质量、窗口 ID 与审计字段；它不是 `TrajectorySample v1`，不伪造公开 source/split/label，也不写入步骤 4 frozen bundle。

持久化的 `wandering-camera-window-v1` 至少固定以下字段；`unavailable` 时所有不适用数组写 `null`，不能用零数组冒充有效轨迹：

```text
schema_version/window_id/parent_tracklet_id/segment_index
source_group_id/source_video_id/device_id/setup_id/stream_epoch/track_id
window_start_sec/window_end_sec
window_status/reason_codes/quality_flags
raw_detection_count/observed_bucket_count/interpolated_bucket_count
observed_ratio/longest_gap_seconds/mean_detection_confidence
bbox_bottom_points/bbox_heights/smoothed_bbox_heights/corrected_points
observed_mask/interpolated_mask/point_quality
shape_normalized_points/point_mask/raw_features/model_features/topology
preprocessing_config_sha256/feature_stats_sha256/model_training_split_sha256
```

这里故意没有 public `split/label`、长期 `person_id`、episode 或 risk 字段；window ID 由完整隔离键、segment index、窗口起止和输入 tracking SHA 的规范串确定性哈希得到。

#### 7.5 RF/TCN 推理规则与输出

每次运行只加载预先指定的主 seed `20260731`：

- RF 使用 `safe_load_development_model()`；camera 窗口用 `extract_features_from_points(shape_points, point_mask, quality)` 得到同一 26 维公式后调用受信模型，禁止把 camera 记录伪装成 `wandering-preprocessed-sample-v1`，禁止直接 `joblib.load`；

### 步骤 12：校准与拒识

- 在 validation 上做 temperature scaling；
- 计算每类 prototype；
- 合成质量故障样本，并保留真实异源/困难负例；
- 联合选择概率、距离和 energy 阈值；
- 阈值选择目标是控制错误高置信预测，不是最大化闭集准确率。

模型 artifact 必须包含温度、prototype、拒识阈值、归一化统计、类别顺序、配置和 split 哈希。

### 步骤 13：episode、日级证据和心理模块接入

先在徘徊子包内完成三层证据，再接共享心理管线：

```text
窗口概率与质量状态
  → 平滑、迟滞和相邻窗口合并
  → WanderingEpisode
  → 过滤极短或低质量 episode
  → 每日次数/总时长/最长时长/夜间比例/子类型分布
  → WanderingDailySummary
  → 现有 baseline.py 的徘徊字段扩展
  → WanderingDailyEvidence + wandering_baseline_deviation
  → routine_irregularity_score/risk_factor_details
  → AlgorithmEvent(module=mental_health)
```

要做：

- 定义 `WanderingWindowResult`、`WanderingEpisode`、`WanderingDailySummary` 和基线增强后的 `WanderingDailyEvidence`；
- 为窗口平滑、迟滞、episode 起止、跨午夜拆分和重叠去重编写边界测试；
- 日级统计至少包含 `wandering_episode_count`、`wandering_episodes_per_valid_observation_hour`、`wandering_total_duration_seconds`、`wandering_duration_ratio`、`max_wandering_episode_seconds`、`night_wandering_ratio`、`pattern_distribution`、`trajectory_coverage` 和 `uncertain/unavailable` 比例；
- 只有上游提供稳定、非空业务 `person_id` 时才进入跨日个人基线，`track_id` 不能代替；
- 扩展现有 `mental_health/baseline.py` 的指标表，并复用其基线成熟度、持续天数、置信度和风险等级策略；
- 为 `wandering_baseline_deviation` 的方向、零方差保护、有效观测小时归一化、版本变化重暖机和缺失日编写回归测试；
- 把徘徊证据写入 `routine_irregularity_score` 和 `risk_factor_details`，不创建 `module=wandering`；
- 生成可供比赛展示的算法侧趋势卡片 JSON fixture，但不实现家属 App、后台、通知或工单。

完成标志：

- 相同窗口序列重复运行得到相同 episode 和日级统计；
- `uncertain/unavailable/inference_error` 不被计为正常或徘徊 episode；
- 单个高概率窗口不会直接提高心理风险等级；
- 基线未成熟、覆盖不足或持续天数不足时沿用现有等级上限；
- `WanderingEvidence` 不含自由文本动作或独立风险等级；
- 最终事件严格符合数字 `risk_level=0..4` 和枚举 `recommended_action` 的 `AlgorithmEvent` 契约；
- 跌倒模块输出和配置不发生变化。



### 步骤 14：冻结评估、授权摄像头烟测和比赛交付

先冻结代码、split、阈值和模型 artifact，再运行一次公开封存测试与独立摄像头烟测。开发视频与封存视频必须隔离；用过封存数据调参后，该结果立即失去封存资格。

公开数据和合成压力测试报告：

- wandering 二分类：AUROC、AUPRC、sensitivity、specificity；
- 四类：macro-F1、balanced accuracy、每类 precision/recall/F1、混淆矩阵；
- 概率：NLL、Brier、ECE 和 reliability diagram；
- 拒识：OOD AUROC、FPR@95TPR、coverage-risk 曲线；
- 稳定性：至少 5 个 seed 的均值和标准差；
- 无锚点兼容性：平移/尺度确定性、旋转/投影一致率、low/medium/high 鲁棒曲线；
- 注入故障：长缺口、瞬移、ID 拼接和 bbox 高度突变的 QC 检出率；相机移动先报告显式 `camera_motion_state=moved` 的拒绝率，若另有 MP4 背景运动检测，再单列其真实检出证据，不能与 sidecar 注入混写；
- 工程：参数量、artifact 大小、CPU 单窗口延迟和长流内存。

授权固定摄像头烟测至少覆盖：

- 日间与夜间；
- 正常通行、pacing、lapping、random-like；
- 找东西、打电话踱步、锻炼、清洁等形状相近的目的性困难负例；
- 进出画面、短遮挡、漏点、轨迹碎片、ID 变化和相机位置变化；
- 从视频到 bbox tracklet、窗口、episode、日级证据和 `AlgorithmEvent` 的完整回放链。

烟测指标分两种证据等级：

1. 无人工 episode 真值：只报告可用窗口比例、轨迹覆盖率、最长缺口、fragments/person-minute、`unavailable/uncertain` 比例、端到端延迟和预测分布；
2. 有独立人工事件起止真值：再报告事件级 Precision/Recall/F1、false alarms/person-hour、匹配容差和失败案例。人工记录由项目测试人员完成，不要求老人使用系统进行标记。

短时摄像头烟测只能验证视频到窗口、episode 和日级汇总的工程链，不能验证 7 日个人基线或心理风险准确率。比赛中展示长期趋势时使用冻结、来源明确的多日历史 fixture 验证计算逻辑；只有取得真实纵向个人数据和独立风险真值后，才能报告个人基线或日级风险效果。

比赛交付包必须包含：

- 可执行离线 Demo 和固定输入示例；
- 外部平台联调记录：业务后端取得可解码直播地址并按输入契约交给算法；仅播放本地 MP4 不能表述为“已完成萤石开放平台接入”；
- 数据卡、split/hash、环境、配置、模型卡和部署说明；
- RF、纯 TCN、TopoWander-MPT 的同协议对照与消融；
- 公开基准、合成压力测试、真实烟测三套严格分开的结果；
- 质量拒识、未知拒识、困难负例和失败案例；
- 算法侧趋势卡片 JSON、标准 `AlgorithmEvent` 示例和非诊断声明；
- 演示录像或可重复演示脚本。

所有指标必须分数据源和证据等级报告，不能只给一个漂亮总分，也不能把公开轨迹或合成污染结果包装成真实居家老人验证。

## 14. 必做消融实验

先完成三个固定主对照，它们不是三条产品路线：


| 模型                   | 身份                         | 回答的问题                     |
| -------------------- | -------------------------- | ------------------------- |
| 手工特征 + Random Forest | 传统可解释下限，`comparison_only`  | 人工轨迹统计能做到多少               |
| 纯 TCN + 分层头          | 普通深度时序下限，`comparison_only` | 局部时序表征相对 RF 是否有增益         |
| TopoWander-MPT       | 唯一目标模型                     | 语义 patch、关系偏置和鲁棒训练是否进一步有效 |


RF、纯 TCN 与 TopoWander-MPT 的主对照固定相同数据、标签、split、seed 集合、指标和分阶段评估协议，但不同模型使用各自预注册的优化预算，不能笼统宣称“训练预算相同”。只有下面 TopoWander-MPT 内部消融彼此使用完全相同的优化器、epoch/早停和增强预算，并依次移除：


| 实验                             | 回答的问题                   |
| ------------------------------ | ----------------------- |
| 完整模型                           | 目标结果                    |
| 去掉 TCN，只用 token MLP            | 局部时序卷积是否必要              |
| 去掉语义 patch                     | 显式运动语义是否有效              |
| 去掉 relation bias               | 回访/反向关系是否有效             |
| 去掉掩码预训练                        | 自监督是否有效                 |
| 普通几何增强替代拓扑增强                   | 语义保持增强是否有效              |
| 去掉 prototype/energy            | 拒识是否有效                  |
| 去掉无锚点中心/尺度归一化                  | 不同画布和位置对齐是否必要           |
| x/y 独立 min-max 替代各向同性尺度        | 错误拉伸是否破坏类别几何            |
| 去掉 bbox 高度局部补偿                 | 远近尺度变化的自动补偿是否有效         |
| 去掉随机 projective warp           | 轻度透视不变性是否来自该组件          |
| 只用独立高斯噪声                       | 相关抖动和成块缺失是否必要           |
| 去掉 clean/corrupted consistency | 成对视图约束是否有效              |
| source-only，不做投影和观测污染          | 直接训练公开轨迹会损失多少鲁棒性        |
| 去掉故障注入与 QC 拒识                  | ID 拼接、长缺口是否会被误判为 random |
| 不合并 episode                    | 重叠窗口是否造成重复计数和重复预警       |
| 不做覆盖时长归一化                      | 摄像头运行时长是否虚假抬高日级证据       |
| 不使用个人基线                        | 日级绝对水平与相对个人变化有何差异       |


接受一个组件的依据不是“结构更先进”，而是：

- validation 多 seed 结果稳定改善；
- 不以校准、拒识或某个困难类别明显退化为代价；
- 测试冻结后仍保持方向一致；
- 延迟和模型大小可接受。



## 15. 常见错误与排查顺序



### 15.1 训练准确率很高，测试很差

依次检查：

1. 同一原轨迹的重叠窗口是否跨 split；
2. 归一化统计是否偷看 validation/test；
3. 文件名、长度、padding 或来源特征是否泄漏类别；
4. 增强是否只应用于 train；
5. 是否把程序化样本放进 test；
6. WanderingPatterns 是否只有轨迹级随机划分。



### 15.2 lapping 和 random 混淆

检查累计绕转、闭合距离、回访周期性和覆盖熵是否正确；可视化 relation attention，确认模型是否看到跨 patch 的闭环关系。

### 15.3 pacing 和 direct 混淆

检查：

- 短窗口是否只截到 pacing 的单程；
- 增强裁剪是否删掉反向点；
- patch 长度是否覆盖一次有效往返；
- episode 是否应该在更长上下文上二次聚合。

不要仅靠增大网络解决“窗口没有证据”的问题。

### 15.4 公开数据好、摄像头很差

这是预期风险，优先排查：

- 像素坐标未做正确归一化；
- 错用了上游 bbox `center/speed_px_per_sec`，没有从原始 bbox 重算底边中心；
- ID switch 和遮挡被当作随机轨迹；
- 摄像机透视造成速度/距离畸变；
- `raw_features` 未经过步骤 4 冻结 `feature_stats` 就送入 TCN，或旧 artifact 的时间通道被擅自改为非零；
- 正常目的性活动负例不足；
- 公开合成轨迹过于干净；
- 质量通道没有真正进入模型。



### 15.5 uncertain 太多或太少

不要先改模型。先分别画已知正确、已知错误、质量故障和异源样本的 probability、prototype distance、energy 分布，再在 validation 上调阈值。

### 15.6 窗口分数很好，但系统反复报警

检查是否绕过 episode 层直接按重叠窗口计数。40 秒窗口、20 秒步长会让同一段行为产生多个预测；必须先做平滑、迟滞和 episode 合并，再进入日级统计。

### 15.7 把 track ID 当成跨日老人身份

立即停止个人基线写入。`track_id` 只在当前 `source_group_id/source_video_id/device_id/setup_id/stream_epoch` 内有效；跨日聚合必须由上游提供稳定、非空业务 `person_id`。多人身份不确定时只保留 track-level 工程结果。

### 15.8 没有真值却出现实拍准确率

检查摄像头报告是否只有视频和预测、没有独立人工事件起止记录。无真值时删除 Accuracy/Precision/Recall/F1 和 false alarms/person-hour，只保留覆盖、fragment、拒识、延迟和预测分布。

### 15.9 风险卡片与算法接口不一致

展示层可以把数字等级映射成 `L1/L2` 文案，但不得把字符串写回 `AlgorithmEvent.risk_level`。徘徊窗口和 episode 不产生动作；只有现有心理管线产生数字 `0..4` 和标准 `recommended_action`。

### 15.10 本地 MP4 能运行，却声称萤石平台已接入

本地 MP4 只证明离线算法链。只有业务后端实际取得萤石可解码直播地址、算法按输入契约成功消费并保存联调记录，才能声称完成开放平台接入；token、账号和设备管理仍不属于本仓库。

### 15.11 成人脚本烟测被写成真实老人验证

如果烟测参与者不是目标老人群体，报告名称固定为“典型居家脚本工程烟测”。它可以验证输入、质量、episode 和延迟，不能证明真实老人泛化、心理预测或临床有效性。

### 15.12 摄像头记录无法进入 `PreprocessingInput`

这是预期的边界，不要放宽公开 schema 或伪造 `source_dataset/split/label`。检查步骤 7 是否使用独立 `CameraWindowInput`，并按 `arc_length_resample → robust_isotropic_normalize → build_raw_features → apply_feature_stats` 调用共享纯函数。

### 15.13 TCN 安全加载突然提示源码或配置哈希漂移

先检查是否为了步骤 7 修改了 `tcn_baseline.py`、步骤 6 的 train/evaluate/benchmark 脚本或 `wandering_tcn_v1.yaml`。这些文件受 development manifest 绑定；步骤 7 应把 camera forward 写在新的 `camera_inference.py`，不能关闭哈希校验或直接加载 NPZ。

## 20. 方案边界

- 本文给出的是目标设计和实施顺序，不是已训练完成的模型。
- 公开四类轨迹分数只能证明公开基准上的形状识别，不能等价为摄像头或临床验证。
- 无锚点方案只近似对齐轨迹形状，不恢复真实米制位置、速度、房间拓扑或跨摄像头连续轨迹。
- 用户不需要放置锚点、测量房间、标注行为或修正骨架；相应代价是系统不能从二维 XY 可靠推断行为目的。
- 通用投影和观测污染只能作为训练增强与压力测试，不能写成目标摄像头实测误差。
- `track_id` 是短时跟踪标识，不等于长期 `person_id`。
- 模型先识别行为证据，日级心理风险由独立的基线与心理模块逻辑处理。
- 当证据不充分时输出不确定或不可用，不能为了覆盖率强行给风险结论。
- 比赛最终需要授权固定摄像头烟测，但短时烟测只证明有限 setup 下的工程链路，不能证明跨人员、跨家庭、真实老人或临床有效性。
- 家属端、社区后台、萤石账号/token、推送和关怀工单不在本算法仓库实现；算法只交付可验证证据、标准事件和 Demo fixture。
- `WanderingEvidence` 不直接携带心理风险等级；数字风险等级与 `recommended_action` 必须由现有 `mental_health` 管线按统一接口生成。
