# 徘徊五日算法交付契约

版本：`m0cam-5d-w5d00-v1`

本契约固定五日闭环的算法侧输入身份、输出文件、统一状态和 source reference。它交付 `module=mental_health` 的徘徊证据，不直接发出 `AlgorithmEvent`，也不实现后端、前端、消息或处置流程。

## 1. 输入与运行身份

- B01 36 条、B02 12 条可用视频统一为 `dataset_role=development`，允许反复分段、边界、送模、预处理、binary threshold 和必要的轻量模型开发。
- B01/B02 同属 `P-OFFICE-01`、`C6C-OFFICE-01`；不能据此声明跨人或跨机位泛化。
- B02-0008 的早期 sidecar 保留旧 setup 别名 `office-setup-01`；index 显式记录 `sidecar_setup_id` 和 `setup_binding_status=owner_confirmed_legacy_alias`，不改写历史 sidecar。其他未登记的 setup 漂移失败关闭。
- 两条 frame-check 视频固定排除。每条 index 记录必须绑定并校验 video、tracking、media sidecar、派生 truth 和原始 per-video CVAT XML 的路径及 SHA-256。
- fixed primary 为 `topowander-m0s-seed20260731-epoch0005`，model state SHA-256 为 `94c3c22d4caa38ece347d6a10f440b9fb3f7067b6c791ac1f259ce7efe69c031`。
- camera 输入固定为 80 点、14 个 model feature、2 个 shape coordinate；binary 规则固定为 `sigmoid >= 0.5`。W5D-00 只验证 CPU safe load，不重训模型。
- 居家 MP4 当前登记为 `awaiting_input`。该状态不阻塞 W5D-03A context core、日报、基线或 handoff；当前以 B01+B02/fixture 完成工程验收。MP4 到位后先作 truth-free smoke，人工标签不是运行前置；若据其继续调参，身份改为 development。

## 2. Fresh 与不覆盖

所有运行写入 `tmp/wandering_camera_5d_runs/<unique_run_id>/` 下的新目录。最终目录必须不存在；producer 使用同文件系统 staging 后原子提交。历史目录、报告和证据均不得覆盖。

固定 handoff 文件名：

```text
episode_results.jsonl
context_reviews.jsonl
daily_reports.jsonl
baseline_profiles.jsonl
baseline_deviations.jsonl
handoff_manifest.json
run_summary.json
README.md
```

空模态也保留对应空 JSONL 和 manifest descriptor，不通过删除文件表达 unavailable。

## 3. 统一状态

| 状态 | 语义 |
|---|---|
| `ready` | 输入、身份和当前层质量条件满足，可进入下游统计 |
| `uncertain` | 结果可保留和送下游候选统计，但必须保留不确定原因，不得冒充人工接受 |
| `unavailable` | 输入、coverage、provider 或 reference 不足；不填伪造零值 |
| `error` | 可定位的工程异常；保留输入身份和错误码 |

具体层可以增加正交状态，例如 episode 的 `proposal_status`、baseline 的 `readiness_status`，但顶层 `status` 必须使用上述四值。

外部输入就绪度不复用顶层 run status。W5D-03 及后续 bundle 在 run summary 或扩展 manifest 中记录 `home_input_status=awaiting_input|available`、`home_annotation_status=not_provided|unlabeled|available`、`home_smoke_status=not_run_input_unavailable|ready|uncertain|error` 和实际 `validation_scope`。`not_run_input_unavailable` 不能把其余已完成输出降为 `error`；未运行居家 smoke 时不得声明 `home_validated`。

## 4. Source Reference 与身份

每条可对接记录至少携带：

```text
schema_version
module=mental_health
person_id
session_id
source_video_id
start_time/end_time or local_date
status
quality_flags
identity.model/config/policy
source_refs
```

`source_refs` 中每项包含 `ref_type`、稳定 `ref_id`、可空 `artifact_path` 和可空 SHA-256。日级与 baseline 跨多个 session/video 时，顶层 `session_id/source_video_id` 可以为 null，但必须用 `source_refs` 列出全部来源。

## 5. 分层语义

- `episode_results`：shape/binary 结果；保留原 `technical_segment_index`、起止秒、`duration_seconds` 和 `reason_codes`。`proposal_status`、顶层四态、QC 四态和运行决策分开保存；`run_status` 固定为 `auto_accepted/uncertain/rejected`。`uncertain` 可送 shape，但不改写为人工 accepted boundary。
- `context_reviews`：运行时使用 `wandering-handoff-context-review-v2`，只描述 phone/searching/cleaning/exercise 等 purpose/context。每个 eligible episode 恰好一行，结构化保存 trigger、`error_code`、episode snapshot SHA、起/中/末三个时点的实际时间/frame index/bbox，以及 scene/crop 的 Git 外路径和 SHA-256。provider 失败输出 `unknown + unavailable`，不得改 shape、boundary、truth、QC 或阈值。W5D-00 的 v1 schema 快照保留为历史 baseline，不覆盖；v2 是 W5D-03A 起的现行 runtime schema。
- `daily_reports`：W5D-04 runtime 使用 `wandering-handoff-daily-report-v2`，按 `person_id + local_date + timezone` 汇总 presence seconds、tracking coverage seconds/ratio、QC coverage、shape/binary、high-confidence/uncertain、context、unavailable/error 和 baseline readiness。W5D-00 的 v1 schema 保留为契约 baseline，不覆盖。
- `baseline_profiles`：1-2 usable days 为 `warming_up`，3-6 日为 `initial_ready`，至少 7 日为 `stable_ready`，最多使用最新 14 个 usable days。
- `baseline_deviations`：只使用 observation day 之前的 reference；reference 不足时输出 null/status，不制造零值。
- `handoff_manifest`：W5D-05 使用 `wandering-handoff-manifest-v2`，绑定所有文件的 schema、record count、byte count、SHA-256、三个上游 stage 和 home/delivery 状态；固定 `algorithm_event_emitted=false`、`medical_diagnosis_emitted=false`、`backend_or_frontend_implemented=false`。W5D-00 的 v1 schema 继续作为契约基线，不覆盖。
- `run_summary`：W5D-05 使用 `wandering-handoff-run-summary-v2`，保存输入/输出/失败计数、降级组件、守恒值、validation scope 和 home/delivery 状态。

完整 JSON Schema 位于 `configs/schemas/wandering_5d_v1/`。是否将这些 evidence 映射为业务 `AlgorithmEvent(module=mental_health)`，由后端对接阶段另行确定。

## 6. 构建命令

Windows/WSL 本机使用项目 conda 环境：

```bash
conda run -n eldercare-ai python scripts/wandering/build_camera_delivery_contract.py \
  --source-root "/mnt/d/徘徊数据集/自采数据" \
  --output reports/mental_health/wandering_camera_5d_contract_v3

conda run -n eldercare-ai python scripts/wandering/run_camera_context_review.py \
  --provider-mode fake \
  --output-dir reports/mental_health/wandering_camera_context_core_w5d03a_v2

conda run -n eldercare-ai python scripts/wandering/run_camera_daily_baseline.py \
  --output-dir reports/mental_health/wandering_camera_daily_baseline_w5d04_v1
```

W5D-04 命令额外验证 48 条 tracking/sidecar descriptor、显式 person/session/timezone/presence binding、strict-prior baseline 和 public loader 重算。当前 sidecar 的 `capture_started_at=null`，因此 binding manifest 使用 declared development schedule，并带 `capture_clock_unavailable_declared_schedule`，不得解释为实测拍摄时钟。

W5D-05 完整 cached-tracking E2E 使用一个 fresh output root：

```bash
conda run -n eldercare-ai python scripts/wandering/run_camera_handoff_e2e.py \
  --output-root tmp/wandering_camera_5d_runs/w5d05-e2e-next \
  --run-id w5d05-e2e-next
```

命令依次执行 W5D-02 episode/shape、W5D-03A context、W5D-04 daily/baseline 和 W5D-05 handoff，不人工修改中间 JSON。最终 `handoff/` 严格只有 8 个契约文件；public loader 会重新验证 descriptor、现行 row schema、跨阶段 identity/snapshot/source hash 和 count/duration 守恒。正式 B01+B02 证据为 [handoff v2](../../reports/mental_health/wandering_camera_handoff_w5d05_v2/README.md)，provider-disabled 非阻塞证据为 [disabled v2](../../reports/mental_health/wandering_camera_handoff_w5d05_disabled_v2/README.md)。
