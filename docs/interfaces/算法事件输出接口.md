# 算法事件输出接口

算法模块统一输出事件化 JSON。业务系统只消费该 JSON，不需要理解模型内部细节。

## 1. 通用字段

```json
{
  "module": "fall_risk",
  "device_id": "ezviz_cam_001",
  "person_id": "elder_001",
  "timestamp": "2026-06-26T14:20:00+08:00",
  "scene_region": "bedroom_bedside",
  "risk_level": 3,
  "risk_score": 0.84,
  "confidence": 0.87,
  "trigger_event": "near_fall",
  "risk_factors": [
    "重心快速横向偏移",
    "步态节律中断"
  ],
  "recommended_action": "notify_guardian",
  "evidence_window": {
    "start_time": 15.2,
    "end_time": 17.6
  },
  "model_version": "fall-risk-v0.1"
}
```

## 2. 模块编码

| 编码 | 含义 |
|---|---|
| `fall_risk` | 跌倒风险 |
| `mental_health` | 心理健康风险 |

## 3. 风险等级

| 等级 | 含义 |
|---:|---|
| 0 | 正常 |
| 1 | 低风险 |
| 2 | 中风险 |
| 3 | 高风险 |
| 4 | 紧急风险 |

## 4. 建议动作

| 编码 | 含义 |
|---|---|
| `record_only` | 仅记录 |
| `observe` | 持续观察 |
| `remind_user` | 建议提醒老人 |
| `notify_guardian` | 建议通知家属 |
| `emergency_alert` | 建议紧急告警 |
| `manual_review` | 建议人工复核 |

## 5. 心理健康模块特别说明

心理健康模块输出的是风险预警，不是医学诊断。高风险输出应进入人工复核或专业人员评估流程，不应由算法直接给出诊断结论。

## 6. 跌倒风险直播服务接口

除健康检查外，请求均携带 `Authorization: Bearer ${ALGORITHM_API_TOKEN}`：

| 方法与路径 | 行为 | 成功状态 |
|---|---|---:|
| `POST /v1/monitoring/sessions` | 提交直播地址并创建后台会话 | 202 |
| `GET /v1/monitoring/sessions/{session_id}` | 查询会话状态和最后出帧时间 | 200 |
| `PUT /v1/monitoring/sessions/{session_id}/stream-url` | 更新过期直播地址并由原线程重连 | 200 |
| `POST /v1/monitoring/sessions/{session_id}/stop` | 幂等停止并释放资源 | 202 |
| `GET /health/live` | 进程存活检查，无需鉴权 | 200 |
| `GET /health/ready` | 配置可读、模型存在且所选 FFmpeg 后端可用时就绪 | 200/503 |

启动请求字段为 `request_id`、`stream_url`、`device_id`、`person_id`、`scene_region` 和 `callback_url`。相同 `request_id` 幂等返回原会话；单进程已有非终止会话时，不同请求返回 409。会话查询响应另含 `stream_epoch`、`frame_diagnostics` 和 `runtime_diagnostics`：前者标识成功打开流后的会话边界；后两者包含队列计数、源/接收采样率、最大 gap、帧龄、目标状态、分支 `valid/unavailable/inference_error`、窗口质量、阶段耗时和 epoch 清理原因，不包含直播地址、token 或原始帧。解码器错误进入 `last_error` 前必须脱敏直播地址；可打开但未达到稳定时长或帧数门槛的短连接会累计连续失败预算，避免无限重连。

实时融合产生的 `AlgorithmEvent.metadata` 包含 `stream_epoch`、`feature_coverage`、`fusion_mask` 和各分支状态。不可用或推理失败分支不提供伪造的 `0.0` 分数；融合 mask 只对当前有效分支开放。目标诊断中的 `binding_verified` 当前固定为 `false`，因为 `person_id` 是专属视频流的业务先验，不是视觉身份识别结论。

风险回调不修改共享 `AlgorithmEvent` 必填字段，而是在跌倒实时服务 envelope 中增加：

| 字段 | 含义 |
|---|---|
| `event_id` | 不可变事件版本 ID；同一版本重试和显式重放复用该值 |
| `episode_id` | 同一风险过程的稳定 ID；首次、升级、静止条件满足、恢复或 unresolved 版本通过它关联 |
| `session_id` | 产生事件的监测会话 |
| `stream_epoch` | 产生该版本的流 epoch；重连不改写旧事件 |
| `lifecycle_state` | `suspected`、`confirmed_static`、`recovered` 或 `unresolved` |
| `version_kind` | `initial`、`observation_update`、`confirmed_static`、`recovered` 或 `unresolved` |
| `first_generated_time` | 该不可变版本首次生成的 UTC 时间 |
| `schema_version` | 当前为 `1.0` |

`confirmed_static` 只表示配置的跌倒后静止工程条件满足，不表示医学、人工或真实跌倒确认。状态边的源 PTS、进入单调时间、峰值时间、最后有效观测、TTL、触发条件和技术清理原因位于 `metadata.episode_transition`；`unavailable` 和 `inference_error` 不会被写成正常观测或恢复边。

普通 0 级观测不回调，1-4 级事件按 30 秒策略去重且升级立即生成新版本。`recovered` 和 `unresolved` 是已有 episode 的唯一终止更新，即使其 `risk_level=0` 也必须回调，因此它们是“普通 0 级不回调”的明确例外。

服务使用进程内、固定容量的异步 outbox。`process_frame()` 只冻结载荷并尝试非阻塞入队；HTTP、有限重试和等待均在投递线程执行。默认最多 3 次单次 HTTP 尝试，连接失败、超时和非 2xx 均复用原 `event_id` 和完全一致的载荷。投递状态独立记录为 `pending`、`retrying`、`delivered` 或 `failed`，不会改写算法 episode 状态。

默认 outbox 容量为 32。队列满时，新的 4 级或 episode 终止版本可确定性替换最早的、未在投递中的普通版本；4 级、终止版本和在途版本不被静默覆盖。无法接纳时记录拒绝类型、事件 ID 和计数。重连或直播地址更新只清理推理 episode，旧 epoch 已生成版本继续使用原 epoch 和回调上下文投递。停止默认给 outbox 3 秒排空预算，并记录已投递、最终失败、未完成、拒绝和线程是否仍在结束中的结果。

当前 outbox 不使用数据库，只保证当前进程内的有界投递和最近版本重放；进程崩溃或重启后的持久恢复不在本阶段能力内。鉴权继续使用 `Authorization: Bearer ${CALLBACK_TOKEN}`，诊断和日志不返回 token、完整直播地址或原始帧。
