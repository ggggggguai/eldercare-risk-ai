## 3. 后续发现的 P0

### 3.1 Git source identity 自引用与 replace-ref 绕过

当前 `git_tree` 同时要求 contract 内 identifier 等于 active HEAD，又要求包含该 identifier 的 contract blob 属于同一 commit，形成无法通过普通提交构造的 commit-hash fixed point。默认 `git cat-file` 还会采用 replace refs；临时 Git 仓实证中 HEAD 保持原 commit，但 `cat-file` 读取了 replacement tree。

### 3.2 runtime trust closure 不完整

固定 trust-root 清单遗漏实际导入链中的 `anchorless_normalization.py`、`topology.py`、`handcrafted_features.py`、`rf_baseline.py`、`tcn_baseline.py`、`datasets.py`、`manifests.py`、`schemas.py` 和相关 package initializer。现有 closure 测试只检查手写 subset，不能证明完整传递闭包。

### 3.3 restore 可返回假 ready

tmp-only 复现在 restore 读取 contract 后、ready marker 提交前改变合法 contract 字节，得到：

```json
{"contract_mutation_triggered":true,"marker_matches_current_contract":false,"restore_status":"ready"}
```

最终 marker 回读还只比较解析后的 JSON 语义，而不是 canonical bytes。后续 preflight 会拒绝，不改变 restore 本次错误返回 ready 的事实。

### 3.4 rollback ownership 只按路径记录

第一资产组提交后由另一写者替换同路径对象，再令第二组失败，tmp-only 复现得到：

```json
{"failure_observed":true,"competitor_survived":false,"competitor_parent_survived":false}
```

rollback 只记录路径，没有确认当前对象仍是本次提交对象，因此删除了竞争者。

## 4. 次要未关闭项

- 缺失或不可读 `.git`、HEAD、packed-refs 等部分 source 失败仍可能落到 CLI exit 1，而不是结构化 blocked/exit 2；
- application network guard 是无锁的进程全局 monkeypatch，并发作用域没有直接回归；
- rollback failure matrix、Windows junction/reparse、detector path/inode、READY extra/drift 和 ZIP metadata 的报告覆盖描述强于实际测试。
